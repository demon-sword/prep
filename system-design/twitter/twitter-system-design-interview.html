Non-Functional Requirements (Technical)

Latency

Home LCP < 2.5s on 4G; optimistic post paint < 50ms; timeline scroll 60fps with variable-height virtualization

Scale

Millions DAU; infinite feeds; same tweet in 5+ surfaces — normalized entity store, not duplicate blobs per tab

Reliability

WS/SSE reconnect with dedup; idempotent publish; partial timeline on fan-out-on-read cold start

Security

OAuth 2.0 PKCE; httpOnly session + ct0 CSRF; XSS-safe tweet rendering; block/mute enforced at render

Metrics · Constraints · Assumptions

  • Metrics: LCP/INP, scroll jank rate, stream reconnect success %, duplicate-tweet rate after realtime+pagination, publish retry success
  • Constraints: Rate limits (429 + Retry-After); hybrid fan-out (push vs pull for high-follower authors); mobile autoplay policies
  • Assumptions: Authenticated primary UX; BFF aggregates bootstrap; REST v2 + upload.twitter.com for media; web-first (responsive)

MemoryNormalized entities, React Query infinite pages (ids only), height cache for virtualizer
IndexedDBCompose drafts, upload session (media_id + segment ack), failed publish outbox
localStorageUI prefs, study checklist — not auth tokens on web
Server (SoT)Timelines, tweet graph, counts, notification read state, DM history
Rule: React Query holds ordered ID lists + cursors per surface; entity store holds tweet/user bodies. Never duplicate full tweet objects inside each infinite page — patch once on like/repost and all surfaces update.

Data Model

~5 min · Entities · Relationships · Normalized graph
▼

Store tweets and users by id; timelines are ordered id lists with opaque cursors. Parse tweet text into entities (mentions, URLs, cashtags) once at ingest.

Tweet { id, // id_str in API text, displayTextRange?, authorId, createdAt, conversationId, inReplyToTweetId?, quotedTweetId?, repostOfTweetId?, mediaIds[], pollId?, likeCount, replyCount, repostCount, bookmarkCount, lang, possiblySensitive, _meta: { version, pending?, clientTweetId? } } User { id, handle, displayName, avatarUrl, bannerUrl, verifiedType?, isProtected, relationshipToViewer: following | blocked | muted } Media { id, type: photo | video | gif, url, previewUrl, aspectRatio, altText?, variants[], processingState? } TimelinePage { ids: string[], cursorTop, cursorBottom, // opaque rankingVersion?, // For You only fetchedAt } Notification { id, type: mention | repost | follow | like ..., actorIds[], targetTweetId?, read, createdAt } Conversation { id, participantIds[], lastMessagePreview, lastMessageAt, unreadCount, isRequestFolder }

Key relationships

Network lifecycle notes

  • Reconnect: WS exponential backoff 1s→2s→4s (cap 30s); on reconnect, fetch head cursor via REST and dedup ids already in React Query pages
  • Idempotency: client_tweet_id (UUID) on POST CreateTweet — safe retry after 401 refresh or flaky network; swap pending:* → real id_str
  • Rate limits: Honor Retry-After on 429; disable optimistic buttons; show account-level vs app-level messaging
  • Pagination race: If realtime prepends while fetchNextPage in flight, merge with id-set dedup — never double-render same tweet
  • Auth retry: Single-flight token refresh on 401; queue API calls; drafts stay in IndexedDB during re-login

Deep Dive

~10 min · Pick 1–2 areas the interviewer cares about
▼

Say: “I'll go deep on Performance and Real-time — happy to switch to Security, Media, or Testing/Observability.”

  • Virtualization: react-virtuoso / react-window with dynamic height cache; aspect-ratio boxes on media to prevent CLS; measure tweet row once, reuse height until content changes
  • LCP: Bootstrap BFF coalesces viewer + first timeline page; priority image on above-fold avatar; route-level code split (home vs DM vs settings)
  • Prefetch: When within 3 viewports of bottom, prefetch next cursor page; idle prefetch profile metadata on hover card
  • Render: Selectors from normalized store — row re-renders only when tweetsById[id] version bumps; batch count updates via rAF
  • CDN: Responsive srcset + blurhash/LQIP; separate metrics endpoint with short TTL so counts stay fresh without busting tweet body cache
  • Transport: Following may use WS/SSE for tweet_create events; For You often polls rank head — don’t refetch entire feed on every event
  • New posts banner: Buffer incoming ids + increment counter; tap prepends above viewport or replaces only if user at scrollTop ≈ 0
  • Dedup: Maintain Set<tweetId> per feed mode; ignore WS events already in last REST page; handle out-of-order delete-before-create
  • Scroll stability: Freeze displayed window during read — don’t reshuffle ranked items above anchor tweet without user action
  • Counts: Batch like/repost counter patches; avoid re-mounting virtualized list on every socket tick
  • OAuth PKCE: Web login with code_challenge; refresh token single-flight; proactive refresh at 80% TTL
  • Session: httpOnly cookies for session; access token in memory — not localStorage
  • CSRF: ct0 cookie + header on mutating requests; SameSite=Lax
  • XSS: Never dangerouslySetInnerHTML on tweet text — parse entities to React nodes; sanitize link hrefs
  • Graph safety: Block/mute filters at selector — don’t render then hide; protected accounts gate tabs server-side
  • CSP: Strict script-src; ads/analytics via nonce or isolated iframe where required
  • Upload FSM: INIT → APPEND (4–5MB segments) → FINALIZE → STATUS poll until succeeded
  • Retry: Re-send failed segment_index only; persist media_id + acked segments in draft IDB
  • Composer: Early upload on file pick; cap concurrent uploads; block Post until FINALIZE+processing ready for video
  • Playback: Muted autoplay intersection observer; data-saver disables prefetch; alt text required flow for a11y
  • Unit: Cursor merge, dedup reducer, optimistic id swap, entity count monotonic merge, mention offset parser
  • Integration: React Query infinite cache + WS fixture stream; 401 → refresh → retry once
  • E2E: Post optimistic → appear in Following; tab switch preserves scroll; new posts banner prepend
  • Observability: RUM LCP/INP; trace x-transaction-id; client metrics: duplicate rate, reconnect latency, virtualizer overflow
  • Load: 500 heterogeneous tweet heights in virtualizer; WS 100 events/sec count batching

Interview close (30 sec)

Three patterns I'd repeat: (1) normalized entities + surface-scoped id lists (Following/For You never share one cache key), (2) client_tweet_id + realtime/REST dedup so retries and sockets don't duplicate tweets, (3) bounded failure domains — auth refresh without wiping IDB drafts, per-segment upload retry, read-only degraded mode when API is down.
