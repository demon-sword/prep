Non-Functional Requirements (Technical)

Latency

Optimistic send paint < 50ms; socket event → UI update < 200ms p95; channel switch with warm cache < 300ms

Scale

100k+ messages per channel (virtualized); 500+ channels/DMs in sidebar; 200-member channel typing aggregation

Reliability

WebSocket reconnect with event replay; offline outbox with same client_msg_id; dedup socket + REST paths

Security

Workspace-scoped state isolation; OAuth token refresh; XSS-safe mrkdwn; no cross-workspace data leaks

Metrics · Constraints · Assumptions

  • Metrics: socket reconnect success %, message dedup collision rate, unread badge accuracy, time-to-first-message after channel open
  • Constraints: Slack ts is string seconds.microseconds; one WebSocket per active workspace; LB idle timeout ~60–120s
  • Assumptions: BFF wraps Slack Web API + Events API; authenticated workspace members; single-region v1; Enterprise Grid out of scope unless asked

Scope — In vs Out

In scope (v1)Out of scope (defer)
Web client SPA, channels/threads/DMs, realtime feed, composer, unread badges, workspace switchHuddles/video, Slack Connect shared channels, Canvas, Workflow Builder, full search index, mobile native apps

State Management — Where State Lives

Ephemeral (JS)Typing debounce timers, scroll pinned-to-bottom flag, optimistic temp IDs, event coalesce buffers
MemoryActive workspace slice: messagesById, timelines, unread, drafts, presence
Disk (IDB)Message pages, channel metadata, offline outbox, cold workspace slices
localStorageLast-open channel per workspace, UI prefs, composer draft backup
Server (SoT)Committed messages, last_read_ts, channel membership, notification prefs
Rule: Server owns committed history and read cursors. Client owns interaction latency. Never duplicate message objects — one messagesById entry, multiple timeline index lists.

Data Model

~5 min · Entities · Relationships · Invariants
▼

Store messages in a normalized map keyed by ts, with separate timeline indexes per conversation surface. All tenant data namespaced under workspaceId.

Workspace { id: teamId, name, domain, icon_url, token, token_expires_at, plan: free | pro | enterprise } User { id: userId, workspace_id, name, display_name, avatar_url, presence: active | away | dnd, status_text?, status_emoji?, status_expiration?, is_bot, is_restricted } Channel extends Conversation { id: channelId, workspace_id, name, is_private, is_im, is_mpim, topic, purpose, num_members, last_read_ts, latest_ts, unread_count_display?, notification_prefs: all | mentions | mute } Message { ts, channel: ConversationId, user: userId, text, blocks?, attachments?, thread_ts?, reply_count?, latest_reply?, client_msg_id?, reactions: Record<emoji, userIds[]>, edited?, deleted? } ChannelTimeline { conversationId, topLevelTs: string[], threadsByParentTs: Map<parentTs, { replyTs[], hasMoreOlder }>, historyCursor: { oldestLoaded, newestLoaded, hasMoreOlder } }

Key relationships & invariants

OperationStore behavior
Send messageOptimistic entry in messagesById + append to topLevelTs; dedup on socket ACK via client_msg_id or ts
Thread replySingle message object; indexed in threadsByParentTs, not in topLevelTs; bump parent reply_count
Also send to channelSeparate top-level message or flagged broadcast copy in channel feed
Mark readAdvance last_read_ts on Channel; clear unread badge; sync via conversations.mark
Workspace switchActivate workspaces[teamId] slice; no shared global maps for tenant data

Network lifecycle notes

  • Optimistic send: Render bubble immediately with client_msg_id → POST → on ACK replace temp id with server ts; on failure show retry
  • Dedup: Index by ts and client_msg_id; socket event matching pending optimistic → merge, don't duplicate
  • Ordering: Sort by ts (lexicographic string compare); buffer out-of-order events briefly
  • Offline: Queue sends in IndexedDB outbox; replay with same client_msg_id on reconnect
  • Multi-tab: SharedWorker owns one socket; BroadcastChannel syncs events to other tabs

Deep Dive

~10 min · Pick 1–2 areas the interviewer cares about
▼

Say: "I'll go deep on Performance and the WebSocket reconnect path — happy to switch to Security, observability, or testing if you prefer."

  • Virtualization: react-virtuoso or react-window for message list + sidebar; dynamic height cache per message row
  • Scroll anchoring: Pinned-to-bottom flag; "N new messages" pill when scrolled up; overflow-anchor or manual scrollHeight delta compensation
  • Lazy history: Fetch 50–100 messages on channel open; conversations.history with cursor on scroll-up
  • Event coalescing: Batch reaction events in 100ms window; aggregate typing indicators; throttle presence during incidents
  • Workspace switch: LRU cache hot slices; prefetch on quick-switcher hover; IndexedDB cold hydrate; target < 300ms warm
  • Bundle: Code-split emoji packs, Block Kit renderers; lazy-load per-workspace assets
  • Tenant isolation: All state keyed under workspaces[teamId]; never read channelId without workspace prefix
  • Auth: OAuth xoxc/xoxp tokens; refresh before expiry; SSO/SAML redirect for Enterprise
  • XSS: Parse mrkdwn to safe AST; never dangerouslySetInnerHTML on raw user text; sanitize link URLs
  • Token storage: HttpOnly cookies preferred over localStorage; never log tokens
  • File uploads: Presigned URLs; virus scan on server; sanitize link unfurl HTML
  • Idempotency: client_msg_id prevents double-send on reconnect; server dedupes within TTL window
  • Client: socket connect latency, reconnect success %, event processing lag, dedup collision rate, virtualizer frame p95
  • Client: unread badge drift — local count vs server unread_count_display after reconnect
  • Server: WebSocket connection count, event fan-out latency, history API p95, mark-read sync lag
  • Trace: client_msg_id / ts across optimistic UI → REST → socket ACK
  • Product: channel switch time, scroll-to-message success, offline outbox drain rate
  • Unit: timeline index mutations, dedup by client_msg_id, unread computation from last_read_ts, mrkdwn parser
  • Unit: event router reducer — message, message_changed out-of-order, reaction coalescing
  • Integration: mock WebSocket with fixture event streams; optimistic send → ACK merge; reconnect replay
  • E2E: send while scrolled up (pill appears); thread reply updates parent badge; workspace switch preserves drafts
  • E2E: offline send → reconnect → outbox drain with no duplicates
  • Load: virtualizer with 10k synthetic messages; 100 events/sec socket burst
  • aria-live="polite" on message region for new messages when focused; avoid announcing every reaction
  • Keyboard: Cmd+K quick switcher with arrow nav + Enter; focus trap in modals; Cmd+Enter send
  • Unread badges: don't rely on color alone — bold text + count for @mentions
  • Virtualized list: preserve focus when new messages arrive; announce "N new messages" pill
  • Reduced motion: disable typing indicator bounce; respect prefers-reduced-motion
  • High contrast: ensure presence dots and mention highlights meet WCAG AA

Interview close (30 sec)

Three patterns I'd repeat: (1) normalized message store with separate timeline indexes — one object, many views, (2) client_msg_id + server ts for optimistic sends and reconnect dedup, (3) workspace-scoped state partitions keyed by teamId so cross-tenant leaks are structurally impossible.
