AreaMust have (v1)Nice to have

Non-Functional Requirements (Technical)

Latency

TTFT < 500ms perceived; optimistic send < 50ms; stream visible within 1 frame batch (~16ms)

Scale

500+ messages virtualized; 10k sidebar rows; concurrent tabs same conversation

Reliability

Partial stream preserved on disconnect; offline queue; idempotent confirms

Security

JWT + org scoping; upload sanitization; MCP egress allowlist; sandbox artifacts

Metrics · Constraints · Assumptions

  • Metrics: TTFT, tokens/sec render rate, stream recovery success %, tool confirm dedup rate
  • Constraints: Context window cap (~200k tokens); mobile Safari SSE limits; no raw MCP tokens in browser
  • Assumptions: BFF owns provider keys; single-region v1; authenticated users; Anthropic-primary with adapter layer

State Management — Where State Lives

Ephemeral (JS)Token buffer, rAF flush queue, parse cache, optimistic temp IDs
MemoryActive conversation graph view, height cache, sidebar prefetch (~20 threads)
Disk (IDB)Message pages, offline outbox, upload resume, partial stream on drop
localStorageComposer drafts, UI prefs, study progress
Server (SoT)Message tree, active_leaf, generation checkpoints, tool ledger
Rule: Server owns committed history + model context. Client owns interaction latency (draft, stream buffer, scroll). Never treat React messages[] as source of truth — it's a view over the graph.

Data Model

~5 min · Entities · Relationships · IR blocks
▼

Store as a message graph, not a flat array. Persist IR (Internal Representation) — provider-neutral content blocks — compile to Anthropic/OpenAI only at the adapter boundary.

Conversation { id, org_id?, owner_user_id, title, active_leaf_id, conversation_revision, // optimistic concurrency created_at, updated_at } MessageNode { id, conversation_id, parent_id?, // tree edge role: system | user | assistant, content: ContentBlock[], // IR status: final | streaming | superseded | cancelled, model_id?, branch_label?, created_at } ContentBlock = TextBlock | ImageBlock | ToolCallBlock | ToolResultBlock | ThinkingBlock ToolExecution { tool_use_id, conversation_id, idempotency_key, status: pending | awaiting_approval | running | completed | failed, approved_by?, audit_hash } Generation { id, message_id, stream_cursor, last_event_id, status: running | interrupted | complete }

Key relationships

OperationGraph behavior
Send messageNew user node; child of current active leaf
Stream replyNew assistant node; status streaming → final
Edit message NSibling fork under parent(N), not in-place overwrite
Retry assistantNew assistant sibling under same user parent
Tool resultBlocks appended to next user turn (Anthropic shape in IR)

API Design / BFF

~10 min · Protocols · Endpoints · Real-time · Edge
▼

Protocol choice

PatternUse in Claude chatWhy
SSELLM token stream (default)Server→client push; HTTP auth; Last-Event-ID reconnect; AbortController cancel
RESTSend, edit, cancel, history pages, tool execute, uploadsIdempotency-Key; standard caching; clear error taxonomy
WebSocketOptional: multi-tab sync, presence, async job pushFull-duplex when client→server churn is high
Long pollingAvoid for tokensHigher latency than SSE for streaming text
gRPCInternal service-to-serviceNot browser-facing; BFF translates to REST/SSE

Core endpoints (BFF)

MethodEndpointPurpose
POST/conversations/:id/messagesSend user turn → returns stream_id / opens SSE
POST/conversations/:id/messages/:mid/editFork branch + start regen
POST/generations/:id/cancelStop inference + finalize partial
GET/generations/:id/stream?after=cursorResume interrupted stream

POST/conversations/:id/tools/executeHITL confirm; Idempotency-Key header
POST/uploads/presignMultipart attach → quarantine → extract
GET/conversations?cursor=&q=Sidebar list + search

Streaming adapter (normalized events)

Provider wire format → StreamDecoder → normalized events consumed by one client reducer:

message_start · content_delta · tool_call_delta · thinking_delta · content_block_stop · message_stop · error

Network lifecycle notes

  • Cancel chain: UI AbortController → close SSE → BFF cancels provider job → client finalizes partial MD
  • Drop recovery: Keep partial UI → retry with Idempotency-Key OR resume with generation cursor
  • Backoff: Exponential 1s→2s→4s (cap 30s); honor Retry-After on 429
  • Edge: CDN for static assets; API at origin; optional edge auth refresh — not for SSE body

Deep Dive

~10 min · Pick 1–2 areas the interviewer cares about
▼

Say: “I'll go deep on Performance and Security — happy to switch if you prefer observability or testing.”

  • Virtualization: react-window/virtuoso; dynamic height cache; pin streaming row outside virtualizer or as last item
  • Streaming render: rAF batch + incremental markdown blocks; defer Shiki until fence closes
  • Backpressure: pause ReadableStream read(); coalesce tokens; shed highlight under load
  • TTFT: optimistic bubble immediately; measure provider TTFB vs client paint separately
  • Sidebar 10k: metadata-only rows, cursor pagination, FTS index, IDB cache
  • Auth: JWT claims → ctx; Postgres RLS belt; org_id never from client body alone
  • XSS: Never dangerouslySetInnerHTML on full stream; escape code blocks; sanitize artifact sandbox
  • MCP trust: Egress allowlist; data minimization; audit log with input/output hashes
  • Uploads: Quarantine bucket; content firewall; never inject uploads into system role
  • Artifacts: iframe sandbox allow-scripts only; strict CSP; postMessage origin check
  • Idempotency: (user_id, key) unique — double confirm in 200ms → one booking
  • Client: tokens_received − tokens_rendered, frame p95, parse ms, stream recovery rate
  • Server: TTFT, generation duration, tool latency, 429/529 rates, checkpoint lag
  • Trace: request_id / generation_id across UI → BFF → provider
  • Product analytics: branch edits, tool confirms, stream interrupts (not user abort)
  • Unit: branch assembler, IR compile, markdown block parser, idempotency key derivation
  • Integration: SSE reducer with fixture event streams; tool confirm dedup
  • E2E: send → stream → stop; edit mid-thread → new branch; offline outbox drain
  • Load: virtualizer with 500 synthetic messages; stream at 100 chunks/sec
  • aria-live="polite" on message region; aria-busy until first token
  • Stop button keyboard accessible; focus trap in confirm modal
  • Reduced motion: disable typing dot bounce
  • i18n: RTL composer; locale-aware dates in sidebar; CJK token estimate caveat

Interview close (30 sec)

Three patterns I'd repeat: (1) server graph is source of truth with client optimism, (2) idempotency keys + stream cursors for duplicate actions and duplicate bytes, (3) bounded failure domains — sandbox kill, stream checkpoint, auth pause — never freeze the whole app.
