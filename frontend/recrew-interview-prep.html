Curry
function curry(fn) { return function curried(...args) { if (args.length >= fn.length) return fn(...args); return (...more) => curried(...args, ...more); }; }
Debounce
function debounce(fn, delay) { let timer; return function(...args) { clearTimeout(timer); timer = setTimeout(() => fn.apply(this, args), delay); }; }
Throttle
function throttle(fn, limit) { let inThrottle; return function(...args) { if (!inThrottle) { fn.apply(this, args); inThrottle = true; setTimeout(() => inThrottle = false, limit); } }; }
Promise.all from scratch
function myPromiseAll(promises) { return new Promise((resolve, reject) => { const results = []; let count = 0; promises.forEach((p, i) => { Promise.resolve(p).then(val => { results[i] = val; if (++count === promises.length) resolve(results); }).catch(reject); }); }); }

Array.prototype.myMap = function(fn) { const result = []; for (let i = 0; i < this.length; i++) { result.push(fn(this[i], i, this)); } return result; };

Virtual DOM & Reconciliation

React maintains a lightweight copy of the real DOM (Virtual DOM). When state changes:

  1. React creates a new virtual DOM tree
  2. Diffs it against the previous virtual DOM (reconciliation)
  3. Calculates the minimal set of changes
  4. Updates only those nodes in the real DOM

Why keys matter: Keys help React identify which items changed, were added, or removed. Without unique keys in lists, React falls back to index-based diffing which leads to unnecessary re-renders and state bugs.

React.memo + useCallback combo
// Parent const handleClick = useCallback(() => { doSomething(); }, [deps]); // Child — won't re-render if props unchanged const Child = React.memo(({ onClick }) => { return <button onClick={onClick}>Click</button>; });

Common pitfall: Passing a new object/function inline defeats memoization. Always use useCallback for functions passed as props, and useMemo for expensive computed values.

useEffect infinite loop — why does this happen?
// ❌ BAD: fetchData recreated every render useEffect(() => { fetchData(); }, [fetchData]); // re-creates function → infinite loop // ✅ GOOD: wrap in useCallback const fetchData = useCallback(() => { ... }, []); useEffect(() => { fetchData(); }, [fetchData]);

Why: The dependency array includes fetchData, which is re-created on every render (function objects are not equal by reference). Effect runs → state updates → component re-renders → fetchData recreated → effect runs again. Fix: memoize with useCallback.

useState functional updates
// ❌ BAD: stale state in async/batched updates setCount(count + 1); // ✅ GOOD: always use updater function setCount(prev => prev + 1);

Why: In concurrent mode or batched updates, count may be stale by the time the update executes. The updater function always receives the latest state, eliminating race conditions.

React Native New Architecture

Old Architecture: JS Bridge — asynchronous, JSON serialization bottleneck between JS and Native threads.

New Architecture (2024+):

  • JSI (JavaScript Interface) — synchronous native calls, no serialization overhead
  • Fabric — new rendering system, direct shadow tree communication
  • TurboModules — lazy-loaded native modules, type-safe with C++
  • Hermes — optimized JS engine for RN (faster startup, lower memory, AOT bytecode compilation)

Just knowing this exists puts you ahead for a "basics" round — shows senior-level awareness.

StyleSheet.create() vs inline styles
// ❌ Inline — creates new object on every render <View style={{ flex: 1, backgroundColor: '#fff' }} /> // ✅ StyleSheet — created once, IDs passed across bridge const styles = StyleSheet.create({ container: { flex: 1, backgroundColor: '#fff' }, }); // <View style={styles.container} />

Why it matters: StyleSheet.create creates an object once on the JS side and sends lightweight IDs over the bridge instead of full style objects on every render. More performant, especially for lists.
