30Objective Metrics for TTS

The proxies you can actually run in CI — MCD, WER through an ASR, speaker-embedding cosine — what each one is a distance in, and the systems where each confidently disagrees with the listeners.

Theory

What the three proxies measure

Mel-cepstral distortion is a Euclidean distance between mel-cepstral coefficient vectors, read out in decibels: MCD = (10/ln 10) √(2 Σd=1..D(cd−çd)²), averaged over frames, with c0 dropped because it carries gain rather than spectral shape. It needs a reference recording of the same words, and it needs frames that correspond — synthesis almost never matches the reference's durations, so you align with DTW first or you are measuring rhythm and reporting it as spectrum. WER runs the synthesis through an ASR and scores the transcript against the prompt; the raw number is partly the recogniser's own error, so it only means something as a delta against that same ASR's WER on human reads of the same prompts down the same channel. Speaker-embedding cosine takes a verification embedding — an x-vector or ECAPA-TDNN — of the synthesis and of an enrolment clip and cosines them. The scale belongs to that embedding model, so a threshold is meaningless in the abstract: calibrate on same- and different-speaker pairs from held-out real audio and quote the operating point you chose.

Where each one diverges from listeners

MCD rewards proximity to one reference reading. A model trained under a pointwise loss sits near the conditional mean or median of the plausible realisations, which is exactly the over-smoothing listeners hear as flat — so an over-smoothed non-autoregressive system can beat a held-out human recording of the same sentence on MCD and lose the listening test. WER is blind in the opposite direction. ACR raters never see the prompt text, so a word dropped by an attention failure barely moves MOS while it dominates WER; and an ASR is robust to vocoder buzz that listeners find unpleasant, so an artefact-heavy system can transcribe perfectly. Whisper-class models also emit text over silence, which lands as insertions on a system whose only fault is a long trailing pause. Cosine similarity rewards copying the reference clip's channel — room reverb, mic colouration, codec — so the highest-similarity clone is often the one that dragged the acoustics along with the voice.

Learned MOS predictors

UTMOS, NISQA and DNSMOS regress a listening score directly and rank systems better than MCD does. They are still regressors fitted to particular listening tests: agreement is much stronger at the system level than per utterance, and on a system unlike anything in their training pool their behaviour is not something to bet a launch on. Fast screen, not verdict.

Measure on the wire, not on headphones

Mel warping is m = 2595 log10(1 + f/700). At 24 kHz the axis runs to m(12000) ≈ 3267 mel and the telephone band ends at m(3400) ≈ 1992, so about 39 % of the mel axis you are computing MCD over describes audio a PSTN leg discards. Run the metrics through the 8 kHz mu-law path the caller hears and the ranking changes. None of these three sees latency either: 0.1 MOS of naturalness bought with 200 ms more in an 800 ms turn is a regression, gated separately.

In CI, and with PHI

This is the gate a listening test cannot be. Two hundred prompts at ~5 s is 1,000 s of audio; at an illustrative ASR real-time factor of 0.05 that is 50 GPU-seconds, and MCD and cosine cost far less, so the whole sweep is about a minute per build. Keep the golden set consented and scripted rather than harvested from patient calls, run the ASR inside your own boundary rather than a vendor API, and if you must evaluate on real traffic keep transcripts and metrics under retention rather than the audio.

The characteristic failure

You ship the model that won the metric your tuning loop optimised. Every one of these becomes a target and stops being a measure: pushed on MCD, the model that wins is the one that hedges. Gate hard on ΔWER, which has a direction listeners agree with, screen on MCD and cosine, and re-check the correlation itself against a periodic listening test — the scatter below is what that check looks like.

The three metrics, as you would actually compute them

K = 10.0 / math.log(10.0) * math.sqrt(2.0)          # 4.3429 * 1.4142 = 6.1418

def mcd_frame(a, b):                 # a, b: mel-cepstral vectors, c0 dropped
    d = a[1:D + 1] - b[1:D + 1]      # c0 is gain, not spectral shape
    return K * math.sqrt(float(d @ d))

# Durations differ, so frame i of the synthesis is not frame i of the reference.
# Align first, or the number you report is rhythm mismatch wearing MCD's units.
path = dtw_path(ref_mcep, syn_mcep, cost=mcd_frame)      # monotonic, no skips
mcd  = sum(mcd_frame(ref_mcep[i], syn_mcep[j]) for i, j in path) / len(path)

# Intelligibility: WER against the SAME ASR's floor on human reads of the SAME
# prompts, through the SAME 8 kHz mu-law path the caller is listening on.
delta_wer = wer(asr(ulaw(synth)), prompt) - wer(asr(ulaw(human_ref)), prompt)

# Cloning similarity: cosine in a speaker-verification embedding space.
secs = cosine(spk_emb(synth), spk_emb(enrolment))
# A bare cosine is not a verdict. Calibrate on held-out same/different-speaker
# pairs, take the threshold at the EER operating point, and quote both.
thr = eer_threshold(same_pairs, diff_pairs)              # model-specific

The line I'd actually say

“I run three, and I know what each one lies about. MCD is a cepstral distance to one reference reading — it needs DTW first, or you're scoring duration mismatch — and because it rewards sitting near the conditional mean, an over-smoothed model can beat a real human recording on MCD and still lose the listening test. WER through an ASR is the one I actually gate on, as a delta against the recogniser's own floor on human reads of the same prompts, because it catches skipped and repeated words that MOS raters miss entirely — they never see the text. Speaker cosine is for cloning, and its scale belongs to the embedding model, so it means nothing until I calibrate a threshold on same- and different-speaker pairs.”

“Two things I'd insist on for telephony. Compute all of it through the 8 kHz mu-law path — roughly 39 % of the mel axis at 24 kHz is above the phone band, so wideband MCD is partly scoring audio the caller never hears — and remember none of the three sees latency, so they can all improve while the agent gets slower. The failure mode is Goodhart: whichever one the tuning loop optimises stops being a measure. I keep the correlation itself under test against a periodic listening panel.”

Takeaways

  • MCD is a distance, not a quality score. (10/ln 10)√(2Σ(cd−çd)²) over DTW-aligned frames with c0 dropped; un-aligned, it measures rhythm. It rewards hedging toward the reference, so over-smoothed systems win it and listeners don't.
  • Report ΔWER, never raw WER. Subtract the same ASR's error on human reads of the same prompts down the same channel. It catches the skips and repeats that ACR raters miss, and it is deaf to the vocoder buzz they hate.
  • A cosine needs a calibrated threshold. The scale is the embedding model's, and similarity rewards copying the reference clip's room and codec — the top-scoring clone may be the one that brought the reverb with it.
  • Evaluate on the wire. About 39 % of the 24 kHz mel axis sits above the 3.4 kHz phone band; metrics computed wideband rank systems the caller would rank differently. Latency is a separate gate — put it on Prometheus and Grafana, not in this suite.
  • Wire it into CI, and keep the correlation under test. Version the golden prompts and reference audio as Parquet, run the sweep in GitHub Actions, log per-build metrics to MLflow, and re-fit metric-versus-MOS against a periodic listening panel so Goodhart drift is visible.
  • PHI stays inside the boundary. A consented scripted golden set, ASR self-hosted rather than a vendor API, and transcripts plus metrics retained rather than caller audio.
