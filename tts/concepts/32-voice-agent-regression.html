32Regression Testing a Voice Agent

Replaying a golden call set through the whole ASR→LLM→TTS loop — asserting on meaning and milliseconds instead of waveform bytes, pacing the replay in real time so turn-taking races actually happen, and attributing each new failure to the stage that caused it.

Theory

What is under test is the loop, not the models

Every stage of a voice agent can pass its own unit tests while the assembled call is wrong, because the interesting failures live at the boundaries. The ASR emits a hypothesis one digit different; the LLM answers correctly for the text it was given; the TTS synthesises that answer faithfully; the caller is told the wrong copay. Nothing threw. So the regression suite has to be the whole loop: recorded caller-side audio pushed into the same ingress the carrier uses — 8 kHz mu-law, 20 ms packets at 50 per second, through the real jitter buffer — with the agent's own instrumentation captured per turn.

Capture, for every turn: the ASR partials and final with their timestamps, the endpoint decision time, the exact prompt sent to the LLM, its response and tool calls, the text chunks handed to TTS, time-to-first-audio, and the offset at which any barge-in cancellation landed. Without those intermediates a diff tells you the call changed. With them it tells you which stage changed it, which is the only form of the answer you can act on.

Assert on meaning and timing, never on bytes

Waveform equality is neither achievable nor desirable. Sampling temperature, VITS-style stochastic duration prediction and codec-LM sampling all make synthesis non-deterministic by design, and even greedy decoding is not bit-stable across a driver upgrade, a kernel change or a different batch size, because floating-point reduction order is not associative. A byte-diff suite is red on its first run and switched off by its second week — that abandonment, not a false green, is the characteristic failure mode here.

Assert instead on four things. Text: compare the text handed to the TTS, not a re-transcription of its output — it is exact and free, and re-running an ASR over your own speech only adds that recogniser's errors to yours. Entities: exact match on the fields that carry the risk — member ID, date of birth, dosage, appointment time. A 3 % WER that lands on the digits of a member ID is a different incident from 3 % spread over filler, and a corpus-level WER cannot tell them apart. Tool calls with their arguments. Timing: endpoint delay, first-audio latency against the roughly 800 ms at which a caller reads the pause as dead air, and the trailing audio still playing after a barge-in cancel.

Pace it in real time, or do not claim to test turn-taking

Endpointing hangover, jitter-buffer depth and barge-in cancellation are all wall-clock phenomena. If the harness pushes a golden WAV in as fast as it can read the file, a 300 ms hangover elapses in microseconds and the race between "vocoder is still emitting" and "cancel arrived" never happens. The suite goes green while callers get talked over. So pace the sender at 50 packets/s and pay for it: 120 golden calls averaging 75 s is 9,000 s of audio, two and a half hours run serially, or about 7.5 minutes at 20 concurrent sessions — and it costs 20 concurrent GPU-backed sessions for those minutes. Keep a fast text-in/text-out lane for prompt and tool changes on every commit, but do not let it certify anything with a millisecond in it.

Attributing a regression to a stage

Full factorial over three stages at two versions each is 2³ = 8 replays of the whole set. The cheaper structure is a ladder: A/A/A, B/A/A, B/B/A, B/B/B — four runs, each new failure attributed to the stage swapped at that rung. Use common random numbers across rungs (same seeds, same golden audio, same order) so a difference between rungs is the swap and not the sampling. The ladder is incomplete by construction: it cannot see an interaction that only appears when the new TTS meets the old ASR, so when it attributes nothing, fall back to the full eight. Pin model digests, decoding parameters, prompt-template version and the ASR's version string into every run's metadata — a vendor ASR that silently updates underneath you invalidates the baseline and you will confidently attribute its regression to your own commit.

Thresholds come from measured variance

Nothing here repeats exactly, so every timing assertion is a threshold and every threshold needs a baseline distribution. Replay the golden set K times against unchanged HEAD, take each call's mean and standard deviation per metric, and gate at roughly three standard deviations, or gate the set-level p95 rather than each call. Averaging N repeats shrinks the standard error as √N: a call whose first-audio latency has sd 45 ms, measured once, trips a ±50 ms tolerance about 27 % of the time (2(1−Φ(50/45))); at N = 9 the standard error is 15 ms and the same tolerance trips under 0.1 %. That is the whole flake budget in one line — tighten the tolerance or raise the repeats, and pay in wall clock either way.

The golden set is PHI

Real calls are the best test material and the worst artifact to hold. Prefer scripted, consented recordings that reproduce the distribution that matters — accents, speakerphones, hold music, mobile dropouts — rather than harvested patient audio. If production calls must be minted into fixtures, do it under consent and de-identification, keep them inside your boundary with a retention clock, and remember the run artifacts inherit the classification: the transcripts, prompts and tool arguments a regression run writes are PHI too, not just the audio.

The assertion set and the attribution ladder

TOL_MS   = 50          # from 3*sd of K baseline replays, not from taste
WER_TOL  = 0.010       # absolute, and only ever as a delta vs the same ASR's floor

def assertions(turn, base):
    yield "entities",  turn.entities == base.entities            # exact: member ID, DOB, dose
    yield "tools",     turn.tool_calls == base.tool_calls         # exact: name AND arguments
    yield "wer",       turn.wer - base.wer <= WER_TOL
    if PACING == "realtime":        # the fast lane must not certify these
        yield "first_audio", turn.first_audio_ms - base.first_audio_ms <= TOL_MS
        yield "endpoint",    turn.endpoint_ms    - base.endpoint_ms    <= TOL_MS
        if base.barge_in:
            yield "trailing",  turn.trailing_ms  - base.trailing_ms    <= TOL_MS

# Ladder: 4 replays instead of the 2**3 = 8 of a full factorial. Common random
# numbers across rungs -- same seeds, same audio, same order -- so a rung-to-rung
# difference is the swap and not the sampling.
LADDER = [set(), {"asr"}, {"asr", "llm"}, {"asr", "llm", "tts"}]

def attribute(call, name):
    prev = None
    for rung, swapped in enumerate(LADDER):
        ok = replay(call, swapped).passes(name)
        if not ok and rung == 0:
            return "FLAKE"            # fails with nothing swapped => it is noise
        if prev and not ok:
            return sorted(swapped - LADDER[rung - 1])[0]
        prev = ok
    return None                       # never failed: an interaction, run the full 8

The line I'd actually say

“I replay a golden call set through the whole loop — real SIP ingress, 8 kHz mu-law, 20 ms packets — and I assert on meaning and milliseconds, never on waveform bytes. Synthesis is stochastic by design and isn't even bit-stable across a driver upgrade, so a byte-diff suite is red on day one and disabled by week two. So: exact match on entities and tool arguments, delta WER against that same recogniser's floor, and timing — endpoint delay, first-audio latency, trailing audio after a barge-in cancel.”

“The thing I'd insist on is pacing the replay in real time. If you shove the WAV in as fast as you can read it, a 300 ms endpointing hangover elapses in microseconds and the barge-in race never happens — the suite is green while callers are getting talked over. And for attribution I run a ladder rather than a full factorial: baseline, then ASR, then ASR+LLM, then all three, with common random numbers, so each new failure lands on the stage swapped at that rung. That's how you catch the compounding case where a better ASR hears one digit differently, the LLM answers perfectly for what it was given, and the caller still gets the wrong member ID read back.”

Takeaways

  • Test the loop, not the stages. Every model can pass its own contract while the call is wrong — a one-digit ASR change propagates through a correct LLM and a faithful TTS. Capture per-turn intermediates (hypotheses, prompts, tool calls, chunk timings) or a diff can only tell you the call changed, not who changed it.
  • Assert on meaning and milliseconds, never on bytes. Stochastic duration, sampling and non-associative float reductions make waveform equality impossible; the failure mode is a suite everyone disables. Gate entities and tool arguments exactly, WER as a delta, and latency against the 800 ms budget.
  • Real-time pacing is the whole point. 50 packets/s or turn-taking races never occur. 120 calls × 75 s = 9,000 s of audio: 2.5 h serial, ~7.5 min at 20 concurrent sessions. Keep a fast text-only lane for prompt changes, but never let it certify a timing assertion.
  • A ladder attributes; a factorial confirms. Four replays (A/A/A → B/B/B) with common random numbers pin each failure to a stage; when nothing is attributed, it is an interaction and you owe the full 2³. Pin model digests and the vendor ASR's version string into run metadata or you will blame your own commit.
  • Thresholds come from baseline variance. sd 45 ms at N = 1 trips a ±50 ms gate ~27 % of the time; at N = 9 the SE is 15 ms and it trips under 0.1 %. Store the per-build metrics in MLflow and the golden manifest as Parquet, run the fast lane in GitHub Actions, and page off Prometheus and Grafana for the same metrics in production.
  • The fixtures and the run artifacts are both PHI. Prefer scripted consented recordings over harvested patient audio; if you mint from production, de-identify, keep it in-boundary and retention-bound, and classify the transcripts and tool arguments the run writes the same way as the audio.
