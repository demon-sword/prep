29MOS, CMOS and Subjective Evaluation

Listening tests remain the ground truth for naturalness, and most of the ones you will read are underpowered. What the scale measures, how many raters buys a real difference, and why pairing beats a bigger panel.

Theory

The scale, and what it is a scale of

Mean Opinion Score is the average of a listening panel's category ratings. ITU-T P.800 fixes the instrument: Absolute Category Rating puts one stimulus in front of a listener and asks for a score on a five-point scale — 5 excellent, 4 good, 3 fair, 2 poor, 1 bad. The scale is ordinal, so the mean is a convention rather than a measurement, and each number judges one stimulus in isolation, which is where the trouble starts. P.800's Comparison Category Rating instead puts both systems in front of the same listener for one relative judgement on a seven-point scale, −3 (much worse) through 0 to +3 (much better); the mean of those is CMOS. Also worth naming: MUSHRA (ITU-R BS.1534), a 0–100 scale with a hidden reference and low anchor, and P.808, which makes crowdsourced testing defensible with headphone screening and trapping questions.

Why an absolute MOS does not travel

A MOS is a property of a test, not a system: listeners calibrate to the range shown, so a bad anchor lifts everything above it, and panel, wording, order, text and playback path all move it. Name that last one in a telephony interview — a 24 kHz render judged on studio headphones says little about the 8 kHz mu-law leg, where the band above 3.4 kHz carrying the cue for s, f and th is gone. Test through the codec path you ship.

How many ratings you actually need

At α = 0.05 and 80 % power an independent-samples comparison needs n = 2σ²(z.975+z.80)²/δ² ratings per system. Take σ = 0.9 on the five-point scale — illustrative, but the right order — and δ = 0.1 MOS: 2 × 0.81 × 2.80² / 0.01 ≈ 1,300. Nor are those ratings independent: a listener who marks everything low adds the same offset to every rating they give. Kish's design effect 1 + (m−1)ρ is the correction — at ICC ρ = 0.35 with 10 utterances each it is 4.15, so an interval computed as if the ratings were independent is √4.15 ≈ 2.0× too narrow, and the real requirement is 1,300 × 4.15 ≈ 5,300 per system — 1,056 listeners, which nobody recruits. That number is why the next section exists.

Why a paired design beats a bigger panel

Model a rating as μsystem + blistener + e. Between listeners, each system goes to a different group, so the SE of the difference carries the b term and extra utterances per listener never shrink it — only more listeners will. Have the same listener rate both and b cancels exactly, leaving 2σe²/(mn): the 5,300 becomes 830. CMOS drops the factor of two as well — one judgement of the difference rather than two noisy absolute ones — so about 260 judgements. Pairing cancels a listener's additive offset, not their scale usage.

The characteristic failure

Not the test that misses — the underpowered test that finds something. When power is low, the only estimates clearing significance are those that landed far from zero, so the reported effect is inflated (Gelman and Carlin's Type M) and a real fraction point the wrong way (Type S). “+0.3 MOS, p < 0.05” on twenty listeners is decorated noise — hit resample below.

In a healthcare voice product

Crowd listeners sit outside your BAA, so recorded patient calls cannot go to a panel — use a consented scripted corpus mirroring the real content, versioned as an artifact. And utterance MOS is blind to what callers complain about: a voice 0.1 MOS better that adds 200 ms to an 800 ms turn is worse on the phone. Conversational quality is its own test (P.805), latency its own gate.

The model behind the simulator

# rating = system effect + listener's standing offset b + judgement noise e,
# b[i] ~ N(0, sb2), and rho = sb2/(sb2+se2) is the listener ICC.
sb2 = rho * sigma**2
se2 = (1.0 - rho) * sigma**2

def se_delta(design, n_listeners, m_items):
    if design == "ACR_between":     # each listener hears ONE system
        per = sb2 + se2 / m_items   # variance of one listener's mean
        return sqrt(2.0 * per / (n_listeners / 2))   # b never averages out
    if design == "ACR_within":      # same listener rates both -> b cancels
        return sqrt(2.0 * se2 / (m_items * n_listeners))
    if design == "CMOS":            # ONE CCR judgement per pair, -3..+3
        return sqrt(kappa**2 * se2 / (m_items * n_listeners))

se     = se_delta(design, n_listeners, m_items)
z      = 1.959964                          # alpha = 0.05, two-sided
power  = Phi(delta/se - z) + Phi(-delta/se - z)
wrong  = Phi(-delta / se)                  # the higher mean is the worse system
type_s = Phi(-delta/se - z) / power        # significant, and backwards

# SE**2 = C/R in every design above, so the required R is exact:
n_ind = 2 * sigma**2 * (1.959964 + 0.841621)**2 / delta**2
deff  = 1.0 + (m_items - 1) * rho     # Kish clustering correction
need  = {"ACR_between": n_ind * deff,           # 1272*4.15 = 5277/system
         "ACR_within":  n_ind * (1 - rho),      # b cancels -> se2 share
         "CMOS": n_ind * (1 - rho) * kappa**2 / 2}[design]

The line I'd actually say

“MOS is still the ground truth for naturalness, but it's a property of the test, not of the system — listeners calibrate to whatever range you show them, so my MOS and a paper's aren't comparable. Both systems go in one test, or I don't quote a difference. What most listening tests get wrong is power: at a rating SD around 0.9, detecting 0.1 MOS at 80 % needs roughly 1,300 independent ratings per system, and ratings cluster by listener — at an ICC around 0.35 with ten utterances each the design effect is 4.15, so you really need 5,300, a thousand listeners. That's why I'd reach for CMOS: the same listener judges the pair, their offset cancels, and you measure the difference directly instead of subtracting two noisy absolute scores.”

“The failure mode isn't a test that misses; it's an underpowered test that finds something — the estimates clearing significance are the ones that landed far from zero, so the effect is inflated and sometimes backwards. For telephony, two additions: play the stimuli through the real 8 kHz mu-law path, since headphones hide exactly the band the phone throws away, and never send recorded patient calls to a crowd panel.”

Takeaways

  • A MOS is a test result, not a system property. Range and anchor effects make it meaningful only against the other systems in the same test; cross-paper MOS comparisons are not evidence.
  • Do the power arithmetic first. 2σ²(z.975+z.80)²/δ² ≈ 1,300 independent ratings per system for 0.1 MOS at σ = 0.9, then multiply by the design effect 1+(m−1)ρ because ratings cluster: 4.15× at ρ = 0.35 and m = 10, so 5,300 real ratings — 1,056 listeners.
  • Pair whenever you can. Within-listener ACR cancels the listener offset and CMOS also removes the factor of two, cutting those 5,300 ratings to about 830 and 260. Both beat the panel expansion buying the same SE.
  • Underpowered and significant is the dangerous cell. Type M inflates the effect, Type S can flip its sign: “p < 0.05 on 20 listeners” is a reason to rerun, not to ship.
  • Evaluate through the path you ship. 8 kHz mu-law playout, not headphones; a consented scripted corpus rather than recorded PHI; latency gated separately. Version the corpus as Parquet, log each panel run and its CI to MLflow, and let GitHub Actions block only on objective proxies — a listening test is too slow for CI.
