07Grapheme-to-Phoneme Conversion

Turning orthography into pronunciation — lexicon lookup for the common case, a learned G2P model for out-of-vocabulary words and names, and why IPA versus ARPAbet is a real engineering choice rather than notation preference when you mix datasets.

Theory

A dispatcher, not a model

Once normalization has turned every token into words, something has to turn those words into the phone sequence the acoustic model actually conditions on. English will not let you do that with rules: ough alone carries at least half a dozen readings — through, though, thought, tough, cough, plough — and none of them is predictable from the letters. So production G2P is a dispatcher with a learned model at the bottom, not a model with a lexicon bolted on: homograph table → tenant overlay → pronunciation lexicon → learned model → cache. Each layer exists because the one below it is wrong in a specific way.

The lexicon does most of the work. CMUdict carries roughly 134,000 English entries in ARPAbet with a stress digit on every vowel — 0 unstressed, 1 primary, 2 secondary — so appointment is AH0 P OY1 N T M AH0 N T. On the general-English body of a call the hit rate is high. The tail it misses is precisely the tail that matters on a healthcare line: surnames, town names, clinic and insurer names, drug names.

The model behind the lexicon

Classical G2P is joint-sequence: Sequitur aligns graphemes to phonemes into multigrams and runs an n-gram over the joint symbols; Phonetisaurus compiles the same idea into a weighted finite-state transducer and decodes it with OpenFst. The modern replacement is a small seq2seq — a BiLSTM with attention, or a two-to-four-layer transformer of a few million parameters — characters in, phones out, decoded autoregressively. Both are scored with phone error rate (phone edit distance over reference length) and word error rate (a word is wrong if any phone is). WER on genuinely unseen words is the number that matters, and it is not small — which is the whole argument for lexicon-first ordering: you only pay the model's error rate on words nothing else could answer.

ARPAbet versus IPA is an engineering choice

ARPAbet is ASCII, English-only, 39 phones in the CMUdict inventory, stress carried as a digit glued to the vowel. IPA is universal, Unicode, and what eSpeak-NG-driven phonemizers used by many open TTS recipes emit. The symbol set is your model's input embedding table, so it is not swappable after training — and mapping between the two is not a bijection. CMUdict's AH is /ʌ/ when stressed and /ə/ when it is AH0, so ARPAbet→IPA needs the stress digit as an input, not just the letters; ER splits into /ɝ/ and /ɚ/ the same way. In the other direction, IPA distinctions English does not use collapse onto the nearest ARPAbet symbol. Mix two corpora without a checked mapping and two symbols end up meaning one sound, each trained on half the data.

The failure mode, and where it lands

G2P is confidently wrong on exactly the words that matter. A mispronounced surname is synthesised in the same fluent voice as a correct one: nothing throws, no confidence score reaches the caller, and the downstream vocoder has no idea. On an 8 kHz narrowband leg it is worse, because the listener has less acoustic evidence to repair the error — the band separating /s/, /f/ and /θ/ sits above the 3.4 kHz the phone network keeps.

Latency is the easy part. A lexicon hit is a hash lookup; the model runs only on a chunk's out-of-vocabulary words, batches, and caches on the word string, so a clinic's vocabulary goes warm within minutes of a shift. Take a 15-word streamed chunk at 2% OOV: 0.3 words reach the model, and at a few milliseconds each that is roughly 1 ms against a ~150 ms time-to-first-audio target. G2P is a quality risk, not a latency risk — the effort belongs in the overlay lexicon and the SSML <phoneme ph="…"> escape hatch, not in shaving its decode. 

# G2P dispatch: homograph -> tenant overlay -> lexicon -> model, with an OOV cache.
ARPA_IPA = {"AA":"ɑ","AE":"æ","AO":"ɔ","EH":"ɛ","IH":"ɪ","IY":"i","UH":"ʊ","UW":"u",
            "EY":"eɪ","OW":"oʊ","AY":"aɪ","AW":"aʊ","OY":"ɔɪ", # … consonants omitted}

def arpa_to_ipa(phones):
    out = []
    for p in phones:
        stress = p[-1] if p[-1].isdigit() else None
        base   = p[:-1] if stress else p
        # The two mappings that need the stress digit, not just the letters:
        if   base == "AH": sym = "ə" if stress == "0" else "ʌ"
        elif base == "ER": sym = "ɚ" if stress == "0" else "ɝ"
        else:              sym = ARPA_IPA[base]
        # IPA stress belongs before the syllable onset; placing it on the
        # vowel is an approximation until you have syllabified.
        out.append({"1":"ˈ","2":"ˌ"}.get(stress,"") + sym)
    return "".join(out)

def g2p(word, pos=None):
    key = word.lower()
    if key in HOMOGRAPHS: return HOMOGRAPHS[key][pos or "NN"]   # needs the POS tag
    if key in OVERLAY:    return OVERLAY[key]                   # curated, per tenant, PHI
    if key in CMUDICT:    return CMUDICT[key]                   # ~134k entries, ~1 us
    if key in oov_cache:  return oov_cache[key]
    phones = model.decode(key)          # few ms/word on CPU — illustrative
    oov_cache[key] = phones             # LRU; clinic vocabulary goes warm fast
    return phones
Homographs are not G2P's problem to solve alone. read, live, lead and record need a part-of-speech tag that the characters do not carry. That tag comes from the normalization stage in front of G2P — which is why the two are usually one component with one context window, not two services.

The line I'd actually say

"G2P is a dispatcher, not a model. Homograph table first because record needs a POS tag, then a per-tenant overlay of the names this clinic actually says, then CMUdict, then a small seq2seq for what's left, with an LRU on the word string. The neural model is the last resort on purpose — its word error rate on genuinely unseen words is high enough that you don't want it answering anything a lexicon could have."

"The failure mode is that it's confidently wrong on surnames and drug names, and nothing downstream can tell — it gets synthesised in the same fluent voice, and on an 8 kHz line the caller has less acoustic evidence to repair it. Latency isn't the issue: a couple of percent OOV on a 15-word chunk is about a millisecond against a 150 ms time-to-first-audio budget. Two things I'd watch — keep ARPAbet and IPA from mixing silently, because AH maps to schwa or /ʌ/ depending on the stress digit and a careless mapping trains two symbols on one sound; and treat the overlay of patient surnames as PHI, because a list of names with pronunciations is a list of identifiers."

Takeaways

  • Order the layers, don't pick one. Homograph table → tenant overlay → CMUdict (~134k entries) → learned model → LRU cache. Each layer only sees what the one above genuinely could not answer, so you pay the model's word error rate on the smallest possible slice.
  • The symbol set is the embedding table. ARPAbet is ASCII and English-only; IPA is Unicode and universal. The mapping is not a bijection — AH0 is /ə/ but AH1 is /ʌ/, so stress is an input to the conversion. Mix corpora without checking it and two symbols split the data for one sound.
  • Wrong is silent. No exception, no confidence signal reaching the caller, and on an 8 kHz narrowband leg the fricative cues that would let a listener self-repair are already gone. Ship a curated overlay and an SSML <phoneme> escape hatch, and export OOV rate per tenant to Prometheus as the leading indicator.
  • Latency is not the constraint here. 2% OOV on a 15-word chunk is ~0.3 model calls, roughly 1 ms of a ~150 ms TTFA. Train the seq2seq in PyTorch, export to ONNX and run it in-process next to normalization rather than adding a network hop; back the shared cache with Redis so a warm clinic vocabulary is warm for every media host.
  • Homographs belong upstream. The POS tag that separates read from read comes from the normalization stage, so keep normalization and G2P as one component with one context window.
  • A pronunciation overlay of patient surnames is PHI. It is a list of identifiers with a per-tenant scope; give it the same retention, access control and deletion path as the recorded audio, not the config repo.
