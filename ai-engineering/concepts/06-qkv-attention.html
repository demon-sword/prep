Transformers

Query, Key, Value Attention

Self-attention mechanism: Q/K/V projections, scaled dot-product attention, softmax, multi-head attention, and causal masking.

Theory

The Core Insight: Differentiable Lookup

Attention is best understood as a soft, differentiable key-value store lookup. Imagine a database of key-value pairs. To retrieve a value, you supply a query and compare it to every key; the similarity scores determine how much of each value you blend together. The transformer makes this entire process end-to-end differentiable by parameterizing Q, K, and V as learned linear projections of the same input sequence.

Formally, given an input matrix X ∈ ℝ^{n×d_model}, three learned weight matrices project it into queries, keys, and values:

Q = X·W_Q  |  K = X·W_K  |  V = X·W_V
W_Q, W_K ∈ ℝ^{d_model × d_k}  |  W_V ∈ ℝ^{d_model × d_v}

The dot product Q·Kᵀ computes a raw similarity between every query-key pair, producing an n×n score matrix. This is scaled by √d_k to prevent the softmax from saturating (at large d_k, dot products grow in magnitude, pushing gradients to near-zero), then normalized via softmax to get attention weights, then applied to values:

Attention(Q, K, V) = softmax( Q·Kᵀ / √d_k ) · V

Why the √d_k Scaling Matters

If Q and K are initialized with unit variance, their dot product has variance d_k. Without scaling, for d_k = 64 (typical in GPT-2), dot products have std ≈ 8, pushing softmax into regions where gradients vanish. Dividing by √64 = 8 restores unit variance. This is not just a stability trick — without it, training is qualitatively harder, especially in the first few layers.

Multi-Head Attention

Single-head attention computes one set of attention patterns. But language requires attending to different relationships simultaneously: subject-verb agreement, coreference, positional adjacency, semantic similarity. Multi-head attention runs h independent attention heads in parallel, each with its own projection matrices:

head_i = Attention(X·W_Qᵢ, X·W_Kᵢ, X·W_Vᵢ)
MultiHead(X) = Concat(head₁, ..., headₕ) · W_O
where W_Qᵢ, W_Kᵢ ∈ ℝ^{d_model × (d_model/h)}

In GPT-style models, d_model is split evenly across heads: GPT-2 (1.5B) uses h=25 heads with d_k=64. GPT-3 uses h=96 heads with d_k=128. The output projection W_O ∈ ℝ^{d_model × d_model} mixes information across heads. Empirically, different heads specialize: some attend to local context, others to distant syntactic dependencies. This is verified via probing experiments — ablating individual heads shows measurable degradation on specific linguistic tasks.

Causal Masking for Autoregressive Models

Decoder-only models (GPT, Llama, etc.) must not allow token i to attend to token j > i during training — that would let the model cheat by peeking at future tokens. Causal masking sets the upper triangle of the attention score matrix to -∞ before softmax, making those positions contribute zero weight after exponentiation. The result is a lower-triangular attention pattern.

This masking is the reason decoder-only models can be trained with a simple next-token prediction objective: every position predicts its next token in parallel using only its causal context. Encoder models (BERT) use full bidirectional attention (no mask) and are trained with masked language modeling (MLM) instead.

KV Cache: The Inference-Critical Optimization

During autoregressive decoding, each new token needs to attend to all prior tokens. Without caching, this requires recomputing K and V for all previous positions at every step — O(n²) work total for a sequence of length n. The KV cache stores K and V matrices for all past tokens; each step only computes Q/K/V for the new token and appends to the cache.

KV cache memory cost: for a model with L layers, h heads, d_k per head, sequence length n, and batch size B, in FP16: 2 × L × B × n × h × d_k × 2 bytes. For Llama-2-70B with n=4096 and B=1: ~≈17 GB just for the cache. This is why long-context inference is memory-bound, not compute-bound.

Grouped-Query Attention (GQA) and Multi-Query Attention (MQA)

To reduce KV cache size, Multi-Query Attention (Shazeer 2019) shares a single K and V across all query heads — slashing cache by factor h at the cost of some expressivity. Grouped-Query Attention (Ainslie et al. 2023, used in Llama-2-70B) groups h query heads into g groups, each sharing one K/V pair. GQA reduces cache by h/g while maintaining most quality — Llama-2-70B uses 8 KV heads for 64 query heads (8× reduction). This is now the dominant pattern in production models.

Flash Attention: Memory-Efficient Exact Attention

Naive attention materializes the full n×n score matrix in HBM (GPU memory), which costs O(n²) memory and creates expensive memory I/O. FlashAttention (Dao et al. 2022) tiles the computation to stay within SRAM (L2 cache), computing attention in blocks without ever materializing the full matrix. This reduces HBM reads/writes from O(n²) to O(n), achieving 2–4× wall-clock speedup for sequence lengths ≥ 1K. FlashAttention-2 adds better parallelism across sequence positions; FlashAttention-3 exploits H100 TMA hardware. All major frameworks (PyTorch, JAX) use Flash variants by default.

Positional Encoding and Attention

Attention itself is permutation-invariant — it has no sense of token order. Position must be injected separately. In the original transformer: absolute sinusoidal PE added to embeddings before attention. Modern LLMs use RoPE (Rotary Position Embedding, Su et al. 2021): rotation matrices applied to Q and K at each attention head so that inner products naturally encode relative distance. RoPE generalizes better to sequence lengths beyond training — RoPE + YaRN / ALiBi extensions allow extrapolation to 128K+ token contexts. Llama-2, Mistral, and GPT-NeoX all use RoPE.

Key Takeaways

  • The √d_k scaling is not cosmetic — without it, dot products grow proportional to √d_k, saturating softmax and killing gradients in large heads. In GPT-3 (d_k=128), unscaled std ≈ 11, causing near-zero gradients in all but the max-scoring pair.
  • KV cache is why long-context inference is memory-bound: a 70B model serving 32K tokens with B=8 needs ~70GB for the KV cache alone. GQA (Llama-2-70B uses 8 KV heads for 64 query heads) reduces this 8× with minimal quality loss — now the standard pattern in production-grade models.
  • FlashAttention-2 does not reduce FLOPs — it reduces HBM memory bandwidth usage by tiling to SRAM. The speedup (2–4×) is entirely from avoiding the O(n²) memory write of the attention matrix, making long-context training 4–8× more memory-efficient.
  • Different attention heads provably specialize: syntactic heads track subject-verb dependencies, positional heads handle local context, semantic heads do long-range coreference. Head pruning experiments (Michel et al. 2019) show 50–70% of heads can be removed from BERT with <1% task degradation — but which heads matter depends on the task.
  • RoPE (used in Llama, Mistral, Falcon) encodes relative position via rotation, making attention scores decay naturally with distance and enabling better length extrapolation vs. learned absolute embeddings. Combining RoPE with YaRN or dynamic NTK scaling lets models generalize from 4K→128K tokens without full retraining.
  • Causal masking is what enables teacher-forcing: the entire sequence is processed in one forward pass with O(n) parallelism during training. At inference, this collapses to sequential token-by-token generation, which is why prefill (parallel) is compute-bound and decode (sequential) is memory-bound.
