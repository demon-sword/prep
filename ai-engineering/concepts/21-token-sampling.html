Token Sampling: Temperature, Top-K, Top-P

How LLMs select the next token — temperature scaling, top-K filtering, and nucleus (top-P) sampling — and how each reshapes the distribution between diversity and coherence.

Theory

The Fundamental Problem: Turning Logits into a Token

An LLM's final layer produces a vector of logits — one raw score per vocabulary token (a frontier model vocabulary: ~100K tokens, Llama-3: 128K, BERT: 30K). These raw scores are unbounded real numbers. To sample a next token, we must convert them to a valid probability distribution. The process: logits → softmax → probability distribution → sample one token. The design choices made between "softmax" and "sample" define the entire character of the model's output.

Softmax and the Logit Landscape

Standard softmax: P(i) = exp(z_i) / Σ exp(z_j). The exponential function naturally concentrates probability mass — a logit difference of just 5 translates to roughly 150× higher probability. This means a model's raw output is already quite "peaky" around high-confidence tokens. The sampling strategies below all operate on this post-softmax distribution (or on logits before the division, in the case of temperature).

Temperature Scaling

Temperature (T) is applied before softmax by dividing all logits by T: 

P(i) = exp(z_i / T) / Σ exp(z_j / T)

T < 1.0 (cold): dividing by a small number amplifies logit differences — the distribution sharpens and becomes more deterministic. At T → 0, sampling becomes greedy argmax (always pick the highest-probability token). Models become repetitive, factual-but-boring.
T = 1.0: the raw model distribution — whatever the model actually learned.
T > 1.0 (hot): dividing by a large number compresses logit differences — the distribution flattens. Tokens that were nearly impossible now have non-trivial probability. Output becomes more creative, surprising, and eventually incoherent.

Typical production values: T = 0.0–0.3 for factual/code tasks; T = 0.7–1.0 for creative writing; T = 1.2–2.0 for brainstorming or diversity sampling. OpenAI API default: 1.0. Many practitioners set T = 0 for evals and classification.

Top-K Sampling

Top-K truncates the distribution to only the K highest-probability tokens, then renormalizes: 

Vocabulary ─► keep top K tokens ─► zero out the rest ─► renormalize ─► sample

Why it helps: prevents the model from ever selecting incoherent low-probability tokens, even at high temperature. Key problem: K is fixed regardless of the distribution shape. When the model is very confident (one token at 95% probability), K=50 still allows 49 nearly-zero-probability alternatives. When the model is genuinely uncertain (50 tokens each at 2%), K=10 eliminates most viable alternatives. The fixed K ignores the natural shape of the distribution.

Typical values: K = 10–50 for most tasks. GPT-2 defaults: K = 50. K = 1 is greedy decoding.

Top-P / Nucleus Sampling

Nucleus sampling (Holtzman et al., 2020) fixes Top-K's shape-blindness by selecting a dynamic K: keep the smallest set of tokens whose cumulative probability exceeds threshold P: 

Sort tokens by probability descending → accumulate → stop when cumsum ≥ P → renormalize

When the model is confident: cumsum hits P = 0.9 after just 1–3 tokens → small nucleus → conservative sampling. When uncertain: cumsum hits P = 0.9 after 50+ tokens → large nucleus → more exploratory sampling. The nucleus adapts to the model's certainty at each step.

Typical values: P = 0.9–0.95 for most creative tasks; P = 1.0 disables filtering entirely. Anthropic Claude API default: top_p = 1.0 (off). OpenAI default: 1.0 but recommends not combining with temperature.

Combining Strategies

The practical order of operations: logits / T → softmax → top-K filter → top-P filter → renormalize → multinomial sample. Most frameworks apply them in this order. The OpenAI and Anthropic APIs warn against setting both temperature and top_p away from their defaults simultaneously — the interaction can produce unexpected sharpness or flatness. A common production recipe: either use temperature alone, or top-P alone, with temperature set to 1.0.

Min-P Sampling (Emerging)

A newer approach (used by LM Studio, llama.cpp): filter out any token whose probability is below min_p × max_probability. This is scale-invariant — the threshold moves with the distribution peak. min_p = 0.05 means "never pick a token less than 5% as likely as the best token." This avoids both Top-K's fixed-K problem and Top-P's behavior at extreme confidence levels.

Greedy vs Beam vs Sampling

Greedy decoding (T=0, K=1) is deterministic and fast but notoriously degenerate — prone to repetition loops and locally optimal but globally bad sequences. Beam search maintains N best partial sequences simultaneously, exploring more of the probability space but with O(N) cost and a bias toward short, generic outputs. Sampling (temperature + top-K/P) adds randomness that paradoxically produces more diverse and often higher-quality outputs for open-ended generation. For constrained tasks (translation, summarization), beam search can outperform sampling.

Production Reality: Why This Matters

Evaluation reproducibility: any temperature above 0 makes evals non-deterministic. Always set T = 0 for benchmarks, or run multiple samples and aggregate. Cost at scale: Best-of-N sampling (generate N completions, pick the best) multiplies cost by N — at T=0 this collapses to N identical outputs, wasting compute. Latency: sampling strategy itself adds negligible latency; the token generation loop dominates. Batch diversity: at T=0, you can batch identical prompts and all get identical outputs — cache them. At T>0, each is unique.

Tools like vLLM, TGI (Text Generation Inference), and llama.cpp all implement these sampling strategies in CUDA kernels for efficiency. vLLM's PagedAttention paper notes that at T=1 with top-P=0.9, GPU throughput is nearly identical to T=0 — the sampling step is not the bottleneck.

Gotcha: Temperature affects perplexity calculations. When computing perplexity for evaluation, always use T=1.0 (raw model distribution). Sampling temperature should never be applied to loss/perplexity metrics.
The repetition problem: even with temperature, models can enter repetition traps. Modern systems add repetition penalty (divide logits of recently used tokens by a penalty factor) or frequency penalty (subtract a penalty proportional to how often the token has appeared). These are applied before temperature scaling.

Key Takeaways

  • Temperature is a multiplier on uncertainty, not quality. T < 1 makes the model sycophantic toward its own priors — great for factual retrieval, terrible for diversity. T > 1 doesn't add knowledge; it just spreads mass to tokens the model weakly considered, which often produces hallucinations in factual domains.
  • Top-P is almost always better than Top-K for open-ended generation. Top-K's fixed cutoff doesn't adapt to distribution shape — at high-confidence steps it still wastes budget on near-zero tokens. Top-P (nucleus) contracts naturally. The original "The Curious Case of Neural Text Degeneration" (Holtzman 2020) empirically shows nucleus sampling produces more human-like text.
  • For evals, always use T = 0 or run multiple samples. Any T > 0 makes results non-deterministic. A 1-point benchmark difference might vanish across seeds. Major leaderboards (MMLU, HumanEval) typically eval at T = 0.
  • vLLM, TGI, and llama.cpp implement sampling in CUDA — it's essentially free latency. The bottleneck in decode phase is always memory bandwidth for KV cache, not the softmax+sample step. Don't optimize sampling for speed; optimize it for output quality.
  • Repetition penalty is underrated. Even with nucleus sampling, models can degenerate in long generations. llama.cpp's --repeat-penalty 1.1 with a context window of 64 past tokens is a practical default that prevents most looping without hurting output quality measurably.
  • Don't combine temperature and top-P simultaneously unless you understand the interaction. Most API providers document this warning. Use one primary lever: either tune temperature (with top-P = 1.0) or tune top-P (with temperature = 1.0). Mixing both creates non-obvious distribution shapes that are hard to reason about.
