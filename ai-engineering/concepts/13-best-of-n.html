Best-of-N & Beam Search

Inference-time compute scaling: generate multiple candidates, score with a reward model, and select the best — improving output quality without any retraining.

Theory

Best-of-N (BoN) and beam search are inference-time compute scaling strategies. Instead of accepting the first token sequence a model produces, you generate multiple candidates and pick the best one. This is a fundamental lever: you trade compute budget for output quality without touching model weights at all.

Why Inference-Time Compute Matters

Training-time compute is expensive and irreversible — you bake knowledge into weights over weeks or months. Inference-time compute is cheap, parallelizable, and reversible — you can dial it up or down per request. This asymmetry makes inference-time compute scaling especially attractive for high-stakes queries where quality matters more than cost.

The insight behind BoN is simple: the probability that at least one of N independent samples is high quality grows rapidly with N, especially when combined with a reliable scoring function (reward model). Google's early RLHF paper showed that Best-of-128 sampling could match or exceed expensive RL fine-tuning in some settings. More recently, OpenAI's o1 and DeepSeek's R1 demonstrate that inference-time chain-of-thought scaling (a generalization of BoN) can dramatically improve reasoning — o1-mini with extended thinking can outperform o1 on certain benchmarks.

Best-of-N Sampling (Rejection Sampling)

The mechanism is direct:

  • Sample N complete sequences from the language model (typically with non-zero temperature).
  • Score each with a reward model (or proxy metric like ROUGE, self-consistency vote, length heuristic).
  • Return the sequence with the highest score.

The quality gain follows a log-linear law: each doubling of N yields diminishing but consistent returns. Empirically, going from N=1 to N=4 gives a large jump; N=4 to N=16 gives a moderate jump; N=64 to N=128 gives little. The plateau is set by model diversity — once all N samples converge to similar outputs, scoring them differently adds nothing.

Key insight: BoN quality scales as E[max(R₁, R₂, ..., Rₙ)] where Rᵢ are i.i.d. reward scores. For a Gaussian reward distribution, this grows as ~√(2 ln N) — logarithmic returns. You need 4× the compute to gain one standard deviation of reward.

The critical dependency is the reward model quality. If your reward model is miscalibrated, BoN optimizes toward proxy artifacts — longer responses, confident-sounding hedges, preferred vocabulary — not true quality. This is the same reward hacking problem as RLHF, but at inference time.

Beam Search

Beam search is a structured approximation to exhaustive search over all possible sequences. Instead of greedy (pick the single highest-probability next token at each step) or exhaustive (explore all |V|^T sequences), beam search maintains a beam of the top-B partial sequences at each decoding step. 

Step 0: beam = { "" }
Step 1: expand each, keep top-B by cumulative log-prob
Step 2: expand each, keep top-B
...
Step T: return highest-scoring complete sequence from beam

Beam search trades off memory and compute linearly with beam width B. For B=1 it degenerates to greedy decoding. For B=∞ it finds the globally optimal sequence (under the model's probability distribution) but is intractable for long sequences.

A key tradeoff: beam search optimizes for maximum likelihood under the model, not human preference. Empirically, beam search outputs tend to be generic, repetitive, and low-diversity. For open-ended generation tasks (stories, dialogue, creative writing) nucleus sampling beats beam search qualitatively even though beam search has higher log-probability. For constrained tasks (translation, structured extraction) beam search still dominates.

Beam Search Variants

  • Length normalization: Divide cumulative log-prob by sequence length to prevent short-sequence bias.
  • Diverse beam search: Add a diversity penalty between beams to encourage exploration of different hypotheses.
  • Constrained beam search: Force certain tokens to appear (useful for structured outputs).
  • Group beam search: Maintain G groups of beams with inter-group diversity penalty — used in CTRL and prefix-constrained generation.

Best-of-N vs Beam Search: When to Use What

These methods have different computational profiles and quality characteristics:

  • Best-of-N: Embarrassingly parallel — run N independent inference calls concurrently. Best for tasks where diversity of candidates matters (brainstorming, creative tasks, code generation). Requires a reliable reward/scoring function. Works with any model, no modification needed.
  • Beam search: Serially coupled — each step depends on previous. Better when you want maximum likelihood under the model, e.g., translation, structured generation. Does not need a separate scorer but assumes model probabilities align with quality.
Production reality: For code generation (HumanEval benchmark), Best-of-100 with a test-execution scorer gives pass@1 rates equivalent to a significantly larger model. This is why "compute-optimal inference" is a growing area — you can rent BoN at inference time rather than train a bigger model.

Speculative Sampling vs BoN

Don't confuse Best-of-N with speculative decoding. BoN generates N complete sequences and picks one. Speculative decoding generates K draft tokens with a small model and verifies them in parallel with the target model — it's a latency optimization, not a quality-maximization strategy. See concept 35 for speculative decoding.

Self-Consistency as a BoN Variant

Self-consistency (Wang et al., 2022) is a BoN variant where the "reward model" is a majority vote. Generate N chain-of-thought reasoning paths, extract the final answer from each, and return the plurality answer. This approach achieves 74.4% on GSM8K with a 175B model versus 56.5% for greedy decoding — a substantial gain with no additional training.

Key Takeaways

  • BoN quality scales logarithmically with N: doubling N costs 2× compute but gains only ~√(2 ln 2) reward standard deviations. Going from N=64 to N=128 rarely justifies the cost.
  • Beam search maximizes log-probability under the model, which diverges from human preference on open-ended tasks — outputs become generic and repetitive. Use it only where model probability aligns with task quality (translation, constrained extraction).
  • BoN is parallelizable; beam search is serial. In a multi-GPU serving setup, BoN maps naturally to concurrent inference workers — beam search requires synchronized decoding steps, adding coordination overhead.
  • The reward model is the limiting factor in BoN. A miscalibrated scorer (e.g., preferring longer responses) leads to reward hacking at inference time — same failure mode as RLHF but without gradient updates to amortize it.
  • Self-consistency (majority-vote BoN) gained 18+ percentage points on GSM8K math reasoning without any model change. It's one of the highest-ROI inference-time techniques for structured output tasks.
  • Production BoN at scale: cost = N × (1 inference call + 1 reward model call). At N=32 for a 70B model, this is 32 inference calls — feasible only with efficient batching (vLLM, TensorRT-LLM) and a cheap reward model (often a small 7B classifier).
