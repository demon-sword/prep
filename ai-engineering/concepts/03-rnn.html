Foundations

Recurrent Neural Networks (RNN)

RNN cell, hidden state propagation, vanishing gradient problem, LSTM and GRU variants, and why RNNs gave way to transformers.

Theory

The Core Idea: Memory Through Recurrence

An RNN processes sequences by maintaining a hidden state — a fixed-size vector that summarizes everything seen so far. At each timestep t, the cell takes the current input x_t and the previous hidden state h_{t-1}, and produces a new hidden state h_t and optionally an output y_t.

h_t = tanh(W_h · h_{t-1} + W_x · x_t + b)
y_t = W_y · h_t + b_y

This recurrence is the defining mechanism: the same weight matrices W_h, W_x, and W_y are applied at every timestep. The model is "unrolled" across time during backpropagation. This parameter sharing is both the RNN's strength (it generalizes across sequence positions) and its weakness (a single set of weights must handle all temporal distances, making long-range dependencies hard to learn).

The Vanishing Gradient Problem

Training an RNN requires backpropagating gradients through time (BPTT). If a sequence has length T, the gradient of the loss at step T with respect to the hidden state at step 1 involves a product of T-1 Jacobian matrices, each roughly equal to W_h scaled by the tanh derivative.

∂h_T/∂h_1 = ∏_{t=2}^{T} (∂h_t/∂h_{t-1}) = ∏_{t=2}^{T} diag(tanh'(...)) · W_h

The tanh derivative is at most 1.0 (at zero) and quickly falls to near zero at saturation. If the spectral norm of W_h is less than 1, this product shrinks exponentially — gradients vanish, and early tokens stop receiving gradient signal. Empirically, vanilla RNNs struggle to learn dependencies beyond ~10–20 timesteps.

The flip side is exploding gradients: when the spectral norm of W_h exceeds 1, products grow exponentially. The engineering fix for exploding gradients is gradient clipping (clip by norm to a threshold like 5.0); vanishing is harder to fix at the architecture level, which is why LSTM was invented.

LSTM — Long Short-Term Memory

Hochreiter & Schmidhuber (1997) introduced the LSTM to solve vanishing gradients. The key idea: a separate cell state C_t flows through time with only multiplicative interactions (via gates), creating a "highway" for gradients that can propagate without the repeated squashing.

LSTM has four gates, all learned:

  • Forget gate f_t = σ(W_f · [h_{t-1}, x_t] + b_f) — what fraction of the old cell state to keep
  • Input gate i_t = σ(W_i · [h_{t-1}, x_t] + b_i) — how much of the new candidate to add
  • Candidate C̃_t = tanh(W_C · [h_{t-1}, x_t] + b_C) — new candidate values
  • Output gate o_t = σ(W_o · [h_{t-1}, x_t] + b_o) — what part of the cell state to expose
C_t = f_t ⊙ C_{t-1} + i_t ⊙ C̃_t
h_t = o_t ⊙ tanh(C_t)

The cell update is a linear combination of old cell state and new candidate — no repeated nonlinear squashing along the cell path. This means gradients flow back through time without exponential decay (provided the forget gate stays near 1). In practice, LSTMs can learn dependencies spanning hundreds of timesteps, far exceeding vanilla RNNs.

GRU — Gated Recurrent Unit

Cho et al. (2014) proposed the GRU as a simplified LSTM with two gates and no separate cell state. It merges the forget and input gates into a single update gate and adds a reset gate:

z_t = σ(W_z · [h_{t-1}, x_t])    (update gate)
r_t = σ(W_r · [h_{t-1}, x_t])    (reset gate)
h̃_t = tanh(W · [r_t ⊙ h_{t-1}, x_t])
h_t = (1 - z_t) ⊙ h_{t-1} + z_t ⊙ h̃_t

GRU is computationally cheaper than LSTM (~25% fewer parameters for same hidden size) and often matches LSTM performance on many benchmarks. The tradeoff: LSTM's separate cell state gives it more independent control over forgetting vs. outputting, which can matter for tasks requiring very selective memory.

Why RNNs Gave Way to Transformers

Despite LSTM and GRU improvements, RNNs have three fundamental problems that transformers solved:

  • Sequential computation: RNNs must compute h_1 → h_2 → ... → h_T strictly in order. You cannot parallelize across timesteps. On modern GPUs with thousands of CUDA cores, this is catastrophically inefficient — GPU utilization drops to near 0% for long sequences. Transformers process all positions simultaneously via matrix multiplications.
  • Bottleneck hidden state: All information about the past must compress into a fixed-size vector h_t (typically 256–4096 dimensions). At long range, early information inevitably gets overwritten. Transformers' attention mechanism directly reads from all previous representations, no bottleneck.
  • Vanishing gradients remain hard: Even with LSTM/GRU, gradients across very long sequences (>500 tokens) are difficult. Residual connections + layer norm in transformers essentially solve this — gradients flow back near-perfectly.

The tipping point was Vaswani et al.'s "Attention is All You Need" (2017), which showed a transformer outperforming LSTM-based seq2seq on WMT translation while training 8x faster on 8 GPUs. By 2018, BERT (transformer) rendered LSTM-based NLP effectively obsolete for most tasks.

Production Reality

RNNs are not fully extinct. In low-latency, resource-constrained settings (IoT, edge inference), LSTMs still appear because:

  • They process input one token at a time — fixed memory per step, no quadratic attention cost
  • LSTM-based speech systems (e.g., Apple's original Siri acoustic model) ran on device with tiny memory footprints
  • Time-series forecasting on long sequences: architectures like Temporal Fusion Transformer hybrid LSTM with attention

However, for language modeling, translation, and generation, transformers dominate entirely. The RNN era produced the foundational ideas — hidden states, gating, BPTT — that transformers inherited in spirit even while abandoning the recurrence itself.

Key Takeaways

  • Vanishing gradients are architectural, not incidental. In vanilla RNNs, the gradient signal multiplies through W_h's spectral norm at every timestep — at norm 0.9, after 50 steps the gradient is 0.9⁵⁰ ≈ 0.005. LSTMs' additive cell update provides a direct gradient highway, but they still degrade past ~500 tokens.
  • Sequential computation is a GPU killer. An RNN on a sequence of length T uses only 1/T of GPU parallelism compared to a transformer. For T=512 tokens, that's 0.2% GPU utilization during sequence processing — the single biggest reason RNNs lost the race.
  • GRU ≈ LSTM in most benchmarks, ~25% cheaper. For production sequence tasks where you're still using RNNs (on-device speech, lightweight time-series), GRU is usually the right default. LSTM is worth trying only when the task requires selective forgetting that GRU's merged gate can't express.
  • The hidden state bottleneck never goes away. A 512-dim LSTM hidden state must compress everything relevant from an arbitrary-length past into 512 floats. At ~1K+ tokens, this bottleneck dominates quality. Attention sidesteps this by making the "memory" grow with sequence length — at the cost of O(n²) compute.
  • BPTT through time is memory-intensive. Full backpropagation through T timesteps requires storing all intermediate activations — O(T) memory. For long sequences, truncated BPTT (e.g., backprop only 100 steps back) is standard but trades gradient quality for memory. This is a hidden training cost that transformer training (gradient checkpointing) handles more elegantly.
  • RNNs live on in hybrids. Mamba (2023) and RWKV (2023) revive the linear-recurrence idea with modern gating to achieve O(n) inference — transformer-quality results without the quadratic attention cost. They matter for very long contexts (100K+ tokens) where attention becomes prohibitively expensive.
