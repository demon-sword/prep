Dataset Engineering for LLMs

Data formats per task type, quality dimensions, volume estimation, annotation pipelines, augmentation, synthesis, and the full data processing workflow.

Theory

Data is the actual substrate of intelligence in LLMs. Model architecture is largely commoditized — a frontier model, Claude, and Gemini share the transformer skeleton. What differentiates them at the margin is data: its quantity, quality, composition, and the engineering discipline applied to assembling it. A senior AI engineer spends far more time on data pipelines than on model architecture decisions.

1. Data Formats Per Training Objective

Every training objective has a canonical data format. Getting the format wrong — even with the right content — produces silent degradation in the model's ability to generalize. There are four primary formats:

Self-Supervised
{ "text": "raw document..." }

Pure next-token prediction on unlabeled text. Used for pretraining. No annotation required — the label is the next token in the sequence. WebText, The Pile, C4, RedPajama, DCLM are standard corpora.

Instruction
{ "instruction": "...", "input": "...", "output": "..." }

SFT format. The model learns to follow instructions. Alpaca, FLAN, Dolly, OpenAssistant, and ShareGPT are canonical sources. Quality beats quantity — 1K high-quality examples often beat 100K noisy ones.

Preference
{ "prompt": "...", "chosen": "...", "rejected": "..." }

Used for DPO/RLHF. A prompt paired with two responses — a preferred and a rejected one. The model learns to produce chosen-like outputs. Anthropic's HH dataset and UltraFeedback are widely used.

Reward / Scalar
{ "prompt": "...", "response": "...", "score": 4.2 }

Used to train reward models in the RLHF pipeline. A scalar score per (prompt, response) pair, usually 1–5 or 1–10. Requires careful calibration across annotators to prevent reward model miscalibration.

2. The Six Quality Dimensions

Quantity scaling has diminishing returns without quality control. The Chinchilla paper showed that data quality matters as much as scale. There are six key dimensions to assess:

Dimension What It Measures Common Failure Mode
Relevance Does the data match the target task distribution? Generic web text fine-tuned for medical coding
Consistency Are annotations coherent across samples and annotators? Inter-annotator agreement < 0.7 Cohen's κ
Format Does the schema match training expectations exactly? Wrong chat template format breaks SFT silently
Uniqueness Low duplication rate — no repeated n-grams at scale MinHash dedup missed near-duplicates in C4
Compliance PII-free, license-compatible, no harmful content SSNs in fine-tuning data get memorized
Coverage Task, domain, format, and difficulty distribution Code SFT data with 80% Python, 0% SQL

3. Volume Estimation

How much data do you need? The answer varies by objective:

  • Pretraining: Chinchilla-optimal is ~20 tokens per parameter. A 7B model needs ~140B tokens; a 70B model needs ~1.4T. Modern practice overtrains on compute-to-tokens ratio (LLaMA 3 used ~15T tokens for 8B params) for better inference-time efficiency.
  • SFT: As few as 1,000–10,000 high-quality examples can shift behavior substantially. LIMA showed 1,000 curated examples beat 52K noisy ones. More isn't better if quality is low.
  • DPO/preference: Typically 10K–100K preference pairs. UltraFeedback used 64K; Anthropic's HH used ~160K. The chosen/rejected gap matters more than count — hard negatives drive better learning than easy pairs.
  • Reward model: 50K–500K scalar-scored pairs. Reward model quality is the limiting factor of the entire RLHF pipeline; underinvesting here breaks everything downstream.

4. Data Sourcing: Collection, Annotation, Augmentation, Synthesis

Real-world dataset engineering uses four sourcing strategies:

Human Annotation: The gold standard for quality but expensive — $0.50–$5.00 per annotated sample for complex tasks. Crowdsourcing (MTurk, Scale AI, Surge AI) is common. Requires annotator guidelines, calibration runs, gold sets to catch cheating, and IAA monitoring. Expert annotation (lawyers, doctors, coders) costs 5–20× more but is essential for specialized tasks.

Web Scraping & Filtering: Common Crawl provides ~70PB of raw web data, processed into C4, The Pile, DCLM. Processing steps include: language identification (fastText langdetect), quality filtering (perplexity-based, C4 heuristics), deduplication (MinHash LSH for near-dups, exact SHA hashing for exact dups), and PII removal. The DCLM benchmark showed that filtering strategy matters enormously — carefully filtered 3B tokens outperformed noisier 300B tokens datasets on downstream benchmarks.

Augmentation: For low-resource tasks, augment existing data: paraphrase via back-translation or stronger LLMs, swap entity names, introduce noise (typos, casing), or generate counterfactuals. The risk is introducing distribution artifacts the model learns instead of the underlying task.

Synthetic Data Generation: Use a large model to generate training data for a smaller model. Alpaca used a small fast model to generate 52K instruction-following examples from 175 seed examples. This is now standard practice for SFT at scale. Critical caveats: (1) synthetic data amplifies teacher model biases, (2) training on synthetic outputs from the same model family risks capability collapse (model collapse problem), (3) "teacher ceiling" — student cannot exceed teacher quality without ground-truth grounding.

6. Deduplication — The Most Underrated Step

Duplicate data causes memorization, not generalization. A document repeated 100 times gets memorized verbatim — the model will regurgitate it at inference rather than synthesize new outputs. Lee et al. (2022) showed that deduplication with MinHash LSH reduced the training set of C4 by 30% while improving downstream quality across all benchmarks tested. Semantic deduplication (embedding-based) is more expensive but catches paraphrase-level duplicates that MinHash misses.

7. Chat Templates and Prompt Loss Masking

For instruction tuning, format matters mechanically. Every model family has a specific chat template that the tokenizer uses to delimit system, user, and assistant turns. Using the wrong template during SFT will train the model to produce incorrect delimiters at inference. Common templates: [INST] ... [/INST] (Llama 2), <|im_start|>user\n...<|im_end|> (ChatML / Llama 3+).

Prompt loss masking is equally critical: during SFT, mask the loss on the instruction/system tokens and only backpropagate on the completion tokens. Training the model to "predict" its own system prompt is waste and can cause mode collapse on instruction tokens.

Production Reality

Tools: Hugging Face datasets for hosting and streaming, DataTrove and dolma for large-scale processing pipelines, Argilla for annotation UI, Label Studio for multi-modal annotation, Cleanlab for automated data quality auditing, RAGAS for RAG-specific dataset evaluation.

At production scale, dataset engineering is a continuous pipeline, not a one-time task. You monitor data drift, track annotator performance degradation over time, and run data ablations before each model update. The 80/20 rule applies inversely: 80% of engineering effort goes into data, 20% into model code — but most teams staff it the other way around.

Key Takeaways

  • Quality beats quantity for SFT: LIMA (2023) showed 1,000 curated instruction examples outperform 52K noisy ones. Invest in data quality pipelines (Cleanlab, Argilla) before scaling annotation budget.
  • Deduplication is non-optional: Duplicate data causes verbatim memorization, not generalization. MinHash LSH dedup on C4 reduced dataset size by 30% while improving all benchmark scores (Lee et al., 2022). Run exact + near-duplicate removal before any training run.
  • Synthetic data has a teacher ceiling: LLM-generated SFT data (à la Alpaca) cannot exceed teacher model quality without ground truth grounding. Repeated distillation from the same model family leads to capability collapse — always mix with human-curated or real-world data.
  • Prompt loss masking is a hard requirement for SFT: Backpropagating through instruction tokens (not just completions) wastes gradient signal and causes models to overfit to system prompt structure. Use per-token loss masking in your training harness (supported natively in TRL/Axolotl).
  • The weakest quality dimension sets the ceiling: A dataset with 9/10 on five dimensions and 2/10 on compliance (e.g., PII in training data) will fail production — regulators and model audits will find it. Treat all six dimensions as blockers, not averages.
  • Chat template mismatch silently breaks models: A Llama-3-format SFT dataset applied to a Mistral tokenizer produces token-level misalignment that the loss function cannot distinguish from real signal. Always validate chat template application with a decoded sample before training.
