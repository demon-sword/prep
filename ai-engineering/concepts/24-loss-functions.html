Training #24

Loss Functions: Cross-Entropy & Perplexity

Cross-entropy loss for next-token prediction, perplexity as its exponent, KL divergence for distribution comparison — intuition, formulas, and what they measure.

Theory

What Is the Training Objective for LLMs?

Language model pretraining is a self-supervised task: given a sequence of tokens, the model predicts the next token at every position. The training signal is the cross-entropy loss between the model's predicted probability distribution over the vocabulary and the true one-hot distribution of the actual next token.

For a vocabulary of size V and a true next token at index y, the cross-entropy loss for one position is:

L = −log(p_model(y))
// −log of the probability the model assigns to the correct token

For a full sequence of T tokens:
L = −(1/T) Σ log(p_model(y_t | y_<t)) // average over all positions

This loss is computed in the forward pass, and gradients flow backward to update every weight. The model never sees a "label" — the next token is the label, harvested from the raw text itself.

Why Cross-Entropy?

Cross-entropy comes from information theory. It measures how many bits you need to encode samples from distribution P (the true distribution) using a code optimized for distribution Q (the model's distribution). When P is a one-hot (we know the exact next token), cross-entropy reduces to −log₂(q_y) — the number of bits needed to encode the true token under the model's distribution.

In ML we use natural log (nats) rather than log₂ (bits), but the intuition is the same: a loss of 0 means the model is perfectly certain about the correct token (probability 1.0). A random model over a vocabulary of 50,000 tokens would have loss = log(50,000) ≈ 10.8 nats. Real LLM training converges to losses of ~1.5–3.5 nats depending on model size and data quality.

Perplexity: The Exponent

Perplexity (PPL) is simply the exponentiated average cross-entropy loss:

PPL = exp(L) = exp(−(1/T) Σ log p(y_t | y_<t))

// Equivalent to the geometric mean of 1/p over all positions
PPL = (Π 1/p(y_t))^(1/T)

Perplexity has an intuitive reading: it is the average number of equally-likely choices the model is deliberating between at each step. A perplexity of 10 means the model is, on average, as uncertain as a fair choice among 10 options. GPT-2 (1.5B) achieved ~18 PPL on Penn Treebank; GPT-3 achieved ~20 PPL on PTB (though PTB is not its training distribution). LLaMA-2 70B achieves ~3.3 PPL on its test split — roughly 6× better than GPT-2 on equivalent benchmarks.

Key property: PPL = 1 means perfect confidence, PPL = V (vocabulary size) means a completely uniform random model. A 1-point reduction in perplexity is exponentially more meaningful at low perplexity than at high perplexity — going from 5 to 4 is much harder than going from 100 to 99.

KL Divergence: Comparing Distributions

While cross-entropy compares a model distribution to a one-hot truth, KL divergence compares two full distributions P and Q:

KL(P ‖ Q) = Σ P(x) · log(P(x) / Q(x))

// "Extra bits needed to encode P using code optimized for Q"
KL(P ‖ Q) = H(P, Q) − H(P) // cross-entropy minus true entropy of P

KL divergence is asymmetric: KL(P‖Q) ≠ KL(Q‖P). This matters enormously in practice:

  • KL(P‖Q) — forward KL. Penalizes Q assigning low mass where P has high mass (mode-seeking behavior). Used in variational autoencoders.
  • KL(Q‖P) — reverse KL. Penalizes Q assigning high mass where P has low mass (mode-covering behavior). Used in RLHF PPO as the KL penalty term against the reference policy.

In RLHF, the KL penalty KL(π_θ ‖ π_ref) prevents the policy from drifting too far from the SFT reference model during PPO optimization. Without it, the model collapses into reward hacking. Typical KL budget: 0.1–2.0 depending on task. In DPO, the KL divergence is implicitly controlled by the β parameter.

Cross-Entropy in Different Training Regimes

The same cross-entropy formula underlies multiple training objectives with different data sources:

  • Pretraining (CLM): predict each token from all prior tokens. Loss over the entire sequence. No masking of prompt tokens — all positions contribute equally.
  • Instruction fine-tuning: typically only compute loss on the response tokens, not the system prompt or user turn. This focuses gradients on the behavior you want, not on memorizing the prompt format.
  • Masked LM (BERT): 15% of tokens are masked. Loss only on masked positions. This gives bidirectional context but cannot directly generate text autoregressively.
  • Sequence-to-sequence: loss only on decoder outputs. The encoder is trained via backprop through the decoder's cross-attention into encoder representations.

Prompt Loss Weight and Training Efficiency

A common pitfall in fine-tuning: including the prompt in the loss computation dilutes training signal. If your instruction is 512 tokens and response is 64 tokens, you waste 88% of compute budget learning to predict tokens already learned in pretraining. Solutions:

  • Set prompt_loss_weight = 0 (mask prompt tokens) — best for instruction following
  • Use weighted cross-entropy — downweight prompt tokens by a factor like 0.01
  • Pack sequences efficiently — concatenate examples to minimize padding waste

In practice, most fine-tuning frameworks (TRL, Axolotl, LLaMA-Factory) support response-only loss masking out of the box via DataCollatorForCompletionOnlyLM.

Perplexity as an Evaluation Metric: Caveats

Perplexity is only meaningful within the same tokenizer and test set. Comparing a frontier model's PPL to LLaMA's PPL on the same text gives a misleading number because different tokenizers produce different token sequences. PPL on in-distribution data doesn't predict out-of-distribution performance. BLEU, ROUGE, and LLM-as-judge are better for downstream task evaluation. PPL remains useful for: training loss monitoring, detecting catastrophic forgetting, comparing checkpoints within the same run, and setting data mixing ratios.

Key Takeaways
  • Perplexity comparisons must use the same tokenizer and test set. A model with 10B parameters reporting PPL=5 on its own test split is not comparable to another model reporting PPL=8 on a different split or with a different BPE vocabulary. Always benchmark on a standardized, held-out eval set like HellaSwag or a fixed WikiText-103 slice.
  • Always mask prompt tokens from loss in instruction fine-tuning. Including the system prompt in loss computation typically wastes 50–90% of gradient signal on tokens the model already knows perfectly. Response-only loss (DataCollatorForCompletionOnlyLM in TRL) consistently improves instruction-following on the same compute budget.
  • Forward vs reverse KL determines mode-seeking vs mode-covering. RLHF uses reverse KL (KL(π‖π_ref)) to prevent reward hacking while allowing the policy to be sharper than the reference. VAEs use forward KL which encourages broader posterior coverage. Getting this direction wrong causes pathological training behavior.
  • A 1-nat reduction in cross-entropy loss gets exponentially harder at low loss. Going from loss=3.0 → 2.0 (PPL 20→7.4) is achieved with 10× compute scaling. Going from loss=2.0 → 1.0 (PPL 7.4→2.7) requires roughly 100× more compute. This is why scaling returns diminish and data quality becomes the binding constraint.
  • The KL penalty in PPO has a practical sweet spot of 0.1–2.0. Too small: reward hacking dominates. Too large: the policy can't move from the reference and reward never improves. AnthropicKL annealing schedules or adaptive β (as in KTO/DPO) avoid this hyperparameter sensitivity.
  • Per-token loss variance is a signal for data quality and memorization. Spikes in loss (high-loss tokens) often correspond to rare names, numbers, or code identifiers. Very low loss on entire passages is a memorization signal — the model has seen that exact text in training. Log per-token loss during eval to detect both failure modes.
