Flash Attention

How tiled attention keeps computation in SRAM to avoid materializing the full N×N attention matrix in HBM — 2–4× speedup, O(N) memory, mathematically identical output to standard attention. Dao et al., 2022.

Theory

The Problem: HBM Is Slow

Modern GPUs are compute monsters with a critical weakness. An NVIDIA A100 delivers 312 TFLOPS (FP16 tensor core) but only 2 TB/s of HBM bandwidth. That's an arithmetic-intensity threshold of roughly 156 FLOPs per byte — if an operation does less compute per byte than this, the GPU stalls waiting for memory.

Standard scaled dot-product attention is brutally memory-bound. For sequence length N, computing S = QK^T produces an N×N matrix. With N=8192 and fp16: that's 67 million elements = 134 MB per head per layer. With 32 heads across 80 transformer layers, the raw attention matrix materialization would consume hundreds of gigabytes of HBM traffic — per forward pass. The GPU spends most of its time moving data between HBM and compute, not actually computing.

A100 HBM (High Bandwidth Memory)

80 GB capacity | 2 TB/s bandwidth | Off-chip, far from compute cores

A100 SRAM (On-Chip)

192 KB per SM | 19 TB/s bandwidth | 9.5× faster than HBM, but only ~20 MB total across 108 SMs

The Arithmetic-Intensity Gap

Attention: ~3 FLOPs/byte — far below the 156 needed to saturate A100. Standard attention is memory-bound by design.

The Key Insight: SRAM Is Tiny But Blazing Fast

GPU on-chip SRAM runs at 19 TB/s — roughly 9.5× faster than HBM. The problem is size: each SM on an A100 has just 192 KB of SRAM (total on-chip SRAM across 108 SMs is ~20 MB). For an N=8192 attention matrix (134 MB), the full N×N matrix cannot fit in SRAM even if you dedicated all of it to a single attention head.

The critical question that Flash Attention (Dao et al., 2022) answers: can we compute softmax(QK^T/sqrt(d)) × V without ever writing the full N×N intermediate matrix to HBM? The answer is yes — through tiling and online softmax.

The Tiling Algorithm

Flash Attention breaks the Q, K, V matrices into blocks that fit in SRAM. Instead of materializing the entire S = QK^T matrix at once:

  • Outer loop over Q blocks: Load one block of Q (size B_r × d) from HBM into SRAM.
  • Inner loop over K/V blocks: For each K/V block (size B_c × d), load it into SRAM, compute the local attention scores S_ij = Q_i K_j^T, apply softmax numerically stably using online softmax, multiply by V_j, and accumulate into the output O_i.
  • Write output only: After processing all K/V blocks for a given Q block, write the final O_i block to HBM. The full N×N attention matrix is never materialized anywhere — not in HBM, not in SRAM.

Online Softmax: The Numerical Trick

Standard softmax requires two passes over the data: one to find the maximum (for numerical stability via exp(x_i - max)) and one to compute the sum. In a tiled setting, you don't have all scores at once — you see them block by block. Online softmax maintains a running maximum m and a running sum l:

For each new block with scores s: m_new = max(m_old, max(s)) l_new = exp(m_old - m_new) * l_old + sum(exp(s - m_new)) O_new = exp(m_old - m_new) * O_old + exp(s - m_new) * V_block Final output: O = O_final / l_final

This produces mathematically identical output to standard two-pass softmax. Flash Attention is not an approximation — unlike quantization or pruning, there is zero quality tradeoff. The output tensor is bit-identical to the naive implementation (or within floating-point rounding).

Recomputation for the Backward Pass

During training, the backward pass needs the attention weights (or equivalent information) to compute gradients. Storing all attention weights for all heads and layers would be memory-prohibitive. Flash Attention solves this by recomputing the attention scores during the backward pass, rather than caching them from the forward pass. Since the forward pass was SRAM-optimized and the backward pass can reuse the same tiling pattern with recomputation, the total memory for both passes remains O(N).

FlashAttention-2 (2023): Better Work Partitioning

FA2 improved the real-world efficiency of FA1 by ~2× through better CUDA-level engineering:

  • Reduced non-matmul FLOPs: The softmax and rescaling operations (which don't use tensor cores) were better parallelized across thread blocks.
  • Forward pass parallelism: Switched from parallelizing over Q blocks to parallelizing over both batch and head dimensions simultaneously, reducing the sequential inner loop and improving occupancy.
  • Better warp scheduling: Tighter pipelining of HBM loads and SRAM computations — overlapping data transfer with compute.

FlashAttention-3 (2024): Hopper-Native

FA3 exploits NVIDIA Hopper (H100) architecture features that FA1/FA2 couldn't use:

  • WGMMA (Warp-Group Matrix Multiply-Accumulate): Asynchronous tensor core instructions that let different warp groups compute matmuls while others handle data movement — true async compute.
  • TMA (Tensor Memory Accelerator): Hardware unit for async data movement between HBM and SMEM. Frees up CUDA cores that would otherwise wait on data loads.
  • Results: 740 TFLOPS on H100 — 75% of theoretical peak. FA2 on H100 hit ~35% utilization. This is a systems engineering masterclass: squeezing more from hardware by restructuring how work is dispatched, not by changing the math.

When Flash Attention Helps (And When It Doesn't)

Flash Attention delivers 2–4× speedup on prefill — the phase where the model processes a long prompt in one parallel forward pass. The N×N matrix is materialized in standard attention, and FA eliminates that HBM traffic. Below N=512, the SRAM tiling overhead dominates and the benefit is negligible. For single-token decode (autoregressive generation), the attention matrix is 1×N (current token attending to all previous keys) — not N×N — so the memory savings are minimal. Flash Attention does not significantly accelerate token-by-token decoding.

Flash Attention is also heavily beneficial during training, where the backward pass's recomputation strategy (avoiding storing attention weights) dramatically reduces peak memory. This enabled training on longer sequences that were previously impossible.

Adoption and Ecosystem

PyTorch 2.0 integrated Flash Attention as the default backend for torch.nn.functional.scaled_dot_product_attention — meaning millions of PyTorch programs got FA automatically with no code changes. Every major framework supports it: HuggingFace Transformers, vLLM, TGI (Text Generation Inference), TensorRT-LLM, SGLang, and llama.cpp. On the A100, you get FA2; on the H100, FA3 is the optimal choice. The flash_attn Python package from Dao-AILab provides the canonical implementation.

Key Takeaways

  • Mathematically identical output — zero quality tradeoff: Flash Attention is a pure systems optimization. Unlike quantization, pruning, or speculative decoding, it produces the exact same attention output. Online softmax is numerically stable and equivalent to the two-pass naive softmax. You can adopt it with zero model quality risk.
  • Prefill speeds up 2–4×; decode sees almost nothing: The N×N attention matrix only appears during prefill (parallel processing of the input prompt). During autoregressive decode, attention is 1×N — the matrix is a single row, so the memory savings are negligible. Flash Attention is a prefill + training optimization, not a decode accelerator.
  • Below N=512, the tiling overhead dominates: Flash Attention's SRAM block management has fixed overhead. For very short sequences (< 512 tokens), standard attention with fused kernels often wins. Production serving systems like vLLM dynamically select the backend based on sequence length — FA for prefill, standard for very short prompts.
  • PyTorch 2.0 made it a default: scaled_dot_product_attention in PyTorch 2.0+ auto-selects Flash Attention when the input shapes and hardware support it. Every HuggingFace model using this function gets FA automatically. The flash_attn package from Dao-AILab gives you the standalone implementation for custom attention patterns.
  • FA3 on H100 is a different beast: FlashAttention-3 exploits Hopper-specific features (WGMMA, TMA) that don't exist on A100. It achieves 740 TFLOPS — 75% of H100's theoretical peak — by overlapping async tensor core operations with data movement. On A100s, FA2 is the ceiling. If you're running on H100 GPUs, benchmark FA3 explicitly — the gap vs FA2 is significant at long context.
  • Training benefits are arguably larger than inference: Recomputation in the backward pass means Flash Attention avoids storing the N×N attention matrix for gradient computation. For a 65B model training on 2048-token sequences, this saves ~40 GB of activation memory per GPU — enabling larger batch sizes and longer context windows that were previously impossible. Long-context training (32k, 128k tokens) is practical because of Flash Attention.
