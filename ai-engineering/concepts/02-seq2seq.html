Foundations

Seq2Seq Architecture

Encoder-decoder sequence-to-sequence architecture, attention mechanism, and how it preceded the transformer — mapping variable-length inputs to variable-length outputs.

Theory

What is Seq2Seq?

Sequence-to-sequence (Seq2Seq) models, introduced by Sutskever, Vinyals & Le at Google in 2014, solve the fundamental problem of mapping an input sequence of arbitrary length to an output sequence of (potentially different) arbitrary length. Before Seq2Seq, neural networks required fixed-size inputs and outputs, which made tasks like machine translation — where source and target sentences have different lengths — extremely difficult to handle in a principled way.

The key insight was a two-component design: an encoder that reads the entire input sequence and compresses it into a fixed-size vector (the context vector), and a decoder that takes that context vector and generates the output sequence one token at a time. Both components are typically Recurrent Neural Networks (RNNs), though LSTMs and GRUs quickly became standard due to their ability to capture longer-range dependencies.

Encoder: Compressing the Source

The encoder processes input tokens x₁, x₂, …, xₙ sequentially. At each step t, it updates a hidden state:

hₜ = f(hₜ₋₁, xₜ)
where f is an RNN/LSTM/GRU cell, h₀ is the zero vector

After processing all n tokens, the final hidden state hₙ serves as the context vector c. This vector must encode the entire semantic content of the source sequence — a major bottleneck. For long sequences (e.g., a 50-word sentence), compressing everything into a 512- or 1024-dimensional vector causes an information bottleneck that leads to forgetting early tokens.

Decoder: Generating the Target

The decoder generates output tokens y₁, y₂, …, yₘ autoregressively. At each step t, it takes its previous hidden state sₜ₋₁, the previously generated token yₜ₋₁, and the context vector c:

sₜ = g(sₜ₋₁, yₜ₋₁, c)
P(yₜ | y₁…yₜ₋₁, x) = softmax(Wsₜ + b)
g is another RNN cell; W projects hidden state to vocabulary logits

During training, teacher forcing is used: the ground-truth previous token yₜ₋₁ is fed rather than the model's own prediction. This stabilizes training but creates a train/inference mismatch (exposure bias). At inference time, the model uses its own outputs — introducing error accumulation.

The Attention Mechanism: Solving the Bottleneck

The single context vector bottleneck was the key failure mode for long sequences. Bahdanau et al. (2015) introduced additive attention (also called Bahdanau attention), which fundamentally changed Seq2Seq. Instead of using a single fixed context vector, the decoder dynamically computes a weighted combination of all encoder hidden states at each decoding step:

eᵢⱼ = vᵀ tanh(W₁hᵢ + W₂sⱼ₋₁)   <-- alignment score
αᵢⱼ = exp(eᵢⱼ) / Σₖ exp(eₖⱼ)   <-- softmax weights
cⱼ = Σᵢ αᵢⱼ · hᵢ   <-- dynamic context
at decoder step j, the model looks at all encoder states h₁…hₙ

Luong attention (2015) offered a simpler multiplicative variant: eᵢⱼ = sⱼᵀ · hᵢ, which is computationally cheaper and scales better to larger hidden dimensions. Scaled dot-product attention in the Transformer is a parallelized version of this exact idea.

How Attention Weights Are Learned

The alignment model (computing eᵢⱼ) is trained jointly with the encoder and decoder via backpropagation. No explicit supervision is needed — the model learns which source tokens to attend to based on the translation objective alone. Visualizing attention matrices in trained models reveals linguistically meaningful patterns: when translating "bank" (financial institution) vs "bank" (river bank), the model attends to different context words to disambiguate.

Seq2Seq in Production: When It Was Used

Google's first neural machine translation (GNMT, 2016) used an 8-layer LSTM Seq2Seq with attention and reduced translation errors by 55–85% on some language pairs vs phrase-based MT. The model had ~380M parameters, trained on 36M sentence pairs. Despite this success, three fundamental limitations remained:

  • Sequential bottleneck: RNNs process tokens one at a time — can't parallelize across the sequence. Training a 6-layer LSTM on WMT English-German took ~1 week on 8 GPUs.
  • Quadratic attention cost: Computing all attention weights is O(n·m) — expensive for long documents.
  • Vanishing gradients: Despite LSTMs helping, gradients still degrade across 100+ token sequences.

"Attention Is All You Need" (Vaswani et al., 2017) kept the encoder-decoder structure but replaced RNNs entirely with self-attention, enabling full parallelism. The Transformer trained in 12 hours on 8 P100 GPUs and outperformed all prior Seq2Seq models — effectively making pure RNN-based Seq2Seq architecturally obsolete for most tasks.

Legacy: Why Seq2Seq Still Matters

Understanding Seq2Seq is essential because: (1) Transformer encoder-decoder models (T5, BART, mBART) inherit the same high-level structure — encoder reads, decoder generates; (2) the attention mechanism it pioneered is the core of every modern LLM; (3) many deployed edge systems and lightweight translation models still run LSTM Seq2Seq due to lower inference cost; (4) seq2seq framing (read all context → generate output) is how decoder-only LLMs like GPT work conceptually, just with the "encoder" being the prompt and the attention being self-attention.

Key Takeaways

  • Context vector is the original bottleneck. A single fixed-size vector encoding an entire sequence caused catastrophic forgetting on sentences longer than ~20 tokens. Attention solved this by giving the decoder a dynamic, content-based view into all encoder states — not just the final one.
  • Teacher forcing creates exposure bias. Training with ground-truth previous tokens but decoding with model-predicted tokens causes distribution mismatch. In production, scheduled sampling (gradually replacing ground-truth with model outputs during training) or minimum-risk training mitigates this — but it's still a gap Transformers don't fully escape either.
  • Seq2Seq → Transformer is architectural, not conceptual. T5, BART, and mBART still use encoder-decoder design — they replaced RNN cells with self-attention layers. Tasks needing full-input comprehension before generation (e.g., translation, summarization with extractive step) still benefit from the encoder-decoder split vs decoder-only GPT-style.
  • Attention weights ≠ interpretability. Visualizing attention matrices became popular for interpretability, but Jain & Wallace (2019) showed attention weights often don't correlate with feature importance. They are alignment scores, not causal explanations. Don't over-index on them as ground truth.
  • GNMT showed the compounding power of engineering tricks. Google's production Seq2Seq (2016) used 8 LSTM layers, residual connections between layers, attention, and aggressive quantization (INT8 weights). The tricks together — not any single one — produced the 55–85% error reduction. System-level thinking beats algorithmic purity.
  • Beam search is the default Seq2Seq decoder. Greedy decoding is fast but suboptimal. Beam search (width 4–10) improves output quality at the cost of latency proportional to beam size. Modern LLMs mostly use sampling (top-p, temperature) instead — beam search often produces repetitive, safe outputs.
