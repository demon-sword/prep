01Self-Supervision in LLMs

How LLMs learn from unlabeled text via next-token prediction, masked language modeling, and the pretraining objective — the engine behind modern foundation models.

Theory

The Core Insight: Supervision Hidden in Sequences

Self-supervised learning solves a fundamental problem: we have vastly more unlabeled text than human-labeled data. The key insight is that language itself provides the labels. Given a sequence of tokens, the model can be trained to predict any token from the others — no human annotation required. This transforms an unsupervised abundance (internet text) into a supervised training signal.

Two dominant pretraining objectives emerged:

  • Causal Language Modeling (CLM) — predict the next token given all previous tokens. Used by GPT, LLaMA, PaLM, and virtually every modern autoregressive LLM.
  • Masked Language Modeling (MLM) — mask ~15% of tokens and predict them from bidirectional context. Used by BERT, RoBERTa, and encoder-focused models.

Causal Language Modeling: The Math

For a sequence of tokens x₁, x₂, ..., xₙ, CLM maximizes the likelihood of each token given its prefix:

L(θ) = Σᵢ log P(xᵢ | x₁, ..., xᵢ₋₁; θ)

This factorization is exact — the chain rule of probability guarantees the product of these conditionals equals the joint probability of the full sequence. No approximation. The model is trained to minimize cross-entropy loss at every position simultaneously, so a sequence of length n provides n−1 training signals per forward pass. This is extraordinarily data-efficient compared to supervised approaches where one label is provided per example.

At training time, causal (triangular) masking in the attention mechanism enforces that position i can only attend to positions 1…i. This means every token in the sequence can be a prediction target in a single forward pass — full parallelism during training, despite the task being inherently sequential.

Masked Language Modeling: Bidirectional Context

MLM, introduced by Devlin et al. (2018) in BERT, uses a different strategy. Rather than predicting the next token, it randomly masks a subset of tokens (typically 15%) and trains the model to reconstruct them using both left and right context. Of the masked positions: 80% are replaced with [MASK], 10% with a random token, and 10% kept unchanged — a recipe designed to prevent the model from learning trivial shortcuts.

MLM produces richer bidirectional representations, making it powerful for classification and extraction tasks. However, it cannot be used autoregressively for generation, and the train/inference distribution mismatch (due to [MASK] tokens only appearing during training) is a known limitation. XLNet addressed this with permutation language modeling.

What the Model Actually Learns

A model that achieves low CLM loss must have learned far more than surface-level pattern matching:

  • Syntax: subject-verb agreement, pronoun resolution, nested clause structure
  • Semantics: word meaning, compositional phrase meaning, analogical reasoning
  • World knowledge: facts about entities, events, relationships
  • Pragmatics: discourse coherence, implication, conversational structure
  • Code structure: indentation rules, API signatures, algorithmic patterns (if trained on code)

These capabilities emerge because predicting next tokens well requires correctly modeling the full generative process that produced the text. This is why scaling works: a bigger model can capture more of this structure.

The Scale That Makes It Work

Self-supervision is only viable at scale. BERT was trained on 3.3B tokens. GPT-2 on 40B. GPT-3 on ~300B. LLaMA-3.1 405B used approximately 15T tokens. The Chinchilla paper (2022) established that for compute-optimal training, you need roughly 20× more tokens than parameters — so a 7B parameter model wants ~140B tokens minimum, and inference-optimized models (trained past Chinchilla optimum) use far more.

Why "compute-optimal" ≠ "inference-optimal": Chinchilla optimizes for loss at a fixed compute budget. But in production, you want a model that performs well at a given size — which means training smaller models on more tokens than Chinchilla recommends, yielding cheaper inference for the same quality. LLaMA adopted this strategy explicitly.

From Self-Supervision to Useful Models

Raw CLM pretraining produces a model that excels at continuing text — not following instructions, not refusing harmful requests, not staying helpful. This is why post-training (SFT + RLHF or DPO) is required. Self-supervision gives the model capability; post-training shapes its behavior. The division is fundamental to the modern LLM development pipeline.

Pretraining cost dominates total training cost: GPT-4's pretraining reportedly cost >$100M. Post-training is ~1–5% of that. But post-training typically requires labeled data (instruction-response pairs, preference pairs), making quality control far more expensive per token. The asymmetry — cheap self-supervised pretraining, expensive post-training — drives the field toward better pretraining that requires less alignment work.

Practical Implications

Understanding self-supervision matters for production AI engineering in several ways:

  • Tokenization affects everything: the model predicts tokens, not characters. BPE/WordPiece/SentencePiece tokenizers affect what constitutes a "hard" prediction, how many tokens code vs prose uses, and what the model's effective context window covers in real content.
  • Perplexity is the training signal: lower perplexity = better fit. Perplexity on a held-out set (eval loss) is the primary signal during pretraining to detect overfitting or divergence.
  • Domain mismatch is real: a model pretrained on English web text will have high perplexity on legal German documents. Continued pretraining on domain-specific data (domain-adaptive pretraining) before fine-tuning is a well-established recipe.
  • Data quality beats quantity: FineWeb, RedPajama, and Dolma all found that aggressive deduplication and quality filtering (removing boilerplate, spam, near-duplicates) dramatically improves downstream performance even at the same token count.

Key Takeaways

  • CLM provides n−1 training signals per forward pass — every token in a sequence is simultaneously a context element for future tokens and a prediction target for past positions. This data efficiency is why pretraining can scale to trillions of tokens without running out of labels.
  • Causal masking (not model size) is what makes CLM autoregressive — the triangular attention mask prevents position i from attending to i+1…n, enforcing the left-to-right generative factorization. Remove the mask and you get bidirectional context (like BERT), which is great for understanding but cannot generate.
  • Pretraining domain determines what the model "knows" — models trained on code+text outperform text-only models on coding tasks, not due to fine-tuning but because self-supervised next-token prediction over code teaches the model Python syntax, library APIs, and algorithmic reasoning. Domain-adaptive pretraining (DAP) on domain-specific corpora before SFT is a well-validated recipe.
  • Inference-optimal ≠ Chinchilla-optimal — Chinchilla (2022) says to scale parameters and tokens proportionally. But LLaMA showed training a smaller model on more tokens yields the same quality at a fraction of the inference cost. For production deployments where you serve millions of requests, inference cost dwarfs training cost.
  • Data quality filters matter more than raw token count — FineWeb's ablations showed that quality filtering (removing near-duplicates, boilerplate, low-quality web text) with MinHash + perplexity filtering improved benchmark performance by 2–4% even at the same token count. At scale, garbage data doesn't just add noise — it actively degrades capability.
  • Self-supervision gives capability; post-training gives alignment — the pretrained model is a next-token predictor, not an assistant. It will complete prompts in character voices, continue harmful text, and hallucinate freely. RLHF/DPO and SFT are required to steer behavior — but they work only because the pretrained model already has the underlying capability. Post-training cannot install capability that wasn't learned during pretraining.
