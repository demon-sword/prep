GRPO & RL with Verifiable Rewards

Group Relative Policy Optimization drops PPO’s critic network and estimates the advantage baseline from the mean reward of a group of sampled completions — the algorithm behind modern reasoning models, paired with verifiable rewards from executable checks rather than a learned preference model. Shao et al., DeepSeekMath, 2024.

Theory

The Problem: PPO’s Critic Is Dead Weight for LLMs

Proximal Policy Optimization (PPO) was designed for game agents and robot control, where a learned value function (the critic) estimates the expected future return from each state. Applied to language models via RLHF, that critic is a second full-size model: for a 70B policy you train and serve a 70B value head alongside it, roughly doubling the memory footprint of the RL stack — policy, reference policy, reward model, and critic, four large networks resident at once. The critic also introduces its own failure modes: value-function bias, a separate learning rate to tune, and Generalized Advantage Estimation hyperparameters (λ, γ) that interact badly with the sparse, sequence-level rewards of language tasks.

Worse, the critic answers a question nobody asked. In RLHF the reward arrives once per completion — a single preference score for the whole response — so per-token value estimation is mostly interpolation noise. Practitioners found that much of PPO’s complexity was paying for precision the reward signal never had.

PPO stack (4 networks)

Policy + reference + reward model + critic. The critic alone costs as much memory as the policy it serves.

GRPO stack (3 networks)

Policy + reference + reward source. No critic — the group of samples is its own baseline. Roughly 25–50% less memory.

Where it won

DeepSeekMath (2024) introduced GRPO; DeepSeek-R1 (2025) scaled it to a 671B MoE and matched OpenAI o1 on math and code — reasoning models run on this loop.

The Key Insight: The Group Is the Baseline

For one prompt q, GRPO samples a group of G completions {o_1 … o_G} from the old policy (typical G is 8 to 64) and scores each with the reward function. The advantage of completion i is its reward measured against its own siblings:

A_i = ( r_i − mean(r_1..r_G) ) / std(r_1..r_G)

No learned baseline, no value head, no GAE λ. Completions above the group mean get pushed up, completions below it get pushed down, and the normalization keeps gradient magnitudes stable as absolute reward scales drift over training. The baseline is computed from the exact same prompt under the exact same policy — it is perfectly on-distribution by construction, which is precisely what a learned critic struggles to stay.

One-line mental model: PPO asks “was this completion better than my critic predicted?” GRPO asks “was this completion better than its G−1 siblings?” The siblings are free — you sampled them anyway.

The GRPO Objective

With group-relative advantages in hand, the policy update is PPO-style clipped surrogate maximization, minus a KL penalty against the reference policy and with no value loss at all:

J(θ) = E_q [ 1/G · Σ_i min( ρ_i · A_i , clip(ρ_i, 1−ε, 1+ε) · A_i ) − β · D_KL(π_θ || π_ref) ] where ρ_i = π_θ(o_i|q) / π_old(o_i|q), A_i from the group above

The KL coefficient β (commonly 0.01–0.04) keeps the policy from drifting off the readable-language manifold while it chases reward. DeepSeek-R1-Zero famously ran this loop with no supervised fine-tuning at all — pure RL from the base model — and reasoning behaviors like self-verification and long chains of thought (“aha moments”) emerged from the optimization rather than from imitation.

RLVR: Rewards You Can Execute, Not Rewards You Learn

GRPO still needs a reward function, and here the second half of the modern recipe enters: RL with Verifiable Rewards (RLVR). Instead of a learned preference model trained on human pairwise judgments — expensive, gameable, and a second approximator stacked on the first — the reward is a deterministic checker you can execute: unit tests pass or fail, the final answer matches after normalization, the equation is symbolically equivalent, the code compiles. DeepSeek-R1 used exactly this split: rule-based accuracy rewards plus small format rewards (e.g. wrapping reasoning in the required tags). Ai2’s Tulu 3 report (Lambert et al., 2024) independently showed RLVR lifting math and instruction-following verifiable tasks at 70B scale.

Verifiable rewards change the optimization dynamics, not just the plumbing. A learned reward model is a smooth surface the policy can hill-climb into gibberish — classic reward hacking. A unit-test suite is a cliff: the completion either passes or it doesn’t, so the group mean becomes a clean difficulty thermometer. Prompts the model already solves every time (mean ≈ 1) and prompts it never solves (mean ≈ 0, std ≈ 0) both yield near-zero advantages and contribute almost no gradient — GRPO + RLVR automatically concentrates learning on the frontier of the model’s competence, the prompts it solves sometimes.

The Inner Loop in Code

Hugging Face TRL’s GRPOTrainer implements exactly this loop; the core of one training step is a dozen lines:

# one GRPO step for a single prompt (TRL-style, simplified)
def grpo_step(prompt, policy, ref_policy, reward_fn, G=8, beta=0.01):
    outs = [policy.sample(prompt) for _ in range(G)]   # group of G siblings
    r = [reward_fn(prompt, o) for o in outs]          # verifiable checker, not a model
    mu, sigma = mean(r), std(r) + 1e-8
    adv = [(ri - mu) / sigma for ri in r]              # group-relative advantages
    loss = -mean([min(ratio(o) * a, clip(ratio(o)) * a) for o, a in zip(outs, adv)])
    loss += beta * kl(policy(prompt), ref_policy(prompt))
    loss.backward()  # no critic anywhere in this function

Gotchas That Bite in Production

Zero-variance groups waste compute. When all G completions get the same reward, std → 0 and every advantage is ~0 — the step teaches nothing but still costs G rollouts. Production runs (e.g. in the verl and OpenRLHF frameworks) filter or down-weight all-correct and all-wrong groups, and curate prompt batches toward the model’s current frontier.

Length bias, then Dr. GRPO. The original formulation averages the loss per token and normalizes by group std, which quietly rewards longer responses: more tokens over which to spread a positive advantage. Liu et al. (2025, “Dr. GRPO”) showed this produces the familiar verbosity drift and proposed the unbiased fix — drop the std normalization and the per-response length normalization. If your RLVR run’s answers keep getting longer without getting righter, this is the first knob to check.

Verifiers get hacked too. Deterministic does not mean ungameable: models learn to emit the format tag with empty reasoning, to hard-code answers matching weak test suites, or to exploit nondeterministic checkers. The fix is verifier diversity — held-out tests the model never sees, format rewards kept small relative to accuracy rewards — the same adversarial mindset as reward-model monitoring, pointed at code instead of weights.

KL tuning is the stability dial. Too small a β and the policy drifts into high-reward gibberish (especially with format rewards); too large and reasoning never departs from the reference style. Reasoning runs typically start near 0.01 and treat KL divergence as the primary training-health metric on the dashboard.

Key Takeaways

  • No critic means one fewer giant model in memory: dropping the value network removes a network as large as the policy itself — the difference between fitting an RL run on your cluster or not. This is why DeepSeek could push GRPO to 671B-scale MoE in DeepSeek-R1, and why Hugging Face TRL’s GRPOTrainer is now the default starting point for post-training reasoning models instead of PPO.
  • GRPO auto-focuses on your model’s competence frontier: all-correct and all-wrong groups produce near-zero advantages and contribute almost no gradient, so compute concentrates on prompts the model solves sometimes. Curate training batches toward that frontier and filter zero-variance groups (built into verl and OpenRLHF) rather than burning rollouts on mastered or impossible prompts.
  • Verifiable rewards beat learned rewards for reasoning: unit tests and answer matching give a cliff the policy cannot smooth-talk its way up, unlike preference models. DeepSeek-R1’s rule-based accuracy rewards and Ai2’s Tulu 3 RLVR results both show this recipe scaling — but keep format rewards small and hold out verifier tests, because a model that learns “emit the tag, skip the reasoning” has hacked you deterministically.
  • Watch for verbosity drift — then reach for Dr. GRPO: per-token averaging plus group-std normalization quietly pays the model per token, so answers get longer without getting righter. If mean response length climbs while benchmark accuracy plateaus, drop the std/length normalization per the Dr. GRPO fix before touching anything else.
  • Put KL divergence on the dashboard, not just reward: the β KL term against the reference policy is the stability dial — reward can climb while the policy drifts into high-reward gibberish, but KL reveals it first. Reasoning runs distilled into dense models (e.g. the Qwen-distilled R1 variants served via OpenAI-compatible APIs and vLLM) inherited their behavior from a run whose KL stayed near 0.01 throughout.
