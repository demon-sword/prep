The ARCH Framework

Four components with specific things to mention

A Architecture — Components & Data Flow

What pieces exist and how they connect

What to Mention IRCTC Example
Components Session Service, Memory Service, Agents
Data Flow User → Router → Conversational Agent → Tools
Agents Conversational Agent (responds), Memory Agent (extracts facts)
Services Vector DB, LLM API, Tool Registry
State Management Working (RAM), Short-term (cache), Long-term (JSON)
Key line: "We have two agents: Conversational Agent handles the chat, Memory Agent extracts facts asynchronously. They communicate via a shared state object or message queue."

R Routing — Agent Orchestration

How agents run and communicate

What to Mention IRCTC Example
Agent Orchestration Sequential vs Parallel vs Hierarchical
Communication Pattern Direct call, message queue, blackboard
Decision Logic Router/intent classifier picks agent
Key line: "Conversational and Memory agents should run in parallel. User should not wait for fact extraction. Only Conversational Agent output is shown."

C Constraints — What Can Break

Failure modes, limits, and edge cases

What to Mention IRCTC Example
Context Limit Compress at 80%, summarize older turns
LLM Failures Continue chat, log error, retry async
First Startup Graceful init with empty memory JSON
Contradictions Prefer newer, log conflict, notify if critical
Cost Smaller model for fact extraction, batch calls
Key line: "If LLM fails during fact extraction, we skip the update and continue the conversation — never block the user."

H Heuristics — Why This Design

Trade-offs, scaling, and decisions

What to Mention IRCTC Example
Why This Architecture? Parallel agents for latency, JSON for simplicity
Why Not X? Redis would scale but JSON is faster to build
Scaling Path Redis for multi-user, separate DB for long-term
Monitoring Log fact extraction accuracy, track context window usage
Key line: "I chose JSON for long-term memory because it is simple and survives restarts. If we scale beyond single-user, we would migrate to Redis or a lightweight DB."

Critical Gaps to Avoid

Common mistakes in agentic system design answers

🚫 What You Missed in IRCTC

Gap ARCH Fix
Missing memory tiers A — explicitly name Working/Short-term/Long-term
No parallel execution R — say "agents run in parallel"
No failure handling C — "skip update, continue chat"
No scaling plan H — "simple now, Redis later"
