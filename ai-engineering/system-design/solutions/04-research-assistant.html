The ARCH Framework

Four components with specific things to mention

A Architecture — Components & Data Flow

What pieces exist and how they connect

What to Mention IRCTC Example
Components Planner Agent, Search Agent, Reader Agent, Synthesizer Agent, Critic Agent, Knowledge Base, Source Manager, Session Store
Data Flow User Query → Planner → (Search → Reader)* → Synthesizer → Critic → Final Answer (with possible loops)
Agents Specialized agents: Planner (query decomposition), Search (web search), Reader (content extraction), Synthesizer (answer generation), Critic (fact verification)
Services Search API (Google/Bing), LLM API, Vector DB (for embeddings/cache), Knowledge Base (Wikipedia/custom), Session Store (Redis/JSON)
State Management Current query state (in-memory), Search history (session), Extracted passages (vector store), Reasoning trace (for transparency)
Key line: "We have five specialized agents: Planner (breaks query into sub-questions), Search (executes web searches), Reader (extracts relevant passages), Synthesizer (combines findings), and Critic (verifies facts). They operate in iterative loops until confidence threshold is met."

R Routing — Agent Orchestration

How agents run and communicate

What to Mention IRCTC Example
Agent OrchestrationIterative refinement loop: Planner → [Search → Reader]+ → Synthesizer → Critic → (repeat if needed)
Communication Pattern Sequential with looping capability; shared state via session store; async search via message queue
Decision Logic Critic agent determines if confidence threshold met; if not, Planner generates new sub-queries based on gaps
Key line: "The agents operate in an iterative loop: Planner creates sub-questions, Search and Reader gather information, Synthesizer creates draft answer, Critic verifies facts. Loop continues until confidence threshold is met or max iterations reached."

C Constraints — What Can Break

Failure modes, limits, and edge cases

What to Mention IRCTC Example
Search API Limits Rate limiting: cache results, exponential backoff, prioritize by relevance, use multiple search engines
Contradictory Sources Critic agent weights by source reliability; presents multiple viewpoints; confidence scoring reflects uncertainty
Cost/Efficiency Cache search results; limit search depth; use smaller models for initial filtering; batch similar queries
LLM Failures Fallback to extractive summarization; continue with available data; degrade gracefully
Max Iterations Hard limit (e.g., 5 iterations) to prevent infinite loops; return best available answer with confidence score
Key line: "We handle contradictory sources by having the Critic agent weight sources by reliability and present multiple viewpoints. We enforce a max iteration limit (e.g., 5) to prevent infinite loops."

H Heuristics — Why This Design

Trade-offs, scaling, and decisions

What to Mention IRCTC Example
Why This Architecture? Specialized agents allow independent optimization; iterative refinement improves accuracy; modular design enables testing
Why Not X? Single agent would struggle with complex reasoning; no iteration would miss deep insights; no critic would propagate errors
Scaling Path Cache search results; use smaller/quantized models for initial processing; batch similar queries; async processing
Monitoring Track iteration count per query, source reliability scores, answer confidence distribution, search API costs, latency breakdown by agent
Key line: "I chose iterative refinement because complex questions often require multiple search cycles. We balance depth vs cost by caching results and limiting iterations."

E Evaluation — How We Measure Success

Offline benchmarks, online metrics, and per-agent KPIs

Type Metric Target / Example
Offline Factuality score > 90% factual accuracy on TriviaQA/NQ benchmark; < 2% hallucination rate
Offline Answer relevance BERTScore > 0.85 vs human reference; BLEU-4 > 0.3
Offline Coverage > 90% of test questions answered with sufficient detail; < 5% "I don't know" for known topics
Online Answer confidence > 80% average confidence; auto-flag for human review if < 60%
Online Cost per query < $0.10 per question; search API cost < 30% of total
Online Latency p95 < 10 seconds; p99 < 30 seconds (including search)
Per-Agent Planner Agent Sub-query decomposition accuracy > 90%; question coverage > 95%
Per-Agent Search Agent Search result relevance > 85% (human rated); recall > 90%
Per-Agent Critic Agent Factual error detection > 95%; source reliability scoring correlation > 0.85
System User satisfaction 4.5/5 rating; < 5% "insufficient answer" reports
System Source citation 100% of answers include citations; citation accuracy > 95%
Key line: "We evaluate offline on TriviaQA benchmark for factual accuracy (> 90%). Online, we track answer confidence (> 80%), cost per query (< $0.10), and latency (p95 < 10s). Auto-flag answers < 60% confidence for human review."
