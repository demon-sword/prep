The ARCH Framework

Four components with specific things to mention

A Architecture — Components & Data Flow

What pieces exist and how they connect

What to Mention IRCTC Example
Components Intake Agent, FAQ Agent, Troubleshooting Agent, Human Escalation Agent, Feedback Agent, Session Manager, Knowledge Base, Tool Registry
Data Flow User Query → Intake → [FAQ → Troubleshooting]* → [Human Escalation if needed] → Feedback → Response
Agents Specialized agents: Intake (classify intent), FAQ (answer from knowledge), Troubleshooting (run diagnostics), Human Escalation (handoff), Feedback (learn from outcomes)
Services Knowledge Base (FAQs/documents), CRM System, Chat/Web Interface, Email/SMS Gateway, Analytics DB, Tool Registry (for diagnostics)
State Management Session context (conversation history), User profile (preferences/history), Escalation history, Feedback logs, Knowledge base versions
Key line: "We have five specialized agents: Intake (classifies user intent), FAQ (tries to answer from knowledge base), Troubleshooting (runs diagnostic steps), Human Escalation (handles handoff to human), and Feedback (learns from outcomes). They operate in a tiered escalation model."

R Routing — Agent Orchestration

How agents run and communicate

What to Mention IRCTC Example
Agent OrchestrationSequential escalation: Intake → FAQ → Troubleshooting → Human Escalation → Feedback; each step can terminate early
Communication Pattern Sequential with early termination; shared session context; async feedback learning
Decision Logic Intake agent determines complexity; FAQ agent uses confidence threshold; Troubleshooting uses success criteria; Human Escalation triggered by repeated failures or anger detection
Key line: "Agents operate in sequential escalation: Intake → FAQ → Troubleshooting → Human Escalation. Each agent can terminate early if successful (e.g., FAQ agent answers confidently). Feedback agent learns asynchronously from outcomes."

C Constraints — What Can Break

Failure modes, limits, and edge cases

FAQ agent confidence threshold; if low, proceed to Troubleshooting; log gaps for KB updates
What to Mention IRCTC Example
Angry/Frustrated Users Sentiment analysis in Intake agent; fast-track to human if anger detected; de-escalation scripts in Troubleshooting agent
Knowledge Base Gaps
Escalation Thresholds Balance resolution rate vs cost: too low → poor experience; too high → wasted human effort; tune based on historical data
Context Loss in Handoff Transfer full session context + summary + user profile to human agent; use screen sharing/co-browse if needed
Feedback Latency Asynchronous learning: store outcomes, batch process for model updates; real-time alerts for critical failures
Key line: "We handle angry users via sentiment analysis in Intake agent for fast-track to human. Knowledge base gaps trigger progression to Troubleshooting agent. Full session context is transferred during human handoff."

H Heuristics — Why This Design

Trade-offs, scaling, and decisions

What to Mention IRCTC Example
Why This Architecture? Tiered escalation balances cost and quality; specialized agents allow expertise; feedback loop enables continuous improvement
Why Not X? Single agent would be inconsistent; always-human would be expensive; no feedback loop would prevent learning from mistakes
Scaling Path Horizontal scaling of agents; intelligent routing based on complexity; self-service ratio improvement over time; AI-assisted human agents
Monitoring Track escalation rate, first-contact resolution, average handling time, customer satisfaction (CSAT), agent utilization, knowledge base effectiveness
Key line: "I chose tiered escalation to balance cost and quality. We monitor escalation rate and CSAT to tune thresholds. Feedback loop enables continuous improvement from both AI and human interactions."

E Evaluation — How We Measure Success

Offline benchmarks, online metrics, and per-agent KPIs

Type Metric Target / Example
Offline Intent classification accuracy > 95% intent classification accuracy; > 90% sentiment detection accuracy
Offline FAQ coverage > 90% of common questions answered correctly; zero false positives on critical escalations
Offline Regression tests Zero regression on historical support tickets; no increase in false escalations
Online First Contact Resolution (FCR) > 70% FCR; < 5% re-contact rate for same issue
Online Escalation rate < 15% for Tier 1; < 5% for Tier 2; track trend over time
Online Customer satisfaction (CSAT) > 4.5/5; < 3% "dissatisfied" ratings; NPS > 50
Per-Agent Intake Agent Intent classification > 95%; sentiment detection > 90%; routing accuracy > 95%
Per-Agent FAQ Agent Answer relevance > 90% (human rated); resolution rate > 80%
Per-Agent Troubleshooting Agent Diagnostic accuracy > 85%; mean time to suggest fix < 3 minutes
System Human handoff quality Average handling time (AHT) < 60% of baseline; context completeness > 95%
System Learning loop Weekly model updates; feedback incorporation > 90%; knowledge base growth > 10%/quarter
Key line: "We evaluate offline on intent classification (> 95%) and sentiment detection (> 90%). Online, we track First Contact Resolution (> 70%), escalation rate (< 15%), and CSAT (> 4.5/5). Weekly model updates incorporate 90%+ of feedback."
