The ARCH Framework

Four components with specific things to mention

A Architecture — Components & Data Flow

What pieces exist and how they connect

What to Mention IRCTC Example
Components Monitor Agent, Detect Agent, Diagnose Agent, Remediate Agent, Notify Agent, Orchestrator, Alert Manager, Audit Logger, Rollback Manager
Data Flow Infrastructure Metrics/Logs/Traces → Monitor → Detect → Diagnose → [Remediate → Audit] → Notify
Agents Specialized agents: Monitor (collects metrics/logs), Detect (finds anomalies), Diagnose (root cause analysis), Remediate (executes fixes), Notify (alerts teams), Audit (logs actions), Rollback (reverts changes)
Services Monitoring stack (Prometheus/Grafana/ELK), Orchestration (Kubernetes/Docker Swarm), Configuration Consul/Etcd), Communication (Slack/Email/PagerDuty), Storage (S3/ADLS for audit logs)
State Management Current system state (in-memory), Active incidents (incident store), Audit trail (append-only log), Baseline metrics (historical), Rollback snapshots (point-in-time)
Key line: "We have seven specialized agents: Monitor (collects metrics/logs), Detect (finds anomalies), Diagnose (root cause analysis), Remediate (executes fixes), Notify (alerts teams), Audit (logs actions), and Rollback (reverts changes). They operate in a sequential pipeline with feedback loops for validation."

R Routing — Agent Orchestration

How agents run and communicate

What to Mention IRCTC Example
Agent OrchestrationSequential pipeline with conditional branching; Monitor → Detect → Diagnose → [Remediate → Audit → Notify] with Rollback on failure
Communication PatternSequential with conditional paths; shared state via incident store; async notifications; event-driven via message queue
Decision Logic Detect agent uses anomaly detection thresholds; Diagnose agent uses correlation/causation analysis; Remediate agent requires human approval for high-risk actions; Rollback triggered on failed validation
Key line: "Agents operate in a sequential pipeline: Monitor → Detect → Diagnose → [Remediate → Audit → Notify]. Remediation requires human approval for high-risk actions. Rollback is triggered if post-remediation validation fails. Audit logs all actions for compliance."

H Heuristics — Why This Design

Trade-offs, scaling, and decisions

What to Mention IRCTC Example
Why This Architecture? Specialized agents allow expertise in each domain; sequential pipeline ensures proper order; human approval for high-risk actions prevents costly mistakes
Why Not X? Single agent would struggle with both detection and remediation; fully autonomous could cause costly errors; no audit trail would violate compliance
Scaling Path Horizontal scaling of agents; stream processing (Kafka/Flink) for real-time metrics; canary deployments for safe remediation; feature flags for gradual rollout
Monitoring Track MTTR (Mean Time To Resolve), alert fatigue, false positive/negative rates, remediation success rate, human approval rate, audit trail completeness
Key line: "I chose sequential pipeline with human approval for high-risk actions to balance automation with safety. We monitor MTTR, alert fatigue, and remediation success rate to optimize the balance."

E Evaluation — How We Measure Success

Offline benchmarks, online metrics, and per-agent KPIs

Type Metric Target / Example
Offline Anomaly detection accuracy > 95% true positive rate; < 2% false positive rate on synthetic test data
Offline Root cause analysis accuracy Top-1 accuracy > 80%; top-3 accuracy > 95% vs expert diagnosis
Offline Remediation test coverage 100% of automated fixes tested in staging; zero un-tested remediations in prod
Online MTTD/MTTR Mean Time To Detect (MTTD) < 30 seconds; MTTR < 5 minutes for known issues
Online False positive/negative rates < 3% false positives; < 0.1% false negatives on critical alerts
Online Remediation success rate > 90% first-attempt success; < 2% incidents requiring rollback
Per-Agent Detect Agent Anomaly detection > 95% recall; AUC-ROC > 0.95; Alert fatigue < 5/day
Per-Agent Diagnose Agent Root cause accuracy > 80%; Correlation confidence > 0.85
Per-Agent Remediate Agent Fix success rate > 90%; Blast radius < 1% of services; Zero unapproved critical changes
System Safety metrics 100% human approval for critical changes; Audit trail completeness > 99.9%
System Operational efficiency Ops team alert load reduced by > 70%; On-call incidents < 3 per week
Key line: "We evaluate offline on anomaly detection (> 95% recall, < 2% FPR) and root cause analysis (> 80% accuracy). Online, we MTTD < 30 seconds, MTTR < 5 minutes, and remediation success > 90%. Zero unapproved critical changes."
