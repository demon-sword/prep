The ARCH Framework

Four components with specific things to mention

A Architecture — Components & Data Flow

What pieces exist and how they connect

What to Mention IRCTC Example
Components Session Service, Memory Service, Conversational Agent, Memory Agent, Tool Registry
Data Flow User Input → Router → Conversational Agent → (Tools OR Memory Agent) → Response
Agents Conversational Agent (handles chat & tools), Memory Agent (extracts facts asynchronously)
Services LLM API, Vector DB (for tools), Session Store (Redis/JSON), Memory Store (JSON)
State Management Working Memory (RAM): Current session turns
Short-term Memory (Redis): Summaries of recent sessions
Long-term Memory (JSON): Structured facts (name, class preference, routes)
Key line: "We have a three-tier memory system. Working memory holds the current session. When context window hits 80%, we compress older turns to short-term memory. Long-term memory stores structured facts (name, class preference, frequent routes) as JSON to survive process restarts."

R Routing — Agent Orchestration

How agents run and communicate

What to Mention IRCTC Example
Agent Orchestration Conversational and Memory agents run in parallel; user sees only conversational output
Communication Pattern Shared state via blackboard pattern; message queue for async fact extraction
Decision Logic Planner (Router) classifies intent; Conversational Agent handles chat, Memory Agent runs in background
Key line: "Conversational and Memory agents run in parallel. The user never waits for fact extraction. Only the conversational response is streamed. Memory extraction failures are logged but don't block the chat."

C Constraints — What Can Break

Failure modes, limits, and edge cases

What to Mention IRCTC Example
Context Limit Compress at 80% window using summarization; keep last 3 turns intact
LLM Failures Continue chat, log error, retry async with exponential backoff
First Startup Graceful init: create empty memory JSON if file doesn't exist
Contradictions Prefer newer value, log conflict, notify if critical (e.g., passenger name change)
Cost Smaller model for fact extraction (e.g., DistilBERT), batch similar requests, cache frequent queries
Key line: "If LLM fails during fact extraction, we skip the update and continue the conversation — never block the user. First startup creates empty memory JSON gracefully."

H Heuristics — Why This Design

Trade-offs, scaling, and decisions

What to Mention IRCTC Example
Why This Architecture? Parallel agents for low latency; JSON for simplicity and persistence
Why Not X? Redis would scale but JSON is faster to build for MVP; separate agents keep chat responsive
Scaling Path Redis for multi-user isolation, separate DB for long-term facts, Kafka for async fact extraction
Monitoring Log fact extraction accuracy, track context window usage %, monitor agent latency
Key line: "I chose JSON for long-term memory because it's simple and survives restarts. If we scale beyond single-user, we migrate to Redis or a lightweight DB. Parallel agents keep chat responsive."

E Evaluation — How We Measure Success

Offline benchmarks, online metrics, and per-agent KPIs

Type Metric Target / Example
Offline Fact extraction accuracy > 90% precision, > 88% recall on held-out test set
Offline Conversation coherence BERTScore > 0.85 vs human reference
Offline Regression tests 500 synthetic dialogues, zero regression on critical paths
Online Latency (p95) Conversational response < 2s; Memory extraction < 5s
Online Accuracy / F1 Intent classification > 95%; Fact extraction > 90%
Online Cost per conversation < $0.05 per full session (inquiry → resolution)
Per-Agent Conversational Agent Response relevance (human rating 4.5/5), safety score
Per-Agent Memory Agent Facts extracted / ground truth; contradiction rate < 2%
System CSAT / User satisfaction 4.5/5 average; escalation rate < 5%
System Rollback trigger Auto-rollback if accuracy < 85% or p95 latency > 3s
Key line: "We evaluate offline with 500 synthetic test cases before deployment. Online, we track p95 latency, fact extraction F1, and cost per conversation. Auto-rollback triggers if accuracy drops below 85% or latency exceeds 3 seconds."

Quick Reference: ARCH Summary

Memorize this for your answer
A — Architecture: Three-tier memory (Working, Short-term, Long-term). Two agents: Conversational (chat/tools) and Memory (fact extraction).
R — Routing: Conversational and Memory agents run in parallel via shared state. Only conversational output shown to user.
C — Constraints: Context limit → compression at 80%; LLM failure → skip update and continue; first startup → graceful init with empty JSON.
H — Heuristics: JSON for persistence (simple now, Redis later). Parallel agents for low latency. Separate LLM call keeps chat responsive.
