The ARCH Framework

Four components with specific things to mention

A Architecture — Components & Data Flow

What pieces exist and how they connect

What to Mention IRCTC Example
Components Profiler Agent, Curriculum Agent, Question Agent, Hint Agent, Mentor Agent, Session Manager, Content Repository, Progress Tracker
Data Flow Student Interaction → Profiler → Curriculum → Question → [Hint]* → Mentor → Progress Update
Agents Specialized agents: Profiler (assesses knowledge level), Curriculum (selects next topics), Question (generates practice questions), Hint (provides scaffolded hints), Mentor (tracks progress & motivation)
Services LLM API, Content Database (questions/explanations), Progress DB (student analytics), Recommendation Engine, Notification Service (email/push)
State Management Student profile (knowledge map, learning style, progress), Session state (current problem, hints used), Mastery tracking (per skill/concept), Learning trajectory
Key line: "We have five specialized agents: Profiler (assesses knowledge level), Curriculum (selects next topics), Question (generates practice questions), Hint (provides scaffolded hints), and Mentor (tracks progress and motivation). They work together to create a personalized learning path."

R Routing — Agent Orchestration

How agents run and communicate

What to Mention IRCTC Example
Agent OrchestrationSequential workflow with feedback loops; Profiler → Curriculum → Question → [Hint iterations] → Mentor → Progress update
Communication Pattern Sequential with conditional hint loops; shared state via student profile; async progress updates
Decision Logic Profiler determines knowledge gaps; Curriculum selects topics based on prerequisites; Question Agent generates targeted questions; Hint Agent provides graduated assistance; Mentor adjusts difficulty and provides encouragement
Key line: "Agents operate in a sequential workflow: Profiler → Curriculum → Question → [Hint iterations] → Mentor. Hint iterations continue until student solves problem or requests help. Mentor agent adjusts difficulty and provides motivational feedback based on progress."

C Constraints — What Can Break

Failure modes, limits, and edge cases

Prevent memorization by varying question types; introduce novelty; use spaced repetition; track transfer to new contexts
What to Mention IRCTC Example
Overfitting to Student
Engagement vs Learning Balance immediate success (easy questions) with long-term growth (challenging problems); use adaptive difficulty curves; gamification for motivation
Knowledge Gaps Detection Profiler uses diagnostic questions; confidence-based assessment; identifies prerequisite gaps before advancing
Scalability Horizontal scaling of agents; caching common explanations; batch question generation; efficient knowledge graph traversal
Frustration Detection Monitor time-on-task, error patterns, help requests; intervene with encouragement, simpler problems, or break suggestions
Key line: "We prevent overfitting by varying question types and using spaced repetition. We balance engagement vs learning with adaptive difficulty curves. Frustration detection monitors time-on-task and error patterns for timely intervention."

H Heuristics — Why This Design

Trade-offs, scaling, and decisions

What to Mention IRCTC Example
Why This Architecture? Specialized agents allow expertise in each domain; sequential workflow ensures logical progression; feedback loops enable adaptation
Why Not X? Single agent would struggle with both assessment and instruction; fixed curriculum ignores individual differences; no hint scaffolding leads to frustration
Scaling Path Cache common explanations and questions; use embedding-based similarity for content retrieval; horizontal scaling of agents; batch processing for batch operations
Monitoring Track mastery rates per concept, time-to-mastery, hint usage per problem, student satisfaction, retention after intervals, knowledge transfer to new problems
Key line: "I chose specialized agents for expertise in assessment vs instruction. We balance engagement vs learning with adaptive difficulty curves and monitor mastery rates, time-to-mastery, and knowledge transfer."

E Evaluation — How We Measure Success

Offline benchmarks, online metrics, and per-agent KPIs

Type Metric Target / Example
Offline Diagnostic accuracy > 95% alignment with expert teacher assessments; < 5% false negatives on knowledge gaps
Offline Curriculum generation quality Topic prerequisite ordering > 90% expert agreement; no circular dependencies
Offline Question generation Human-rated relevance > 90%; difficulty calibration error < 0.5 grade levels
Online Mastery rate > 80% of students achieve mastery within expected time; < 10% require remediation
Online Time-to-mastery Average time < 20% above teacher estimate; p95 < 50% above estimate
Online Engagement & retention Session completion > 85%; 7-day retention > 60%; 30-day retention > 40%
Per-Agent Profiler Agent Knowledge gap detection > 95%; Misdiagnosis rate < 3%
Per-Agent Curriculum Agent Prerequisite satisfaction > 90%; Student progression rate > 85%
Per-Agent Question Agent Difficulty calibration < 0.5 levels; Human-rated quality > 4/5
System Learning outcomes Post-test scores > 20% improvement over pre-test; Knowledge retention > 70% after 30 days
System Student satisfaction 4.5/5 rating; < 5% "frustrated" reports; Parent satisfaction > 4/5
Key line: "We evaluate offline via expert teacher assessments for diagnostic accuracy (> 95%). Online, we track mastery rate (> 80%), engagement (session completion > 85%), and learning outcomes (20% improvement). Retention > 70% after 30 days."
