Supervised Learning

10k-Nearest Neighbors

Instance-based classification by majority vote among the k nearest neighbors, the curse of dimensionality, and the bias-variance effect of k.

Theory

A Lazy, Non-Parametric Learner

k-Nearest Neighbors is the purest example of instance-based (lazy) learning: there is no training phase in the usual sense — fit() just stores the training set (or builds a spatial index over it). All the work happens at prediction time: to classify a new point x, compute the distance from x to every stored training point, take the k closest ones, and predict the majority class among them (or the mean target for regression). Because it makes no assumption about the functional form of the decision boundary — no linear separability, no Gaussian class-conditional densities — kNN is non-parametric: the "model" grows with the data, and with enough data and small enough k, it can approximate arbitrarily complex boundaries. This flexibility is also the danger: kNN has effectively n parameters (the whole dataset), so it overfits noise readily at low k.

Distance Metrics

"Nearest" requires a distance function, and the choice matters as much as k itself. Euclidean distance (L2, √Σ(xᵢ−yᵢ)²) is the default and assumes isotropic, roughly spherical clusters. Manhattan distance (L1, Σ|xᵢ−yᵢ|) is more robust to outliers along individual axes and often preferred in high dimensions or grid-like feature spaces. Minkowski generalizes both with a parameter p (p=2 → Euclidean, p=1 → Manhattan). For categorical or mixed data, Hamming distance or Gower's distance is used instead. Critically, kNN requires feature scaling — a feature ranging 0–100,000 (e.g. salary) will dominate a distance calculation over a feature ranging 0–1 (e.g. a normalized score) unless both are standardized first (StandardScaler or MinMaxScaler), a requirement decision trees and other split-based models don't share (see 32-feature-scaling).

Choosing k: The Bias-Variance Knob

k directly controls model complexity, mirroring 01-bias-variance-tradeoff. k=1 assigns each new point the label of its single closest training point — the decision boundary is a jagged Voronoi tessellation that perfectly fits (and memorizes noise in) the training data: zero bias, very high variance. As k grows, the boundary smooths — each prediction averages over more neighbors, reducing variance but increasing bias, until at k=n every point is classified as the global majority class regardless of its features (maximum bias, zero variance). The sweet spot is typically found by cross-validating over a range of odd k values (odd to avoid ties in binary classification) — scikit-learn's GridSearchCV over KNeighborsClassifier(n_neighbors=...) is the standard recipe. A useful refinement is distance-weighted voting (weights='distance'): closer neighbors get more say (weight ∝ 1/distance), which lets you use a larger k for robustness while still letting the truly closest points dominate the vote — often outperforms uniform weighting with little extra cost.

The Curse of Dimensionality

kNN degrades sharply as dimensionality grows. In high-dimensional spaces, distances between points concentrate — the ratio of the distance to the nearest point vs. the farthest point approaches 1, so "nearest" stops being a meaningful concept (a well-known result: for d dimensions and n uniformly random points, the expected gap between nearest and farthest neighbor distance shrinks as d grows). Practically, kNN on raw high-dimensional data (raw pixel vectors, raw text TF-IDF with tens of thousands of dimensions) performs poorly; the standard fix is to first reduce dimensionality (PCA, autoencoders) or use a learned/task-specific embedding (e.g. classify in a CNN's penultimate-layer embedding space, not raw pixels) before applying kNN.

Production Reality

Naive kNN prediction is O(n·d) per query (compare against every training point) — fine for a few thousand points, unusable for a training set of millions queried in real time. scikit-learn's algorithm='kd_tree' or 'ball_tree' options build a spatial index at fit time that gets exact-nearest-neighbor query cost down to roughly O(d·log n) in low dimensions (d ≲ 20), but tree-based indexes degrade back toward brute force as dimensionality rises (another curse-of-dimensionality symptom) — scikit-learn's algorithm='auto' falls back to brute force for high-d or sparse data. At real production scale (embedding search over millions–billions of vectors, e.g. recommendation retrieval or RAG document lookup), exact kNN is abandoned in favor of approximate nearest neighbor (ANN) libraries — FAISS, ScaNN, Annoy, or HNSW-based indexes (used in Pinecone, Weaviate, Qdrant, pgvector's HNSW index) — trading a small, tunable recall loss (typically 90–99% recall@10) for 100–1000x query speedups. kNN's other production costs: it must keep the entire training set in memory (or on fast disk) to serve predictions, has no natural way to output calibrated probabilities beyond the raw vote fraction, and is a weak baseline for imbalanced classes (the majority class dominates local neighborhoods unless you weight votes or use imbalanced-learn's neighborhood-aware resamplers).

Key Takeaways

  • kNN has no training cost but expensive inference — the exact opposite of most models. A logistic regression or neural net front-loads all the compute into fit() and predicts in microseconds; kNN's fit() is just a memcopy (or index build) and every single prediction re-scans the dataset. This makes it a poor fit for low-latency, high-QPS serving unless paired with an ANN index (FAISS/HNSW).
  • k is the bias-variance dial, and it should be tuned by cross-validation, not intuition. k=1 gives a Voronoi-jagged, zero-training-error, high-variance boundary; k→n collapses to predicting the global majority class. There's rarely a "correct" default — scikit-learn's default n_neighbors=5 is a starting point, not a recommendation.
  • Unscaled features silently break kNN. Because prediction is purely distance-based, a single high-magnitude feature can dominate the distance calculation and make every other feature irrelevant — always StandardScaler or MinMaxScaler before fitting, unlike tree-based models which are scale-invariant.
  • The curse of dimensionality is real, not folklore — past roughly 15–20 raw dimensions, all pairwise distances start looking similar and "nearest" loses meaning. Production kNN on images/text always runs in a learned embedding space (CNN features, sentence embeddings) or after PCA, never on raw high-dimensional input.
  • Exact kNN doesn't scale — approximate nearest neighbor (ANN) does. FAISS (Meta), ScaNN (Google), Annoy (Spotify), and HNSW-based vector databases (Pinecone, Qdrant, pgvector, Weaviate) are the production answer once n crosses roughly 100K–1M vectors, trading a small recall loss (often 95%+ recall@10) for orders-of-magnitude latency gains — this is the exact mechanism behind RAG retrieval and most recommendation candidate-generation stages.
  • Distance-weighted voting (weights='distance') is an easy, often-skipped win — it lets a larger, more stable k behave like a smaller one near the query point while still smoothing out distant noise, frequently beating uniform voting at the same k with zero extra tuning cost.
