01Bias-Variance Tradeoff

How model complexity trades off bias (underfitting) against variance (overfitting), and why total generalization error is minimized at an intermediate complexity — not at zero training error.

Theory

The Core Decomposition

For a regression model trained to predict y = f(x) + ε where ε is irreducible noise with variance σ², the expected squared error of a prediction at a point x, taken over many random training sets, decomposes cleanly into three additive terms:

E[(y − f̂(x))²] = σ²  +  Bias[f̂(x)]²  +  Var[f̂(x)]

Bias is the error from wrong assumptions in the learning algorithm — how far the average prediction (across many resamples of training data) is from the true function. Variance is the error from sensitivity to the specific training sample — how much the prediction would change if you retrained on a different draw of data. Irreducible error (σ²) is noise in the data-generating process itself; no model, however good, can remove it. This decomposition is the mathematical backbone behind almost every "why is my model doing X" diagnosis in production ML.

What High Bias and High Variance Look Like

A high-bias model is too simple to capture the true relationship — a linear model fit to a clearly nonlinear process, or a shallow decision tree (max_depth=2) on a complex decision surface. Symptoms: training error is high and validation error is roughly equal to training error — the model isn't even fitting the data it has seen. This is underfitting.

A high-variance model is complex enough to memorize idiosyncrasies of the training sample — a degree-15 polynomial fit to 15 noisy points, or an unpruned decision tree grown to purity. Symptoms: training error is near zero, but validation/test error is much higher, and that gap is unstable across different train/test splits. This is overfitting.

Total generalization error, as a function of model complexity, traces a U-shape (or J-shape): bias² falls monotonically as complexity increases, variance rises monotonically, and their sum is minimized somewhere in the middle — the "sweet spot" that cross-validation is designed to find.

Ensembles Attack Different Sides

This decomposition is exactly why bagging and boosting exist as opposite strategies. Bagging (random forests) averages many high-variance, low-bias base learners (deep unpruned trees) trained on bootstrap resamples — averaging cancels variance while leaving bias roughly unchanged, since Var(mean of B i.i.d.-ish estimators) ≈ Var/B under low correlation. Boosting (XGBoost, LightGBM) does the opposite: it starts from high-bias, low-variance weak learners (shallow trees, depth 3–6) and sequentially reduces bias by fitting each new tree to the residual error of the ensemble so far — variance is controlled separately via shrinkage (learning_rate, typically 0.01–0.1) and subsampling.

Double Descent — the Modern Wrinkle

Classical bias-variance theory predicts variance should explode once model capacity exceeds the number of training points (the interpolation threshold). Deep learning empirically breaks this: past the threshold, test error can descend a second time as capacity keeps growing (Belkin et al., 2019). Overparameterized networks with implicit regularization from SGD find flat, generalizing minima instead of just memorizing. This doesn't invalidate the bias-variance framework — it means the variance term behaves non-monotonically for certain model classes (deep nets, and even some boosted ensembles) rather than always increasing with capacity as classical theory assumed for smooth parametric families.

Production Reality

In practice you never observe bias and variance directly — you infer the regime from learning curves (train vs validation error vs training set size, see concept 24) and from the train/validation gap at a fixed dataset size. A gap near zero with both errors high → underfitting, add capacity or features. A large gap with low training error → overfitting, add regularization, more data, or reduce capacity. scikit-learn's GridSearchCV / validation_curve and XGBoost's early_stopping_rounds against a held-out eval set are the standard tools for locating the sweet spot automatically rather than by hand-tuning a single complexity slider.

Key Takeaways

  • Zero training error is a red flag, not a goal. A model that perfectly interpolates training data (degree-15 polynomial on 15 points, an unpruned tree) has driven bias to ~0 but pushed variance to its maximum — the normal-equations solve above becomes numerically unstable near this point precisely because it's fitting noise, which is why production pipelines ridge-regularize even "exact" linear solves.
  • Bagging and boosting are variance-reduction and bias-reduction strategies, respectively — picking the wrong one for your symptom makes things worse. If a single deep tree overfits (high variance), bagging it into a random forest helps; if a single shallow tree underfits (high bias), bagging won't fix it — you need boosting or more capacity.
  • Regularization strength (λ in ridge/lasso, learning_rate in GBMs, dropout rate in nets) is a direct bias-variance dial — sklearn's RidgeCV/LassoCV and XGBoost's early_stopping_rounds exist specifically to search this dial automatically against a validation set instead of hand-tuning.
  • More data reduces variance but not bias. If your learning curve shows train and validation error converging to a high plateau, collecting more data won't help — you have a bias problem and need a more expressive model or better features. This is the single most common wasted-effort mistake in applied ML.
  • Double descent means "more capacity always overfits" is false for overparameterized deep nets. Modern architectures trained past the interpolation threshold with SGD's implicit regularization can generalize better than mid-sized models — but this doesn't apply cleanly to classical models like unregularized polynomial regression or unpruned trees, which behave exactly as classical theory predicts.
  • k-fold cross-validation exists because a single train/test split gives you a noisy point estimate of variance itself. The error-vs-complexity curve above uses one fixed test set for clarity; in practice you'd average that test-error curve over 5–10 folds before picking a degree, since the "sweet spot" location itself has variance when n is small.
