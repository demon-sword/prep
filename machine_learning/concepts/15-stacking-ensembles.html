15Stacking Ensembles

Combining heterogeneous base models via a meta-learner trained on out-of-fold predictions — when stacking beats simple averaging.

Theory

What Stacking Actually Combines

Stacking (stacked generalization) is a two-level ensemble: a set of level-0 base models — ideally heterogeneous in kind (a linear model, a tree, a kNN, a neural net) rather than just re-runs of the same algorithm with different seeds — each produce a prediction for every training row, and a level-1 meta-learner is trained to map those base predictions onto the true label. Formally, given base models f₁,…,f_M, the meta-model learns g(f₁(x),…,f_M(x)) → ŷ. This is a strict generalization of both bagging and simple averaging: averaging is stacking with a fixed, un-learned meta-function g(p) = mean(p); stacking replaces that fixed rule with a learned one, letting the ensemble discover that, say, the kNN model should be trusted more in dense regions and the linear model more in sparse, extrapolation-prone regions — a per-region weighting that a simple average can never express.

Why Out-of-Fold Predictions Are Non-Negotiable

The single most common stacking mistake is training the meta-learner on base-model predictions generated on the same rows those base models were fit on. A base model that overfits (a deep tree, kNN with small k) will reproduce training labels almost perfectly in-sample, and the meta-learner will learn to simply trust that overfit model — a form of leakage that looks great on training accuracy and collapses at test time. The fix, exactly like the cross-validation used to estimate generalization error, is to generate out-of-fold (OOF) predictions: split the training data into K folds, and for each fold, train the base models on the other K-1 folds and predict only on the held-out fold. Stitching those held-out predictions back together gives every training row a base-model prediction that row was never used to produce — the same guarantee sklearn.model_selection.cross_val_predict provides, which is exactly what sklearn.ensemble.StackingClassifier/StackingRegressor use internally (default cv=5) to build the meta-learner's training matrix.

Choosing (and Constraining) the Meta-Learner

Because base-model OOF predictions are already highly informative and often strongly correlated with each other (all three models are trying to predict the same y), the meta-learner should stay simple — logistic or ridge regression is the standard choice, sometimes with a non-negativity constraint on the weights so the meta-model can only ever upweight or ignore a base model, never invert its prediction, which keeps the combination interpretable as a soft weighted vote. Using a second gradient-boosted tree as the meta-learner is a classic overfitting trap: with only M highly correlated input features and limited OOF rows, a complex meta-learner will find spurious interaction patterns in fold noise rather than genuine model-competence structure.

Stacking vs. Blending vs. Simple Averaging

Blending is stacking's cheaper cousin: instead of full K-fold OOF generation, base models are trained once on a training split and their predictions on a single held-out blend set train the meta-learner — one training pass per base model instead of K, at the cost of using less data to fit the meta-learner and a noisier performance estimate. This was the approach the winning Netflix Prize team used at scale, where full K-fold stacking across dozens of models was computationally impractical. Simple (or weighted) averaging needs no held-out data and no leakage guardrails at all, and is often within a fraction of a point of a properly-built stack — which is precisely why stacking is worth the complexity only when base models are genuinely diverse in their error patterns, not just individually accurate.

Production Reality

Stacking wins competitions (nearly every top-10 Kaggle tabular solution blends or stacks multiple model families) but is comparatively rare in low-latency production serving because it multiplies inference cost by M+1 model calls per prediction and multiplies operational surface area — M+1 models to monitor for drift, retrain, and version instead of one. Typical accuracy gains from stacking over the single best base model or a well-tuned weighted average are modest, often 0.5–2 points of AUC or a few tenths of a percent of accuracy — worth it in a high-value, low-QPS batch-scoring context (credit underwriting, churn scoring run nightly) but rarely worth it for a sub-50ms real-time endpoint where that budget is better spent tuning one strong gradient-boosted model. A further subtlety: evaluating the stacked ensemble's OOF accuracy on the same OOF predictions used to fit the meta-learner still slightly overstates generalization, because the meta-learner's own hyperparameters were implicitly tuned against that data — an honest estimate requires a further nested/outer CV loop or a fully held-out test set the meta-learner never touches.

Key Takeaways

  • Out-of-fold predictions are non-negotiable, not an optional refinement. Training a meta-learner on base predictions generated in-sample lets it learn to trust whichever base model overfits hardest; sklearn.ensemble.StackingClassifier's default cv=5 exists specifically to force the same held-out discipline as ordinary cross-validation onto the meta-learner's training data.
  • Keep the meta-learner simple. Ridge or logistic regression (optionally non-negative-weighted) is the standard choice because base-model OOF predictions are already highly correlated and informative — a second gradient-boosted tree as meta-learner is a classic overfitting trap, chasing noise in a handful of correlated features instead of genuine model-competence structure.
  • Diversity of base models matters more than individual accuracy. Stacking three correlated GBMs barely beats one; combining a linear model, a tree, and a kNN — models with genuinely different inductive biases and error patterns — is what lets the meta-learner find real complementary structure to exploit, as this demo's linear stumps + nonlinear kNN combination shows on a two-moons dataset no single axis-aligned model can solve.
  • Blending trades statistical efficiency for speed. A single holdout split instead of full K-fold OOF generation needs only one training pass per base model instead of K — the approach large-scale competition teams (Netflix Prize) used when K-fold retraining dozens of models was computationally impractical, at the cost of a noisier, lower-data meta-learner fit.
  • Production inference cost scales with M+1, not 1. Every stacked prediction requires calling all M base models plus the meta-learner, and every one of those M+1 models needs its own drift monitoring and retraining cadence — the typical 0.5–2 point AUC gain over a well-tuned single model or weighted average rarely justifies that in a low-latency real-time endpoint, but often does in high-value batch scoring (nightly credit/churn runs).
  • Reported OOF accuracy for the stacked ensemble is still slightly optimistic. The meta-learner's weights were fit on those exact OOF predictions, so evaluating on the same OOF set understates generalization error; a rigorous comparison needs a further outer/nested CV loop or a fully held-out test set the meta-learner never influenced.
