07Logistic Regression

Sigmoid link function, log-odds, decision boundary, and maximum likelihood estimation for binary classification.

Theory

The Sigmoid Link, Log-Odds, and the Model

Logistic regression models the probability that an example belongs to the positive class as a linear combination of features passed through the sigmoid (logistic) function: p = σ(z) = 1 / (1 + e⁻ᶻ), where z = w·x + b. Sigmoid squashes any real-valued z into (0, 1), giving a valid probability. Rearranging the model reveals what's actually linear: the log-odds (logit) of the positive class is linear in the features — log(p / (1−p)) = w·x + b. This is the key mental model: logistic regression is a linear model for log-odds, not for probability itself. A one-unit increase in feature xᵢ multiplies the odds by e^wᵢ — a coefficient of 0.69 means the odds roughly double per unit increase, which is exactly why coefficients are reported as odds ratios in epidemiology and credit-risk modeling.

p̂ = σ(w·x + b)   ⟺   log(p̂ / (1 − p̂)) = w·x + b

The decision boundary — the set of points where the model is indifferent between classes — is exactly where z = 0, i.e. w·x + b = 0. Because that equation is linear in x, logistic regression's decision boundary is always a straight line (or hyperplane in higher dimensions), even though the probability surface itself is a smooth S-shaped ramp, not a hard cutoff. This is the source of its main limitation: it cannot separate classes that require a curved or disjoint boundary without manual feature engineering (polynomial terms, interactions) or swapping to a nonlinear model.

Maximum Likelihood and the Cross-Entropy Loss

Unlike linear regression, there is no closed-form solution for the weights. Logistic regression is fit by maximum likelihood estimation: find the w, b that maximize the probability of the observed labels under the Bernoulli model p(y|x) = p̂ʸ(1−p̂)^(1−y). Taking the negative log-likelihood over the dataset gives the loss function actually minimized in practice — binary cross-entropy:

L(w,b) = −(1/n) Σᵢ [ yᵢ·log(p̂ᵢ) + (1−yᵢ)·log(1−p̂ᵢ) ]

Cross-entropy is convex in w, so gradient-based optimization is guaranteed to find the global minimum. Its gradient has an elegant closed form — ∇L = (1/n) Xᵀ(p̂ − y), identical in shape to linear regression's gradient with p̂ replacing the raw linear prediction — which is why the same SGD/mini-batch machinery from linear regression applies directly. In practice, solvers rarely use plain gradient descent: scikit-learn's LogisticRegression defaults to lbfgs (a quasi-Newton method using curvature information for fast convergence on small-to-medium data), with liblinear for small L1-penalized problems and saga for large sparse datasets or when you need both L1 and L2 penalties (elastic net).

Regularization, Perfect Separation, and Multiclass

When classes are linearly separable, cross-entropy has no finite minimum — the optimizer can always reduce loss further by pushing ‖w‖ → ∞, driving predicted probabilities to exactly 0 or 1. This "perfect separation" problem causes non-converging solvers and wildly unstable coefficients in small, clean datasets. The standard fix is the same one used everywhere else: L2 regularization (scikit-learn's default, controlled by C — the inverse of regularization strength, so smaller C means stronger regularization) caps ‖w‖ and restores a finite, stable optimum; this is the direct classification analogue of Ridge regression. For multiclass problems, logistic regression generalizes via softmax regression (multinomial logistic regression): the sigmoid becomes softmax(z)ₖ = e^zₖ / Σⱼe^zⱼ across K classes, and cross-entropy generalizes to the sum over all classes — this is exactly the final layer of virtually every neural net classifier, making logistic regression the "single-layer" special case of a deep classifier.

Production Reality

Logistic regression remains the default first baseline for tabular binary classification (fraud, churn, credit risk) because it's fast to train (O(nd) per iteration), gives calibrated-ish probabilities out of the box, and is directly interpretable via odds ratios — a property gradient-boosted trees and neural nets sacrifice. Use sklearn.linear_model.LogisticRegression for prediction pipelines; use statsmodels.Logit when you need p-values, confidence intervals, and Wald/LR tests for feature significance in an explanatory (not just predictive) setting. Its raw output probabilities are not automatically well-calibrated under class imbalance or model misspecification — check with a reliability diagram and apply Platt scaling or isotonic regression (CalibratedClassifierCV) if downstream decisions depend on probability magnitudes, not just rank order. For imbalanced classes, prefer class_weight="balanced" or threshold tuning over naive resampling, and always standardize features before fitting — unlike OLS's normal equation, gradient-based solvers converge far faster (and L2 penalizes coefficients fairly) when features share a common scale. Finally, remember logistic regression assumes independent observations and a linear log-odds relationship — violated in longitudinal/panel data (use GEE or mixed-effects logit) or when true decision boundaries are curved (add interaction/polynomial terms, or move to trees/GBMs).

Key Takeaways

  • Logistic regression is linear in log-odds, not in probability. The probability surface is a smooth sigmoid ramp, but the decision boundary — where p = 0.5 — is exactly the hyperplane w·x + b = 0. It can never carve out a curved or disjoint region without engineered polynomial/interaction features.
  • Perfectly separable data breaks unregularized MLE. Cross-entropy has no finite minimum when a hyperplane perfectly separates the classes — the optimizer pushes ‖w‖ → ∞ and solvers fail to converge. L2 regularization (scikit-learn's C parameter, smaller = stronger) is not optional polish here; it's what makes the fit well-posed at all.
  • Coefficients are odds ratios, not probability shifts. A coefficient of 0.69 means each unit increase in that feature roughly doubles the odds (e^0.69 ≈ 2) — a nonlinear, multiplicative effect on probability that's easy to misstate in a stakeholder readout.
  • Predicted probabilities aren't automatically calibrated under class imbalance or model misspecification, even though the loss function is a proper scoring rule. Check a reliability diagram before trusting predict_proba for anything beyond ranking — apply Platt scaling or CalibratedClassifierCV if downstream logic uses the probability value itself (e.g. expected-value thresholds).
  • solvers matter: lbfgs (default) is fast and accurate for small/medium dense data; liblinear handles small L1 problems well; saga is the only solver supporting elastic-net and scales to large sparse data (bag-of-words text). Picking the wrong solver for the data size/penalty combination silently degrades convergence, not just speed.
  • It's the linear special case of every softmax classifier head. Multinomial logistic regression's softmax + cross-entropy is exactly the final layer of a deep neural net classifier — understanding logistic regression's optimization surface is understanding the last mile of every classification network you'll ever train.
