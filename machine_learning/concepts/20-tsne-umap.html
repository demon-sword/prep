20t-SNE & UMAP

Nonlinear dimensionality reduction for visualization — how t-SNE/UMAP preserve local neighborhood structure and why global distances aren't meaningful.

Theory

The Problem PCA Can't Solve

PCA finds the linear subspace that maximizes variance, but many real datasets don't live on a linear subspace — they live on a curved, low-dimensional manifold embedded in high-dimensional space (imagine a Swiss roll, or the manifold of natural face images). A linear projection of such data crushes the manifold flat, mixing points that were actually far apart along the manifold's surface. t-SNE (t-distributed Stochastic Neighbor Embedding, van der Maaten & Hinton, 2008) and UMAP (Uniform Manifold Approximation and Projection, McInnes et al., 2018) instead optimize directly for one goal: if two points are close together in high-dimensional space, keep them close in the 2D/3D embedding. They deliberately sacrifice global structure (relative distances between distant clusters) to nail local structure (which points are each other's neighbors) — which is exactly why they've become the default for visualizing embeddings, single-cell genomics clusters, and learned representations.

How t-SNE Actually Works

t-SNE converts high-dimensional Euclidean distances into conditional probabilities that represent similarity: p(j|i) ∝ exp(−‖xᵢ−xⱼ‖² / 2σᵢ²), a Gaussian centered on each point i. Each point gets its own bandwidth σᵢ, chosen by binary search so the resulting distribution's entropy matches log(perplexity) — perplexity is a smooth stand-in for "effective number of neighbors" (typical range 5–50; scikit-learn defaults to 30). These conditionals are symmetrized into a joint distribution P. In the low-dimensional embedding, t-SNE defines a similar joint distribution Q, but crucially uses a Student-t distribution with 1 degree of freedom (i.e. a Cauchy) instead of a Gaussian: q(i,j) ∝ (1+‖yᵢ−yⱼ‖²)⁻¹. This heavier tail is the "t" in t-SNE and is the fix for the crowding problem — in high dimensions there's exponentially more room for moderately-distant points than in 2D, so a Gaussian in the low-dim space would force too many points into a tiny central blob; the heavy Cauchy tail lets moderately dissimilar points spread further apart in the embedding. Optimization minimizes the KL divergence KL(P‖Q) = Σ p(i,j) log(p(i,j)/q(i,j)) via gradient descent with momentum, typically run with early exaggeration (multiplying P by ~4–12× for the first ~250 iterations) to force tight, well-separated clusters to form early before fine-tuning relative positions.

UMAP — Same Spirit, Different Math

UMAP is grounded in topological data analysis rather than information theory. It builds a weighted k-nearest-neighbor graph in high-dimensional space (a “fuzzy simplicial set”), then optimizes a low-dimensional layout via force-directed graph layout (attractive forces between true neighbors, repulsive forces between random negative samples) using stochastic gradient descent — closer in spirit to node2vec-style embedding than to t-SNE's probability matching. Concretely, for each point i it computes ρᵢ = the distance to its nearest non-identical neighbor, then binary-searches a bandwidth σᵢ so that Σⱼ exp(−max(0, d(i,j) − ρᵢ) / σᵢ) = log₂(k). The ρᵢ subtraction is what makes the construction “locally connected” — every point is guaranteed at least one edge of full membership 1.0, so no point is ever left stranded regardless of how sparse its region is. The resulting directed memberships w(i,j) are symmetrized with the probabilistic t-conorm W = w + wᵀ − w∘wᵀ (“i thinks j is a neighbor or j thinks i is”), which is the fuzzy-set union — not t-SNE's arithmetic average. Practically, UMAP tends to run 5–10× faster than t-SNE at scale, supports true out-of-sample transform (umap.transform() on new points — t-SNE has no principled way to embed new points without recomputing), and preserves more of the global structure (relative cluster distances are somewhat more meaningful, though still not to be over-trusted).

UMAP's Two Headline Hyperparameters: n_neighbors and min_dist

n_neighbors (default 15) is the high-dimensional knob and UMAP's rough analogue of t-SNE's perplexity — it sets k in the kNN graph, i.e. how much of the manifold each point is allowed to “see.” Small values (5–10) emphasize very local structure and produce more, tighter fragments; large values (50–200) pull toward a more globally coherent but less locally precise picture. It is analogous to but not the same as perplexity: perplexity targets a Shannon entropy of a normalized probability distribution over all points, while n_neighbors is a hard truncation of the graph plus a log₂(k) membership-mass target over exactly those k edges.

min_dist (default 0.1, range 0.0–0.99) is the low-dimensional knob and has no t-SNE equivalent at all. It is the minimum separation UMAP is willing to enforce between points in the embedding — effectively how tightly it is allowed to pack them on the page. Small values (0.0–0.1) let points clump on top of each other, producing dense, sharply-delineated blobs that emphasize fine local and cluster structure — this is what you want when the question is “how many clusters are there and where are their boundaries?” Large values (0.5–0.99) force points apart, producing an even, spread-out layout that preserves broader topological relationships and relative arrangement at the cost of tight, visually obvious cluster definition — better when the question is “what is the overall shape of this manifold?” It is purely cosmetic-sounding but genuinely changes the objective; it does not touch the kNN graph at all.

The mechanism is indirect and worth knowing for interviews: min_dist enters the algorithm only through the fitted parameters a and b of the low-dimensional kernel

q(yᵢ, yⱼ) = 1 / (1 + a · ‖yᵢ − yⱼ‖2b)

Before optimization even starts, UMAP does a least-squares curve fit of that kernel against a target “desired” curve ψ(d) = 1 for d ≤ min_dist and exp(−(d − min_dist) / spread) otherwise. So min_dist reshapes the plateau of the similarity curve: a small min_dist yields a peakier kernel (large a) that keeps rewarding attraction all the way down to zero distance, while a large min_dist yields a flat-topped kernel that gives no further reward for closing the last bit of gap — so the repulsive term wins there and points settle apart. Note (a, b) = (1, 1) recovers exactly the Student-t/Cauchy kernel t-SNE uses; UMAP's default min_dist=0.1, spread=1.0 fits to roughly a ≈ 1.577, b ≈ 0.895.

Interview trap: “My UMAP clusters are too smeared together, should I lower n_neighbors?” — Not necessarily. If you want visually tighter blobs, lower min_dist; that is a pure layout change and leaves the underlying topology estimate untouched. Lowering n_neighbors changes which points UMAP believes are neighbors at all, and can genuinely fragment one true cluster into several fake ones. Knowing which of the two knobs changes the model versus the rendering is the point of the question.

The Cardinal Interpretation Rule

Both methods are nonlinear and non-convex — the optimization has many local minima, so re-running with a different random seed gives a visually different layout, and this is normal, not a bug. The rules every practitioner must internalize: (1) cluster sizes in the plot mean nothing — t-SNE roughly equalizes the density it displays; a tight, tiny-looking cluster and a loose, sprawling one may represent the same true within-cluster variance. (2) Distances between clusters are not reliable — two clusters that appear far apart may not be more "different" than two that appear close; only the neighbor structure within a local neighborhood is trustworthy. (3) Perplexity/n_neighbors materially changes the picture — always try multiple values (e.g. 5, 30, 50) before drawing conclusions, and never present a single seed/perplexity run as ground truth.

Production Reality

Naive t-SNE is O(n²) in both distance computation and the gradient (every point interacts with every other point each iteration), which is infeasible past a few thousand points; Barnes-Hut t-SNE (scikit-learn's default, method='barnes_hut') approximates distant repulsive forces via a quadtree, bringing this down to O(n log n) and making 10⁴–10⁵ points tractable; for larger corpora, openTSNE or FIt-SNE use FFT-based approximation to reach millions of points. The standard production recipe is: run PCA down to ~50 dimensions first (denoises and speeds up neighbor search dramatically — this is scikit-learn's init='pca' default as of 1.2+, replacing the old random init, and gives more stable, reproducible layouts run to run) then t-SNE or UMAP for the final 2D/3D projection. UMAP (via the umap-learn library) has increasingly displaced t-SNE as the default because of its speed and support for new-data transform, but for pure visualization quality on well-separated clusters both remain roughly comparable. Critically: never feed t-SNE/UMAP output into a downstream supervised model as features — the embedding optimizes for 2D visual neighbor-preservation, not for a metric that generalizes to new points or preserves task-relevant variance; for feature engineering pipelines, use UMAP's genuine transform() (fit on train, applied to test) or stick to PCA/autoencoders.

Key Takeaways

  • t-SNE optimizes local neighbor preservation, not global geometry — inter-cluster distances and cluster sizes in the plot are not meaningful. A common interview trap is asking "which clusters in this t-SNE plot are most similar?" — the honest answer is you can't tell from the plot; only within-neighborhood relationships are preserved by the objective function.
  • The Student-t (Cauchy) tail in the low-dim space is the whole trick, not an implementation detail. It exists specifically to solve the crowding problem: high-dimensional space has exponentially more volume at moderate distances than 2D does, so a symmetric Gaussian kernel in both spaces would force too many points into an unusably dense center — the heavy tail lets moderately-different points spread out.
  • Perplexity (t-SNE) / n_neighbors (UMAP) is the single most consequential hyperparameter, and there's no universal default. scikit-learn's TSNE defaults to perplexity=30, umap-learn defaults to n_neighbors=15 — always sweep 3–4 values (e.g. 5, 15, 30, 50) before trusting a single layout, since low values fragment structure and high values blur it.
  • UMAP has a second headline knob t-SNE has no equivalent for: min_dist (default 0.1), the minimum separation it enforces between embedded points. Low values (0.0–0.1) pack points tightly and sharpen fine local/cluster structure; high values (0.5–0.99) spread them out and preserve broader topological relationships at the cost of crisp cluster boundaries. Crucially it enters the algorithm only through the least-squares-fitted a, b of the low-dim kernel 1/(1 + a·d^{2b}) — it never touches the kNN graph, so it changes the rendering, not the topology estimate. n_neighbors changes the model; min_dist changes the picture.
  • Always PCA down to ~50 dims before t-SNE/UMAP on high-dimensional data (images, embeddings). It denoises, speeds up neighbor search by an order of magnitude, and — since scikit-learn 1.2 — is the default init='pca' initialization, which also makes runs far more reproducible than the old random init.
  • Naive t-SNE is O(n²); Barnes-Hut brings it to O(n log n) and is scikit-learn's default beyond ~1,000 points. For 10⁵–10⁶+ points, reach for openTSNE/FIt-SNE or switch to UMAP outright — UMAP is typically 5–10× faster at the same scale and, unlike t-SNE, supports genuine .transform() on unseen points via its learned fuzzy-simplicial-set model.
  • Never pipe t-SNE/UMAP coordinates into a downstream supervised model as features. The embedding is optimized for 2D visual neighbor fidelity on the exact points fitted, not for a generalizable metric space; for a genuine reusable dimensionality-reduction feature pipeline, use PCA, an autoencoder, or UMAP's real transform() (fit on train, applied to held-out data) instead.
