28Backpropagation

The chain rule applied layer by layer to compute gradients — forward pass caching activations, backward pass propagating error signals to update weights.

Theory

The Chain Rule, Applied Layer by Layer

A neural network is a composition of functions: ŷ = f_L(f_{L-1}(…f_1(x))). Training means minimizing a loss L(ŷ, y) over the weights of every layer, which requires ∂L/∂W for every weight matrix in the network. Backpropagation is not a separate learning algorithm — it's the mechanical application of the multivariate chain rule to compute all of those partial derivatives in a single backward sweep, reusing intermediate results instead of recomputing them from scratch for every weight. For a layer computing z = Wa + b followed by a nonlinearity a' = σ(z), the chain rule says the gradient flowing into that layer from upstream, δ = ∂L/∂a', gets converted into the gradient with respect to that layer's own parameters as ∂L/∂W = (δ ⊙ σ'(z)) · aᵀ and passed further backward as ∂L/∂a = Wᵀ(δ ⊙ σ'(z)). Every layer performs exactly this same local computation — multiply the incoming error signal by the local derivative, then by the transpose of the weight matrix — which is why backprop generalizes to arbitrarily deep and arbitrarily shaped computational graphs without any layer needing global knowledge of the network.

Forward Pass: Caching What Backward Needs

Every layer's forward computation caches its inputs and pre-activation values (z) because the backward pass needs them to evaluate local derivatives like σ'(z) and to compute ∂L/∂W = δ · aᵀ using the *previous* layer's activation a. This is the memory cost of training that inference doesn't pay: a forward-only pass can discard activations as soon as the next layer consumes them, but training must hold every layer's activations in memory until the corresponding backward step runs. For a batch size B and total activation memory M per example, training memory scales roughly as O(B · M · L) across L layers — this is precisely the bottleneck that motivates gradient checkpointing (recomputing activations during the backward pass instead of storing all of them, trading ~30% more compute for a large memory reduction) used in training large transformers.

Backward Pass: Propagating the Error Signal

The backward pass starts at the loss and works right-to-left: δ_L = ∂L/∂ŷ at the output layer, then each earlier layer's δ is derived from the next layer's δ via δ_{k} = (W_{k+1}ᵀ δ_{k+1}) ⊙ σ'(z_k). Each weight's gradient is a local outer product, ∂L/∂W_k = δ_k · a_{k-1}ᵀ, computed once δ_k is known — no weight's gradient needs information from any layer other than its own input activation and its own δ. This is what makes backprop O(1) passes, not O(number of weights): naively perturbing each weight and re-running the forward pass (numerical differentiation) costs one forward pass *per parameter*, which is intractable for a network with billions of weights, whereas backprop computes the gradient for every parameter in roughly the same cost as two forward passes (one forward, one backward), regardless of parameter count.

Reverse-Mode Autodiff, Not Symbolic or Numerical Differentiation

Backpropagation is a special case of reverse-mode automatic differentiation applied to a computational graph. Reverse mode is efficient specifically when there are many inputs (parameters) and few outputs (a scalar loss) — the opposite regime favors forward-mode AD, which is why forward mode is rare in deep learning but common in physics simulations with few parameters and many outputs. Modern frameworks build this graph dynamically: PyTorch's autograd records every tensor operation on a directed acyclic graph as the forward pass executes (define-by-run), then loss.backward() walks that graph in reverse topological order, accumulating gradients into .grad on every leaf tensor with requires_grad=True. TensorFlow's tf.GradientTape does the same thing explicitly, recording operations only within the tape's context. Neither framework requires you to hand-derive a single gradient formula — every built-in op (matmul, conv, softmax, layer norm) ships a registered backward rule, and the chain rule composes them automatically.

Production Reality

Backprop's compounding of derivatives across many layers is the root cause of vanishing/exploding gradients — repeatedly multiplying by σ'(z) and Wᵀ shrinks or blows up the signal exponentially with depth if those factors are systematically <1 or >1 (see Weight Init & Vanishing Gradients). Production training pipelines defend against this with gradient clipping (torch.nn.utils.clip_grad_norm_, typically capping the global norm at 1.0–5.0) to stop exploding gradients from corrupting a step, and rely on residual connections, LayerNorm, and careful initialization to keep the vanishing side in check. Mixed-precision training (FP16/BF16 forward and backward with an FP32 master copy of weights) roughly halves activation memory and speeds up matmuls on tensor cores, but naive FP16 backward passes can underflow small gradients to zero — hence loss scaling in torch.cuda.amp. And because backward passes dominate training FLOPs (roughly 2× the forward pass cost), profiling tools like PyTorch Profiler almost always show the backward pass, not the forward pass, as the larger share of per-step wall-clock time.

Key Takeaways

  • Backprop computes gradients for every parameter in ~2× the cost of one forward pass, regardless of parameter count — this is the entire reason training billion-parameter networks is tractable at all; naive numerical differentiation (perturb-and-re-run) would need one forward pass per weight.
  • It's reverse-mode automatic differentiation, not symbolic or numerical differentiation — PyTorch's autograd and TF's GradientTape record a computational graph during the forward pass and walk it backward, composing each op's registered local gradient rule via the chain rule; you never hand-derive a gradient formula.
  • Training memory is dominated by cached forward activations, not weights — every layer must hold its input/pre-activation values until its backward step runs. Gradient checkpointing (torch.utils.checkpoint) trades ~30% more compute (recomputing activations on the fly) for a large memory cut, standard practice for training large transformers on limited GPU memory.
  • Backward pass FLOPs ≈ 2× forward pass FLOPs — profilers almost always show backward as the larger chunk of per-step wall-clock time; budget compute estimates accordingly (the common "6 × params × tokens" training-FLOPs rule of thumb bakes in roughly a 1:2 forward:backward ratio).
  • Repeated multiplication by σ'(z) and Wᵀ across layers is the root cause of vanishing/exploding gradients — production defenses are gradient clipping (clip_grad_norm_, typically 1.0–5.0), residual/skip connections, and normalization layers, not a fix to backprop itself.
  • Mixed-precision (FP16/BF16) backward passes can silently underflow small gradients to zero — torch.cuda.amp's loss scaling multiplies the loss before backward and unscales gradients after, specifically to keep small gradient values representable in FP16's narrow exponent range.
