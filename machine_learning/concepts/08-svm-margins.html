Supervised Learning

08SVM & Maximum Margin

Maximum margin classifiers, support vectors, the kernel trick, and the C/gamma hyperparameters that control the margin-violation tradeoff.

Theory

Maximum Margin and the Primal Problem

A Support Vector Machine finds the hyperplane w·x + b = 0 that separates two classes while maximizing the margin — the distance from the hyperplane to the nearest point of either class. Unlike logistic regression, which finds any separating hyperplane that maximizes likelihood, SVM explicitly optimizes for the hyperplane with the most breathing room on both sides, which turns out to minimize generalization error under a margin-based bound (Vapnik's statistical learning theory). For linearly separable data, the margin width is 2/‖w‖, so maximizing margin is equivalent to minimizing ‖w‖ subject to every point satisfying yᵢ(w·xᵢ + b) ≥ 1. The points that sit exactly on this constraint boundary — where the inequality is tight — are the support vectors: the only points that determine the hyperplane. Every other point could be deleted or moved (as long as it stays outside the margin) without changing the solution at all, which is the core reason SVM gives a sparse, robust-to-outliers-in-the-interior decision function.

min (1/2)‖w‖²   s.t.   yᵢ(w·xᵢ + b) ≥ 1  ∀i   (hard margin)

Soft Margin, Hinge Loss, and C

Real data is rarely perfectly separable, so the soft-margin SVM introduces slack variables ξᵢ ≥ 0 that allow points to violate the margin at a cost, controlled by the hyperparameter C:

min (1/2)‖w‖² + C·Σᵢξᵢ   s.t.   yᵢ(w·xᵢ+b) ≥ 1−ξᵢ, ξᵢ ≥ 0

This is equivalent to unconstrained minimization of the hinge loss plus an L2 penalty: min (1/n)Σᵢ max(0, 1 − yᵢ(w·xᵢ+b)) + λ‖w‖², where λ ∝ 1/C. Hinge loss is zero once a point is correctly classified with margin ≥ 1 — it stops caring about points that are already comfortably correct, unlike cross-entropy which keeps pushing probabilities toward 0/1 forever. C is the single most important SVM hyperparameter: small C tolerates more margin violations, giving a wider margin and stronger regularization (higher bias, lower variance); large C penalizes violations heavily, giving a narrow margin that hugs the training data (lower bias, higher variance, risk of overfitting to noisy points near the boundary).

The Dual Problem, Support Vectors, and the Kernel Trick

SVMs are almost always solved in their dual form, derived via Lagrangian duality. The dual replaces w with a weighted sum of training points, w = Σᵢ αᵢyᵢxᵢ, where each αᵢ ∈ [0, C] is a Lagrange multiplier satisfying the KKT conditions. Points with αᵢ = 0 are outside the margin and contribute nothing (most of the dataset, in practice); points with 0 < αᵢ < C sit exactly on the margin boundary (free/unbound support vectors); points with αᵢ = C violate the margin — either inside it or misclassified (bound support vectors). Crucially, the dual objective and the decision function f(x) = Σᵢ αᵢyᵢ(xᵢ·x) + b depend on data only through dot products. This is what enables the kernel trick: replace xᵢ·xⱼ everywhere with a kernel function K(xᵢ,xⱼ) that computes the dot product in some (possibly infinite-dimensional) feature space without ever materializing that space. The RBF kernel K(x,x′) = exp(−γ‖x−x′‖²) corresponds to an infinite-dimensional feature map and lets SVM draw arbitrarily curved decision boundaries; the polynomial kernel K(x,x′) = (γx·x′+r)^d captures interaction terms up to degree d without explicitly constructing them. gamma controls how far a single training point's influence reaches — high gamma means each point only affects its immediate neighborhood (tight, wiggly boundary, overfitting risk); low gamma means influence extends far (smooth boundary, underfitting risk). Any valid kernel just needs to satisfy Mercer's condition (the kernel matrix must be positive semi-definite).

Production Reality

Training a kernel SVM (sklearn.svm.SVC) requires storing and optimizing over the full n×n kernel matrix — training scales roughly O(n²) to O(n³), making it impractical past a few tens of thousands of rows. For large or high-dimensional (especially sparse, e.g. bag-of-words text) data, use sklearn.svm.LinearSVC, which solves the primal directly via liblinear's coordinate descent and scales roughly linearly in n — or SGDClassifier(loss="hinge") for truly large-scale streaming data. Feature scaling is not optional: because the margin and every kernel (RBF, polynomial) depend directly on Euclidean distances or dot products, unscaled features (e.g. income in dollars vs. age in years) will dominate the margin computation — always fit on StandardScaler-transformed features. SVM's raw decision function is a signed distance, not a probability; scikit-learn's probability=True fits a separate Platt-scaling logistic regression via 5-fold internal cross-validation, which is expensive and can produce probabilities that are slightly inconsistent with the hard predict() boundary — enable it only if you truly need calibrated scores. Class imbalance is handled the same way as logistic regression, via class_weight="balanced", which reweights the per-class contribution to the hinge-loss sum. Multiclass is handled via one-vs-rest or one-vs-one (scikit-learn defaults to one-vs-one for SVC, training K(K−1)/2 binary classifiers), since the margin formulation is inherently binary. In practice, gradient-boosted trees have displaced kernel SVMs for most tabular problems (better handling of mixed feature types, less sensitivity to scaling, faster training at scale), but SVM with RBF kernel remains a strong, well-calibrated-with-tuning baseline for small-to-medium, high-dimensional, cleanly-separable problems — and the max-margin / hinge-loss framing underlies modern contrastive and metric-learning losses used in deep embedding models.

Key Takeaways

  • Only support vectors matter for prediction. Every point with α = 0 (typically the majority of the dataset once training converges) could be deleted without changing the boundary at all — SVM's decision function is a sparse weighted sum over a small subset of the training set, which is why it generalizes well from limited data but also why adding more "easy" interior points doesn't improve the model.
  • C trades margin width for training fit — it is the primary regularization knob. sklearn.svm.SVC defaults to C=1.0; in practice, tune it on a log scale (0.01, 0.1, 1, 10, 100) via GridSearchCV jointly with gamma, since the two interact — a wide-margin/low-C model can look identical to a narrow-margin/high-C model at different gamma settings.
  • gamma='scale' is scikit-learn's default (1 / (n_features · X.var())), not a fixed constant — it auto-adapts to feature scale, but you still must standardize features first (StandardScaler) since RBF and polynomial kernels are computed directly from Euclidean distances and dot products.
  • Kernel SVM training is O(n²)–O(n³) due to the dense n×n kernel (Gram) matrix — past roughly 50k–100k rows, switch to LinearSVC (primal, liblinear, near-linear scaling) or SGDClassifier(loss="hinge"), both of which forgo the kernel trick and only support linear boundaries.
  • predict_proba is bolted on, not native. probability=True triggers an internal 5-fold Platt-scaling fit that multiplies training time and can yield probability estimates mildly inconsistent with the hard-margin predict() call — don't enable it unless you actually consume the probabilities downstream.
  • Hinge loss's "zero loss once correct with margin" property is exactly what modern contrastive/triplet losses in embedding models borrow — recognizing max-margin hinge loss in a research paper's loss function is a direct callback to this 1990s SVM formulation.
