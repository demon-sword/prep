45Vision Transformers & Registers

How ViTs turn images into patch tokens, why trained ViTs grow high-norm artifact tokens in background regions, and how Darcet et al.'s register tokens give the model dedicated scratch space.

Theory

From pixels to patch tokens

A Vision Transformer treats an image as a set of patches, not a grid. A 224×224 image cut into 16×16 patches yields 14×14 = 196 patch tokens; each patch is flattened and linearly projected to the model dimension, then summed with a learned (or sinusoidal) positional embedding. A learnable [CLS] token is prepended, and the whole sequence goes through a standard Transformer encoder. For the canonical ViT-Base that means: 196 + 1 tokens, 12 layers, 768 dimensions, ~86M parameters.

This set-based view is exactly what makes ViTs droppable and maskable — patches are independent tokens, so you can delete 75% of them and the architecture still works (the idea masked autoencoders exploit). A convolution cannot do that: it needs the dense grid. The price is the loss of built-in translation equivariance, which is why ViTs are hungrier for data and pre-training than CNNs at the same parameter count. See 29-cnn-convolution.html for the convolution side of that tradeoff.

The artifact finding (Darcet et al., ICLR 2024)

When the authors visualized the attention maps of large trained ViTs — particularly DINOv2 models — they found something odd: a small number of patch tokens with abnormally large feature norms sitting in semantically empty background regions (sky, flat walls, out-of-focus areas). These high-norm tokens attract disproportionate attention mass, producing spiky, noisy attention maps, and they degrade the quality of dense per-patch features used by segmentation and depth heads.

The proposed mechanism is simple and worth saying out loud in an interview: softmax attention must distribute its mass somewhere, and the model sometimes needs to park global or background information in a token it is not otherwise using. Low-information background patches become involuntary scratch space — the network repurposes them as memory slots, and their norms blow up as a side effect. It is the visual cousin of attention sinks in language models.

Registers: dedicated scratch space

The fix is architectural and tiny. Append R extra learnable tokens — registers — to the input sequence alongside the patches and [CLS]:

input = [ CLS, patch₁, …, patch₁₉₆, reg₁, …, regᵣ ]  →  encoder  →  drop registers before the head

Registers participate in every self-attention layer exactly like patch tokens, so they can absorb the parked global information the model was stuffing into background patches. They are discarded before the classification or dense head, so they cost nothing at output: a handful of extra tokens (the paper uses as few as 1 and typically 4) adds a negligible number of parameters and a small attention overhead. After retraining with registers, the high-norm outliers disappear from the patch tokens, attention maps become smooth and object-aligned, and dense-prediction performance improves because every patch token once again carries local information.

Without registers

Background patches double as memory slots → a few tokens develop huge norms → attention maps show spurious spikes on empty regions → per-patch features are polluted for downstream dense tasks.

With registers

Parked information flows into dedicated register tokens → patch norms stay uniform → attention concentrates on the object → register activations (visible in the viz below) confirm they absorbed the artifact mass.

What registers are — and are not

Registers are best described as emergent global working memory: unlike [CLS], which is supervised toward a classification target, registers receive no direct supervision and are free to store whatever the network finds useful. That freedom is the point. They are not prompts, not adapters, and not extra capacity in the usual sense — adding the same parameters as wider patches does not reproduce the effect; the effect comes from giving the attention mechanism addressable slots with no local meaning attached.

Two practical notes. First, registers require training (or fine-tuning) with the tokens present — but later work showed even test-time registers appended to a frozen model absorb the outliers comparably, so existing checkpoints can be patched without a full retrain. Second, registers matter most where per-patch feature quality matters: dense prediction, probing, and any pipeline that reads attention maps as explanations. For pure image-level classification the gain is small, which is exactly what you would expect from a fix to spatial feature hygiene.

import torch.nn as nn

class ViTWithRegisters(nn.Module):
    def __init__(self, encoder, dim, num_registers=4):
        super().__init__()
        self.encoder = encoder
        # R extra learnable tokens; no supervision target of their own
        self.registers = nn.Parameter(torch.randn(1, num_registers, dim) * 0.02)

    def forward(self, patches, cls):
        B = patches.shape[0]
        regs = self.registers.expand(B, -1, -1)
        # Append scratch slots, encode, then discard before the head
        seq = torch.cat([cls, patches, regs], dim=1)
        out = self.encoder(seq)
        return out[:, :1 + patches.shape[1]]  # keep CLS + patches only

The interview line

Large ViTs spontaneously turn a few background patches into high-norm memory slots because softmax attention has to park information somewhere — Darcet et al. showed that appending a few learnable register tokens, discarded at the output, absorbs that parked mass, smooths the attention maps, and restores per-patch feature quality for dense tasks.

Key Takeaways

  • Patchify-then-attend is what makes ViTs maskable and droppable where CNNs need dense grids — but it also means every token is addressable memory, including background patches the model never meant to use that way.
  • High-norm artifact tokens are an emergent property of training, not a bug in any one checkpoint: DINOv2 ViTs across sizes park global information in low-information patches, visible as attention spikes on empty regions (Darcet et al., ICLR 2024).
  • Registers work because they are unsupervised scratch slots, not because they add capacity: 1–4 extra tokens in timm or Hugging Face transformers ViT variants remove the outliers, while widening patches by the same parameter count does not.
  • Read per-patch features with suspicion on register-less models: run a norm histogram over patch tokens in PyTorch before trusting attention maps or linear probes — a heavy right tail means your "explanations" may be pointing at sky.
  • Dense tasks gain, classification barely moves: budget register retraining (or test-time registers on a frozen DINOv2 backbone) for segmentation, depth, and detection pipelines, and verify with a frozen-feature linear probe in scikit-learn rather than end-to-end fine-tuning alone.
