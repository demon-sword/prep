Ensembles

12Bagging vs Boosting

Bootstrap aggregating (variance reduction via parallel models) vs boosting (bias reduction via sequential residual fitting) — the two ensemble philosophies.

Theory

Two Different Diseases, Two Different Cures

A single model's generalization error decomposes into bias, variance, and irreducible noise (see 01-bias-variance-tradeoff). Bagging and boosting are the two dominant ensemble strategies, and each one targets a different half of that decomposition. Bagging (bootstrap aggregating) is a variance-reduction technique: it trains many independent copies of a high-variance, low-bias base learner (classically an unpruned decision tree) on different random resamples of the training data, then averages their predictions. Boosting is a bias-reduction technique: it trains a sequence of high-bias, low-variance base learners (classically shallow trees or stumps) where each new learner is explicitly fit to correct the errors left behind by the ensemble built so far. Picking the wrong tool for the wrong problem — e.g. bagging a set of already-underfit stumps — barely moves the needle, because bagging can't fix bias, only variance.

Bagging: Parallel and Independent

Given a training set of size n, bagging draws B bootstrap samples — each of size n, sampled with replacement — and fits one base learner per sample. The final prediction is the average (regression) or majority vote (classification) of all B models: f̂(x) = (1/B) Σ f_b(x). Because each bootstrap sample omits roughly (1 - 1/n)ⁿ ≈ 1/e ≈ 36.8% of the original rows on average, every tree has a free, never-seen-during-training validation set — this is exactly the out-of-bag (OOB) error that scikit-learn exposes via oob_score=True, giving a nearly free generalization estimate without a separate holdout split or cross-validation loop.

The variance-reduction math matters for interview depth: if the B base learners were truly independent with variance σ², averaging would cut variance to σ²/B. But trees trained on overlapping bootstrap samples of the same data are correlated with pairwise correlation ρ, so the actual variance of the average is ρσ² + (1-ρ)σ²/B — as B → ∞ the second term vanishes but the ρσ² floor remains. This is precisely the gap that 13-random-forest closes: by also randomly subsampling features at each split, Random Forest actively decorrelates the trees (lowers ρ), squeezing variance further than bagging alone ever could.

Boosting: Sequential and Additive

Boosting builds an additive model one weak learner at a time: F_m(x) = F_{m-1}(x) + ν · h_m(x), where h_m is a new base learner and ν (the learning rate / shrinkage) scales its contribution. The historical first version, AdaBoost, reweights misclassified training examples upward before each round so the next weak learner focuses harder on the hard cases. The modern, more general formulation is Gradient Boosting (Friedman, 2001): at each round, fit h_m to the negative gradient of the loss function with respect to the current predictions — for squared-error regression this negative gradient is exactly the residual r_i = y_i - F_{m-1}(x_i), so gradient boosting for regression reduces to "repeatedly fit a small tree to whatever the ensemble still gets wrong." This framing generalizes to any differentiable loss (log-loss for classification, quantile loss, Huber loss, ranking losses), which is why XGBoost, LightGBM, and CatBoost can all optimize custom objectives.

Bias/Variance, Overfitting, and Parallelism

Because bagging averages unbiased-but-noisy estimators, adding more trees essentially never hurts — test error typically flattens out and stays flat as B grows (it costs compute, not accuracy), which is why Random Forest's n_estimators is comparatively forgiving to over-set. Boosting behaves the opposite way: since every round chases the training residual harder, enough rounds without shrinkage will eventually memorize noise — training loss keeps falling but validation loss turns upward. In production this is controlled with a small learning rate (XGBoost's default eta/learning_rate is 0.3, but tuned models typically land at 0.01–0.1 with proportionally more trees) plus early_stopping_rounds monitored against a validation set. Bagging's trees are trained completely independently, so n_jobs=-1 parallelizes trivially across cores/machines; boosting's rounds are inherently sequential (round m needs the residuals from round m-1), so XGBoost/LightGBM instead parallelize within each tree's split search (histogram-binned feature buckets, GPU histogram construction) rather than across trees.

Production Reality

On tabular data with a fixed compute budget, gradient boosting (XGBoost, LightGBM, CatBoost) usually beats Random Forest by a meaningful margin — it's the dominant family on Kaggle tabular leaderboards precisely because bias reduction from adaptively targeting hard examples tends to buy more accuracy than variance reduction from passive averaging. The tradeoff: boosting is noticeably more sensitive to label noise and outliers (a mislabeled row generates a persistent residual that later rounds keep "fixing," overfitting to the noise) and needs more careful hyperparameter tuning (learning rate, tree depth, number of rounds, regularization terms) to avoid overfitting, whereas Random Forest with near-default settings (max_features='sqrt', deep trees, n_estimators=200–500) is close to a robust, tuning-free baseline. Bagging-family models (Random Forest, Extra Trees, BaggingClassifier) are the safer first move when interpretability of variance and quick iteration matter; boosting-family models are the move when squeezing out the last few points of leaderboard accuracy matters and you have the time budget to tune and validate carefully against overfitting.

Key Takeaways

  • Match the ensemble strategy to the base learner's failure mode. Bagging only helps when the base learner is high-variance/low-bias (deep unpruned trees) — bagging a set of already-underfit stumps barely improves accuracy because averaging can't remove bias. Boosting is built for the opposite case: high-bias/low-variance learners (shallow trees, stumps) that individually underfit but collectively approximate a complex function through additive correction.
  • OOB error is a nearly-free validation signal unique to bagging. Since each bootstrap sample excludes ~36.8% of rows, scikit-learn's RandomForestClassifier(oob_score=True) gives a generalization estimate without a separate CV loop — useful for quick iteration, though a proper held-out test set is still worth keeping for the final reported number.
  • Bagging is embarrassingly parallel; boosting is inherently sequential. n_jobs=-1 trains bagged trees across all cores simultaneously with no coordination needed. Gradient boosting libraries can't parallelize across rounds (round m needs round m-1's residuals) — XGBoost/LightGBM instead parallelize the split-search within each tree via histogram binning, which is why GPU acceleration helps GBMs more than it helps Random Forest.
  • More trees rarely hurts bagging; more rounds can badly hurt boosting. Random Forest's test error plateaus as n_estimators grows — you're spending compute, not risking overfit. Boosting without early stopping keeps chasing training residuals indefinitely; production XGBoost/LightGBM pipelines almost always pair a small learning_rate (commonly 0.01–0.1, vs XGBoost's default eta=0.3) with early_stopping_rounds against a validation set.
  • Boosting is far more sensitive to label noise and outliers than bagging. A single mislabeled row generates a persistent residual that subsequent rounds keep trying to "fix," effectively overfitting to the noise. If your labels are noisy (weak/crowd-sourced labels, imperfect heuristics), Random Forest or Extra Trees is often the safer default; if labels are clean and you have tuning budget, gradient boosting usually wins on tabular leaderboards.
  • Reach for 13-random-forest when bagging alone plateaus. Plain bagged trees stay correlated (ρ) because every bootstrap sample is drawn from the same feature set — Random Forest's random feature subsampling at each split (max_features='sqrt' for classification, max_features=1.0/all features for regression by default in scikit-learn) actively decorrelates the trees, squeezing variance further than BaggingClassifier alone.
