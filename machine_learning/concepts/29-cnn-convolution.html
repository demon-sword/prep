29CNNs & Convolution

Convolutional filters sliding over input, stride, padding, and pooling — how CNNs build translation-invariant hierarchical feature detectors.

Theory

The Convolution Operation

A convolutional layer slides a small learnable filter (a "kernel", typically 3×3 or 5×5) across the spatial extent of its input and, at every position, computes the elementwise product between the kernel weights and the local patch of input underneath it, then sums the products into a single scalar. Repeating this at every valid position produces a 2D feature map. Strictly, what deep learning frameworks call "convolution" is technically cross-correlation (no kernel-flipping) — the distinction is mathematically real but irrelevant in practice because the kernel weights are learned anyway, so a flipped or unflipped kernel converges to an equivalent solution. With multiple input channels (e.g. RGB, or the output channels of a previous layer), the kernel itself is a 3D tensor — K × K × C_in — and the dot product sums over all channels at each spatial position, so one filter always produces one 2D output map regardless of how many input channels it reads. A layer typically learns dozens to hundreds of such filters in parallel, stacking their outputs into a C_out-channel feature volume.

Why Convolution Beats Fully-Connected Layers on Images

Convolution encodes two structural priors that make it dramatically more parameter-efficient than a dense layer on image data: local connectivity (each output depends only on a small spatial neighborhood, not the entire image) and weight sharing (the same kernel weights are reused at every spatial position, instead of learning a separate weight for every pixel-to-output connection). A 224×224×3 image fed into a fully-connected layer with 4096 outputs needs 224·224·3·4096 ≈ 617M weights for that single layer. A 3×3 convolution with 64 output channels reading the same 3-channel input needs only 3·3·3·64 = 1,728 weights (plus 64 biases) — regardless of the input's spatial resolution. This parameter sharing is also what gives CNNs approximate translation invariance: a filter that has learned to detect a vertical edge fires on that edge wherever it appears in the image, because the identical weights are applied everywhere.

Stride, Padding, and Output Size

Stride S controls how many pixels the kernel moves between applications — stride 1 produces a densely overlapping feature map, stride 2 halves both spatial dimensions and is a common cheap alternative to pooling for downsampling. Padding P (typically zero-padding) controls what happens at the border: "valid" padding (P=0) shrinks the output every layer, while "same" padding adds just enough border so a stride-1 convolution preserves spatial size. The general formula for one spatial dimension is:

output_size = floor((input_size + 2·P − kernel_size) / stride) + 1

Stacking two 3×3 convolutions gives an effective receptive field of 5×5 (each output of the second layer sees a 3×3 window of the first layer's outputs, each of which already saw a 3×3 window of the input) while using 2·(9·C²) parameters versus 25·C² for a single 5×5 layer — fewer parameters, more nonlinearities (an activation after each 3×3), and this is precisely the design philosophy VGGNet popularized and that most modern backbones still follow.

Pooling and Hierarchical Features

Pooling layers (max-pool or average-pool, typically 2×2 stride 2) downsample feature maps, cutting compute for subsequent layers and adding a further degree of local translation invariance — a max-pool output doesn't change if the strongest activation shifts by a pixel within its window. Depth is what builds the feature hierarchy: early layers with small receptive fields learn generic, low-level detectors (oriented edges, color blobs, gradients) that look remarkably similar across totally different trained networks; middle layers combine edges into textures and simple shapes; deep layers, having accumulated a large effective receptive field, respond to object parts and eventually whole objects. This is a real, empirically visualized phenomenon (see Zeiler & Fergus, 2014) rather than just an analogy — visualizing what maximally activates a filter at different depths shows exactly this edges → textures → parts progression.

Production Reality

Modern architectures reduce the raw compute of convolution with 1×1 convolutions (pure channel-mixing, used as bottlenecks in ResNet and Inception to cut channel count before an expensive 3×3) and depthwise separable convolutions (a per-channel spatial convolution followed by a 1×1 to mix channels), which MobileNet uses to cut compute by roughly 8–9× versus a standard convolution at similar accuracy — the reason MobileNetV2 runs in real time on phone CPUs. On GPUs, cuDNN picks among multiple convolution algorithms per shape (im2col + GEMM, Winograd for small kernels, FFT-based for large ones) via autotuning (torch.backends.cudnn.benchmark = True), and channels_last memory format plus mixed precision (FP16/BF16) can give a meaningful speedup on Tensor Cores with no accuracy loss for most vision models. For edge deployment, INT8 post-training quantization (TensorRT, ONNX Runtime) typically shrinks a CNN 4× in size and 2–4× in latency with under 1% accuracy loss, which is why quantization is standard for on-device vision. Note also the more recent architectural trend: Vision Transformers replace convolution's hard-coded local/translation-invariant prior with global self-attention over image patches, trading inductive bias for scale — ViTs generally need substantially more pretraining data than CNNs to match or beat them, precisely because they lack convolution's built-in locality assumption.

Key Takeaways

  • Weight sharing is the entire efficiency story — a 3×3×3→64 conv layer needs only 1,728 weights regardless of image resolution, versus ~617M for a dense layer mapping a 224×224×3 image to 4096 units; this is also what gives CNNs translation invariance for free, since the same detector is applied everywhere.
  • Two stacked 3×3 convs match a single 5×5's receptive field with fewer parameters and an extra nonlinearity (2·9C² vs 25C²) — this is the VGGNet insight that most modern CNN backbones (ResNet, EfficientNet) still build on.
  • Depthwise separable convolutions cut compute ~8–9× versus standard convolution at similar accuracy (MobileNet) — the standard trick for real-time inference on phones and edge devices without a dedicated GPU.
  • cuDNN autotunes the actual algorithm per layer shape (im2col+GEMM, Winograd, or FFT-based) — enabling torch.backends.cudnn.benchmark = True for fixed input sizes, plus channels_last memory format, is free throughput on Tensor Core GPUs with zero accuracy cost.
  • INT8 post-training quantization typically shrinks a CNN ~4× in size and 2–4× in latency for under 1% accuracy loss (TensorRT, ONNX Runtime) — standard for on-device deployment; quantization-aware training closes the gap further when PTQ alone isn't accurate enough.
  • Vision Transformers trade convolution's built-in locality/translation-invariance prior for global attention — that's why ViT needs substantially more pretraining data (JFT-300M scale) to match CNN accuracy on ImageNet-scale training; convolution's inductive bias is a genuine advantage in the low-data regime, not just a legacy design.
