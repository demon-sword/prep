24Learning Curves Diagnosis

Training vs validation error as a function of training set size — diagnosing high bias (both plateau high) vs high variance (large gap) from the curve shape.

Theory

What a Learning Curve Actually Plots

A learning curve plots model error against training set size — not against training epoch or boosting round (that's a "validation curve" / loss curve, a different diagnostic). To build one, you pick a sequence of sample sizes n₁ < n₂ < … < n_k (often log-spaced: 50, 100, 250, 500, 1000, …), and at each size you retrain the model from scratch on a random subset of that size, then record two numbers: the error on that same training subset (training error) and the error on a fixed, held-out validation set that never changes across sizes (validation error). The result is two curves as a function of n. This is exactly what scikit-learn's sklearn.model_selection.learning_curve computes, and it is one of the highest-signal-per-minute diagnostic plots in applied ML — it answers the question "would more data help?" without guessing.

Reading the Shape: Bias vs Variance

The training error curve almost always increases with n — a model can memorize 20 points perfectly (near-zero training error) but cannot memorize 20,000 points without also modeling the true underlying signal, so training error rises toward some floor as n grows. The validation error curve almost always decreases with n, since more data means better-estimated parameters and a model that generalizes better. The diagnosis lives in where the two curves converge and how big the residual gap is:

  • High bias (underfitting): both curves converge quickly to a similar value, but that value is high (well above the achievable/Bayes error). The model is too simple to capture the signal regardless of how much data you feed it — a straight line cannot fit a sinusoid no matter how many points you give it. Diagnostic implication: more data will not help. You need a more expressive model, better features, or a different algorithm.
  • High variance (overfitting): training error stays low (near the achievable floor) while validation error stays substantially higher — a persistent gap that narrows only slowly as n grows. The model has enough capacity to memorize idiosyncrasies of small training sets that don't generalize. Diagnostic implication: more data will help (the gap should keep shrinking as n → ∞), or you can regularize / reduce capacity to close the gap without collecting more data.
  • Good fit: both curves converge to a low value close to the Bayes/achievable error with a small residual gap — the sweet spot of the bias-variance tradeoff (see Concept 01) for this amount of data and model capacity.

Why the Curves Look the Way They Do — the Mechanism

This is the same bias-variance decomposition as always, sliced along a new axis (n instead of model complexity). For a fixed model class, variance of the fitted parameters shrinks roughly as O(1/n) under standard asymptotic theory, which is why the validation curve's descent decelerates — you get diminishing returns from each additional batch of data, visible as the curve flattening. Training error rises because a fixed-capacity model has an increasingly harder time interpolating a growing, noisier sample; it converges toward the model class's irreducible approximation error (the bias term) as n → ∞. The gap between the two curves at any given n is, to first order, the variance term of the decomposition evaluated at that sample size — which is exactly why a persistent, slowly-closing gap is the visual signature of a high-variance model.

Production Reality

Learning curves are the fastest way to answer "should we spend $50K labeling more data, or invest engineering time in a better model?" before either investment is made — a flat high-bias curve is a hard "no, don't buy more data" signal that saves real budget. In practice: (1) use several random subsamples per size and average with error bars (scikit-learn's learning_curve does this via its cv parameter) because small-n runs are noisy and a single draw can mislead; (2) plot n on a log scale when sizes span orders of magnitude, since the interesting curvature happens in the small-n region; (3) computing a full learning curve means retraining the model k × cv_folds times — for a $2M-parameter XGBoost model this is cheap, but for a large neural net it can be prohibitively expensive, so teams often approximate with just 2–3 sample sizes (e.g. 10%, 50%, 100% of available data) rather than a dense sweep; (4) always confirm the validation set itself is large and stable enough that its error estimate isn't the noisy element — a validation set that's too small will show a jittery curve unrelated to the phenomenon you're diagnosing; (5) if the curves haven't plateaued by the time you run out of available data, that's itself informative — it means the model is still data-starved and more labeling is very likely to keep helping.

Key Takeaways

  • The diagnosis is in the gap and the plateau level, not any single number: both curves converging to a high error = high bias (get a better model, not more data); a persistent gap with low training error = high variance (get more data, or regularize/simplify).
  • A flat, high, near-converged curve is a hard "don't buy more labels" signal — it can save a team a multi-week, five-figure labeling effort by showing early that the bottleneck is model capacity or features, not data volume.
  • Use sklearn.model_selection.learning_curve with multiple CV folds per size, not a single draw — small-n error estimates are noisy, and averaging with error bars (or shaded std bands) is what separates a real diagnosis from a misleading one-off curve.
  • Plot n on a log scale whenever sizes span more than ~1 order of magnitude — most of the interesting curvature (steep descent, plateau onset) happens in the small-n region that a linear axis compresses into invisibility.
  • Computing a full learning curve costs k sizes × cv folds full retrains — cheap for gradient-boosted trees or linear models, potentially prohibitive for large neural nets; teams often substitute a coarse 2–3 point sweep (e.g. 10%/50%/100% of data) for expensive models rather than a dense sweep.
  • Don't confuse a learning curve (error vs. training set size) with a validation curve (error vs. hyperparameter, e.g. tree depth) or a loss curve (error vs. training epoch) — all three are "two lines that should converge" plots but diagnose completely different levers, and mixing them up leads to the wrong fix being applied.
