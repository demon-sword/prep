17Hierarchical Clustering

Agglomerative clustering with linkage criteria (single, complete, average, Ward) and reading a dendrogram to choose cluster count.

Theory

Agglomerative Merging: Bottom-Up Cluster Construction

Agglomerative hierarchical clustering starts with every point as its own singleton cluster and repeatedly merges the two closest clusters until only one remains, recording every merge and the distance at which it happened. The output is not a single flat partition but a full hierarchy — a binary tree (dendrogram) where leaves are individual points, internal nodes are merges, and the height of each node encodes how dissimilar its two children were when they merged. This is the opposite direction from divisive clustering (start with one cluster, recursively split), which is far less common in practice because there are exponentially more ways to split a cluster than to pick the closest pair to merge. Crucially, unlike k-means, agglomerative clustering is deterministic given a distance metric and linkage rule — no random initialization, no local-optima sensitivity, and you get every possible cluster count "for free" in one run instead of re-fitting per k.

Linkage Criteria: How "Cluster Distance" Is Defined

The whole algorithm reduces to one question asked at every step: given two clusters (each possibly containing many points), what is the distance between them? The answer is the linkage criterion, and it fundamentally changes the shape of clusters produced:

  • Single linkage — d(A,B) = min distance between any point in A and any point in B. Extremely sensitive to a thin bridge of intermediate points: two visually distinct blobs connected by a chain of a few points will get merged early because some pair is close, producing long, straggly "chained" clusters. Useful for detecting non-convex, elongated structures that k-means can't, but fragile to noise.
  • Complete linkage — d(A,B) = max distance between any point in A and any point in B. The opposite failure mode: it refuses to merge until the worst-case pair is close, producing tight, compact, roughly-equal-diameter clusters, but it can break up one true elongated cluster into several pieces.
  • Average linkage — the mean distance across all cross-cluster point pairs. A middle ground between single and complete, less sensitive to outliers than either extreme.
  • Ward linkage — merges the pair that produces the smallest increase in total within-cluster variance (sum of squared distances to centroid), the same objective k-means minimizes. Its distance formula simplifies to d(A,B) = √(2|A||B| / (|A|+|B|)) · ‖centroid_A − centroid_B‖. Ward tends to produce balanced, spherical clusters similar to k-means and is scikit-learn's default for AgglomerativeClustering — but it technically requires Euclidean distance and doesn't generalize to arbitrary dissimilarity matrices the way single/complete/average do.

All four are special cases of the general Lance-Williams recurrence, which lets you update cluster distances incrementally after a merge without recomputing from raw points — the trick that makes production implementations efficient.

Reading (and Cutting) a Dendrogram

A dendrogram plots merge height (dissimilarity at merge time) on the y-axis against leaves arranged left-to-right on the x-axis so that no branches cross. To turn the hierarchy into a flat clustering, draw a horizontal line at some height h and count how many vertical branches it crosses — that's your cluster count, and the points hanging below each crossed branch form one cluster. Cutting low (small h) yields many small, tight clusters; cutting high yields few, coarse ones. The height of the longest vertical line you can cut through (the biggest gap between consecutive merge heights) is a common heuristic for picking a "natural" cut point — it means the next merge would have joined two clusters that were unusually dissimilar compared to everything merged so far.

Complexity and When Hierarchical Clustering Doesn't Scale

Naively, agglomerative clustering costs O(n³) time (n-1 merge steps, each re-scanning an O(n²) distance structure) and O(n²) memory to hold the pairwise distance matrix. Optimized algorithms bring time down: SLINK computes single linkage in O(n²), and the nearest-neighbor-chain algorithm gives O(n²) for Ward, complete, and average linkage too — but the O(n²) memory floor is unavoidable for the standard formulation. That means hierarchical clustering is realistically limited to tens of thousands of points, not millions — a hard contrast with k-means's O(nkd) per iteration, or DBSCAN's near-linear behavior with spatial indexing. This is the central production tradeoff: you get a full, deterministic, interpretable hierarchy at the cost of quadratic memory and cubic-ish compute.

Production Reality

scipy.cluster.hierarchy.linkage + fcluster is the classic combo for computing and cutting a dendrogram in Python; sklearn.cluster.AgglomerativeClustering wraps the same idea with a scikit-learn-style API and a distance_threshold parameter that lets you cut by height instead of specifying n_clusters up front. A connectivity matrix (typically from kneighbors_graph) can constrain merges to structurally adjacent points — essential for spatially or graph-structured data (image segmentation, geographic clustering) where merging two clusters that happen to be numerically close but physically far apart would be meaningless. The cophenetic correlation coefficient — the correlation between original pairwise distances and the dendrogram's "cophenetic distance" (the height at which two points first merge) — is the standard diagnostic for how faithfully a dendrogram represents the raw distance structure; values above ~0.75 are usually considered a reasonable fit. Common production/research uses: gene expression and phylogenetic trees (where the nested hierarchy itself, not just a flat cut, is the deliverable), building taxonomies for content or product catalogs, and exploratory analysis when the "right" number of clusters is genuinely unknown and you want to inspect several cuts before committing.

Key Takeaways

  • Hierarchical clustering trades scalability for determinism and structure. There's no random initialization and no need to commit to k up front — you get the full nested hierarchy in one deterministic run — but the O(n²) memory floor for the distance matrix means it's realistically capped at tens of thousands of points, not millions, unlike k-means or DBSCAN.
  • Linkage choice changes cluster geometry more than almost any other hyperparameter in unsupervised learning. Single linkage chains through bridges of noise and finds elongated/non-convex shapes; complete linkage forces tight, compact, roughly equal-diameter clusters; Ward mimics k-means's variance-minimizing objective. Try the "bridge points" in this visualization with single vs. complete linkage — same data, dramatically different clusters.
  • Ward linkage is scikit-learn's default for a reason, but it's Euclidean-only. If your distance metric isn't Euclidean (cosine similarity for text embeddings, edit distance for strings, precomputed domain-specific dissimilarities), Ward's centroid-variance formula doesn't apply — fall back to average or complete linkage with a custom affinity/metric.
  • The dendrogram cut height is a real hyperparameter, not a formality. AgglomerativeClustering(distance_threshold=...) lets you cut by height instead of guessing n_clusters, and the biggest vertical gap between consecutive merge heights is a standard heuristic for where to cut — directly analogous to the elbow method in k-means.
  • Use a connectivity constraint (kneighbors_graph) whenever spatial or graph adjacency matters. Without it, agglomerative clustering happily merges clusters that are numerically close in feature space but physically or structurally unrelated — a common bug in image segmentation and geographic clustering pipelines.
  • Validate the dendrogram itself, not just the cut. The cophenetic correlation coefficient (correlation between raw pairwise distances and dendrogram merge heights) quantifies how much distortion the tree introduced; a low value means the hierarchy is a poor summary of the actual distance structure regardless of where you cut it.
