11Naive Bayes Classifier

Conditional independence assumption, how it simplifies Bayes' theorem for classification, and why it works well for text despite the naive assumption.

Theory

From Bayes' Theorem to a Classifier

Naive Bayes turns 02-bayes-theorem into a working classifier by asking: given a feature vector x = (x₁, …, xₙ), which class c maximizes the posterior P(c|x)? By Bayes' rule, P(c|x) = P(x|c)·P(c) / P(x). Since P(x) is the same normalizing constant for every candidate class, classification reduces to maximizing the numerator: argmax_c P(x|c)·P(c) — a prior P(c) (how common is this class overall) times a likelihood P(x|c) (how well do these features fit that class). The entire difficulty is estimating P(x|c): a joint distribution over n features has, in the worst case, exponentially many parameters to learn — utterly infeasible from a finite training set.

The "Naive" Independence Assumption

Naive Bayes sidesteps this by assuming every feature is conditionally independent given the class: P(x₁,…,xₙ|c) = P(x₁|c)·P(x₂|c)·…·P(xₙ|c). This is almost always false in reality — in spam email, the words "click" and "here" co-occur far more than independence would predict, and "prince" and "inheritance" are practically inseparable. Yet the classifier is famously robust to this violation for a subtle reason: NB only needs to get the ranking of P(c|x) across classes right, not the calibrated probability values. Even when the independence assumption skews the magnitude of the estimated posterior (often pushing it toward 0 or 1 more aggressively than justified), it frequently still skews it in the correct direction, so the argmax decision remains correct even though predict_proba() output is poorly calibrated. This is why NB is a strong classifier despite being a weak density estimator — a distinction worth stating explicitly in an interview.

Three Flavors, by Feature Type

Multinomial NB (sklearn.naive_bayes.MultinomialNB) models each feature as a count (word frequency in a document) drawn from a multinomial distribution per class — the standard choice for bag-of-words / TF-count text classification. Bernoulli NB (BernoulliNB) instead models each feature as a binary presence/absence indicator and explicitly penalizes the absence of expected words, not just rewarding presence — better suited to short texts where word presence matters more than frequency. Gaussian NB (GaussianNB) assumes each continuous feature is normally distributed within each class, estimating a per-class mean and variance — useful as a fast baseline on numeric/tabular data, though the Gaussian assumption is often badly wrong for skewed real-world features (worth combining with a power transform first).

Laplace (Additive) Smoothing

A word that never appeared with a given class in training gets estimated likelihood 0, which — because likelihoods multiply — zeroes out the entire posterior for that class regardless of how strongly every other feature supports it. Laplace smoothing (alpha smoothing) fixes this by adding a pseudocount α (scikit-learn's default alpha=1.0) to every count before normalizing: P(word|class) = (count + α) / (total_count + α·|vocab|). This guarantees every probability stays strictly positive. Tuning alpha down (e.g. 0.1–0.5) trusts the training counts more and sharpens the model; tuning it up smooths harder and better protects against unseen-word zeroing on small training sets — a real hyperparameter worth grid-searching, not just leaving at its default.

Numerical Stability: Log-Space

Multiplying dozens or hundreds of probabilities (one per word in a document) underflows floating point almost immediately — a product of 200 numbers each around 0.01 vanishes to 0.0 in double precision. Every real implementation computes in log-space instead: log P(c|x) ∝ log P(c) + Σᵢ log P(xᵢ|c), turning the product into a sum, which is numerically stable and is exactly what MultinomialNB.predict_log_proba() returns internally before exponentiating back for predict_proba().

Production Reality

NB's appeal in production is speed and simplicity: training is a single pass counting word/class co-occurrences — O(n) and trivially parallelizable/incremental (partial_fit supports online/streaming learning, unlike most other classifiers) — and inference is a dot product, sub-millisecond even on commodity hardware. It's the classic first baseline for spam filtering, sentiment analysis, and document routing before reaching for logistic regression, linear SVM, or a fine-tuned transformer. For imbalanced text classification, scikit-learn's ComplementNB (designed specifically for skewed class distributions) typically outperforms MultinomialNB out of the box. The known failure mode: strongly correlated or redundant features get "double-counted" in the naive product, overconfidently swinging the decision — e.g. including both a raw word and a stemmed/lemmatized version of it as separate features compounds the same signal twice. NB is also a generative model (it models P(x|c), and can in principle generate synthetic samples), in contrast to discriminative models like logistic regression that model P(c|x) directly — generative models need less data to reach their asymptotic accuracy but are eventually outperformed by discriminative models as training data grows, a classic result from Ng & Jordan's 2001 NB-vs-logistic-regression comparison.

Key Takeaways

  • NB is a generative classifier that's usually miscalibrated but rarely wrong on ranking. Because the conditional independence assumption systematically distorts the magnitude (not always the direction) of the posterior, predict_proba() outputs often look overconfident (values clustered near 0 or 1) — recalibrate with CalibratedClassifierCV if you actually need trustworthy probabilities, e.g. for a downstream threshold-based business decision.
  • Always smooth — never trust raw counts. scikit-learn's default alpha=1.0 Laplace smoothing exists because a single unseen word in test data would otherwise zero out an entire class's likelihood. In practice, tune alpha via cross-validation; smaller corpora need more smoothing (higher alpha), large corpora need less.
  • Match the NB variant to the feature type — MultinomialNB for word counts/TF, BernoulliNB for binary presence (especially short texts like tweets or SMS), ComplementNB for imbalanced text classification (often beats MultinomialNB out of the box on skewed classes), GaussianNB only for roughly-normal continuous features — using the wrong variant silently degrades accuracy without throwing an error.
  • NB needs far less training data than logistic regression to reach its (lower) asymptotic accuracy — the classic Ng & Jordan (2001) result. It's the right choice for cold-start classifiers with a few hundred labeled examples; once you have tens of thousands of labeled documents, a discriminative linear model (logistic regression, linear SVM) or a fine-tuned transformer will typically overtake it.
  • Redundant/correlated features get double-counted. Feeding NB both a raw token and its stem, or both a word and a bigram containing it, makes the same evidence multiply in twice — inflating confidence without adding real information. Deduplicate or use TF-IDF weighting to dampen this before feeding a bag-of-words into NB.
  • NB supports true online/incremental learning via partial_fit(), updating word/class counts one mini-batch at a time without retraining from scratch — a real production advantage over batch-only models when the training corpus streams continuously (e.g. live spam reports feeding back into the filter).
