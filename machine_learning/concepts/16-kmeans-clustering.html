16k-Means Clustering

Centroid initialization, the assign-update Lloyd's algorithm loop, and the elbow method for choosing k.

Theory

The Objective: Minimize Within-Cluster Sum of Squares

k-Means partitions n points into k clusters by minimizing the within-cluster sum of squares (WCSS), also called inertia: Σₖ Σ_{x∈Cₖ} ‖x − μₖ‖², the total squared Euclidean distance from every point to its assigned cluster centroid μₖ. This is a genuinely hard combinatorial problem — exact minimization over all possible partitions of n points into k groups is NP-hard even in 2D — so in practice everyone uses Lloyd's algorithm, a fast local-search heuristic that provably decreases (or holds constant) the objective every iteration and is guaranteed to converge, but only to a local minimum, not the global one.

Lloyd's Algorithm: Assign, Then Update, Repeat

Starting from k initial centroids, Lloyd's algorithm alternates two steps until assignments stop changing: (1) assignment — label every point with its nearest centroid by Euclidean distance, carving the space into a Voronoi tessellation; (2) update — recompute each centroid as the mean of the points currently assigned to it. Each full pass strictly decreases (or holds) inertia because reassigning a point to its nearest centroid can only shrink its contribution to the sum of squares, and moving a centroid to the mean of its cluster is exactly the point that minimizes summed squared distance to that fixed set of points. Convergence typically happens within 10–30 iterations on well-separated data, but the algorithm halts at whatever local optimum the assign/update loop rolls into — different starting points can converge to visibly different, sometimes much worse, partitions.

Initialization Is Not a Detail — It's Half the Algorithm

Because Lloyd's algorithm only ever improves on its starting point, initialization quality directly determines solution quality. Naive random initialization (picking k random data points as starting centroids) can land two centroids inside the same true cluster, leaving another cluster split awkwardly or unrepresented, and converge to a clearly suboptimal local minimum. k-means++ (the scikit-learn default) fixes this by seeding centroids sequentially: pick the first centroid uniformly at random, then pick each subsequent centroid from the remaining points with probability proportional to its squared distance to the nearest already-chosen centroid — points far from existing centroids are far more likely to be picked next. This spreads initial centroids out across the data's actual structure and provably gives an O(log k)-competitive expected approximation to the optimal inertia, dramatically reducing how often the algorithm lands in a bad local minimum. Because even k-means++ is randomized, sklearn.cluster.KMeans runs the whole assign-update loop multiple times from different seeds (n_init, historically 10, changed to 'auto' in scikit-learn 1.4 — meaning 1 run for k-means++ init, 10 for random init) and keeps the run with lowest final inertia.

Choosing k: The Elbow Method and Its Limits

k-Means requires k as an input, but the "right" number of clusters is rarely known in advance. The elbow method plots inertia against k for a range of candidate values; inertia decreases monotonically as k grows (more clusters can only fit the data more tightly, with inertia hitting zero at k = n), but the rate of decrease sharply slows past the "true" cluster count — the elbow. In practice the elbow is often ambiguous on real data, so it's typically combined with the silhouette score (how much closer a point is to its own cluster than to the next-nearest one, ranging −1 to 1) or domain knowledge about how many segments a business can actually act on.

Assumptions and Failure Modes

k-Means implicitly assumes clusters are roughly spherical, similarly sized, and separated in Euclidean space — because every point is assigned by straight-line distance to a single centroid, the algorithm draws only linear (Voronoi) decision boundaries between clusters and cannot represent elongated, nested, or non-convex shapes (two concentric rings) or clusters of very different density or size, where a large sparse cluster can get fragmented while nearby dense clusters absorb its points. This is exactly the gap density-based methods like DBSCAN are built to fill. Feature scaling matters enormously: since distance is computed across all dimensions jointly, a feature on a 0–10,000 scale will dominate one on a 0–1 scale unless features are standardized first (StandardScaler before KMeans is close to mandatory in production pipelines).

Production Reality

Standard Lloyd's algorithm is O(n·k·i·d) per run (n points, k clusters, i iterations, d dimensions) — cheap enough for exploratory work but expensive to re-run at scale with many n_init restarts. scikit-learn's algorithm='elkan' variant uses the triangle inequality to skip distance computations that provably can't change a point's assignment, giving real speedups on low-to-moderate dimensional dense data. For truly large datasets, MiniBatchKMeans updates centroids using small random batches per step instead of the full dataset, trading a small amount of solution quality for order-of-magnitude speedups — the standard choice for clustering millions of rows or streaming data. Common production uses: customer/behavioral segmentation, vector quantization for compression, initializing Gaussian Mixture Models, and building coarse codebooks for approximate nearest-neighbor search (IVF indexes in FAISS use k-means to partition the vector space into cells).

Key Takeaways

  • Lloyd's algorithm only ever finds a local minimum, and it's not guaranteed to be a good one. Every assign-update pass strictly decreases inertia, but where it stops depends entirely on where it started — this is exactly why sklearn.cluster.KMeans defaults to multiple restarts (n_init='auto') and keeps the lowest-inertia run rather than trusting a single pass.
  • k-means++ initialization is not optional polish — it's the difference between a usable result and a coin flip. Random centroid seeding can place two centroids in the same true cluster and leave another cluster unrepresented; distance-weighted sequential seeding gives an O(log k)-competitive expected inertia and is the scikit-learn default for good reason.
  • Always scale features before k-means. Because cluster assignment is driven by raw Euclidean distance across all dimensions jointly, an unscaled feature spanning thousands of units will silently dominate the clustering — StandardScaler (or MinMaxScaler) before KMeans is close to a hard requirement in any real pipeline.
  • k-means assumes spherical, similarly-sized, similarly-dense clusters — and fails visibly when that's false. Elongated clusters, concentric rings, and clusters of very different density or population size get carved up incorrectly because every boundary is a straight Voronoi line; reach for DBSCAN or Gaussian Mixture Models (which allow elliptical, differently-sized covariance) when that assumption doesn't hold.
  • The elbow method is a heuristic, not an algorithm — pair it with the silhouette score. Inertia decreases monotonically with k by construction (hitting zero at k=n), so the "elbow" is often genuinely ambiguous on real data; a silhouette score (−1 to 1, measuring separation vs cohesion) or a business constraint on actionable segment count is usually needed to actually pick k.
  • At scale, use MiniBatchKMeans, not full-batch Lloyd's. Standard k-means is O(n·k·i·d) per restart and becomes expensive with millions of rows and multiple n_init restarts; mini-batch updates on small random subsets trade a small amount of solution quality for order-of-magnitude speedups, and k-means itself underlies production infrastructure like FAISS's IVF index, which uses it to partition a vector space into coarse search cells.
