19Principal Component Analysis

PCA as variance-maximizing projection — eigenvectors of the covariance matrix, explained variance ratio, and dimensionality reduction tradeoffs.

Theory

The Objective: Find the Direction That Maximizes Projected Variance

PCA answers a precise question: among all possible unit directions in feature space, which one, if you projected every data point onto it, preserves the most spread (variance) of the original data? Formally, for mean-centered data X, PCA seeks a unit vector w maximizing Var(Xw) = wᵀΣw subject to ‖w‖ = 1, where Σ = XᵀX / (n−1) is the feature covariance matrix. This is a constrained optimization problem solved with a Lagrange multiplier, and the solution falls straight out of linear algebra: the maximizing w is the eigenvector of Σ with the largest eigenvalue, and the maximum achieved variance is exactly that eigenvalue. The second-best direction — orthogonal to the first, maximizing remaining variance — is the eigenvector with the second-largest eigenvalue, and so on. The full set of eigenvectors of the covariance matrix, ordered by eigenvalue, is the set of principal components: an orthogonal basis rotated to align with the data's actual axes of spread rather than the original (often arbitrary) feature axes.

Eigendecomposition vs SVD — What scikit-learn Actually Computes

Conceptually PCA is an eigendecomposition of the covariance matrix, but sklearn.decomposition.PCA never explicitly forms Σ — it computes a Singular Value Decomposition (SVD) of the centered data matrix directly: X = UΣVᵀ. The columns of V are exactly the principal component directions, and the singular values relate to the eigenvalues of the covariance matrix by λᵢ = σᵢ² / (n−1). SVD is preferred numerically because forming XᵀX explicitly squares the condition number of the problem, amplifying floating-point error — going through SVD is more numerically stable, especially with correlated or near-collinear features. Default full SVD costs roughly O(min(n,d)² · max(n,d)); for large n or d, scikit-learn's default svd_solver='auto' switches to a randomized SVD approximation (Halko et al.) once the matrix is large and only a handful of components are requested, cutting compute dramatically at negligible accuracy cost.

Explained Variance Ratio and Choosing the Number of Components

Each eigenvalue λᵢ is the variance captured by component i; dividing by the total variance Σλⱼ gives the explained variance ratio — scikit-learn exposes this directly as pca.explained_variance_ratio_. Plotting cumulative explained variance against number of components (a scree plot) is the standard way to pick k: a common production rule of thumb is to keep enough components to cross 90–95% cumulative variance, though the right threshold is domain-specific — for noisy sensor data with 500 correlated features you might compress to 20 components at 90% variance; for a well-conditioned 10-feature table there may be no elbow at all, meaning PCA isn't buying much.

Standardization Is Not Optional

Because PCA maximizes raw variance, a feature measured in larger units (income in dollars vs age in years) will dominate the covariance matrix and hijack the first component purely due to scale, not genuine signal. StandardScaler before PCA — equivalent to running PCA on the correlation matrix instead of the covariance matrix — is close to mandatory whenever features aren't already on comparable, meaningful scales. Whether to standardize is itself a modeling decision: for images where all pixels share the same scale, or for count data already expressed in consistent units, un-scaled PCA can be the right choice.

What PCA Assumes, and When It Breaks

PCA finds only linear, orthogonal directions of maximum variance — it cannot represent nonlinear manifolds (a spiral or Swiss-roll structure gets flattened into a poor linear approximation), and it optimizes for variance, not class separability or task-relevant structure, so a component that maximizes spread might be nearly useless for a downstream classification task (LDA optimizes for class separation instead, when labels are available). PCA is also sensitive to outliers, since variance is a squared quantity — a handful of extreme points can dominate a component. For nonlinear structure, Kernel PCA applies the kernel trick to find nonlinear principal surfaces, and for pure visualization, t-SNE/UMAP (see concept 20) trade global linear structure for locally faithful nonlinear embeddings.

Production Reality

Beyond visualization, PCA's biggest production use is as a preprocessing step: decorrelating and compressing features before feeding them to models sensitive to multicollinearity or the curse of dimensionality (e.g. k-NN, linear regression with near-singular design matrices), denoising signals by dropping low-variance components assumed to be noise, and whitening (whiten=True scales each component to unit variance) to feed downstream algorithms that assume isotropic input. For streaming or memory-constrained settings, IncrementalPCA processes data in mini-batches without holding the full dataset in memory. A frequent interview gotcha: PCA components are linear combinations of all original features, so they sacrifice interpretability — a "component" rarely maps to a single human-meaningful concept, unlike a raw feature or a Lasso-selected subset. Always fit PCA only on the training set and apply the same fitted transform to validation/test data to avoid leaking test-set variance structure into the projection.

Key Takeaways

  • PC1 is the eigenvector of the covariance matrix with the largest eigenvalue — full stop. Everything else (scree plots, explained variance ratio, whitening) is downstream bookkeeping on top of that one linear-algebra fact; if you can state the constrained optimization (max wᵀΣw s.t. ‖w‖=1) and why Lagrange multipliers hand you an eigenvector, you can derive the rest of PCA from scratch on a whiteboard.
  • scikit-learn computes SVD of the data matrix, not eigendecomposition of the covariance matrix. They're mathematically equivalent (λᵢ = σᵢ²/(n−1)), but SVD avoids explicitly forming XᵀX, which squares the condition number and amplifies floating-point error — this is why PCA is numerically preferred over manual eigendecomposition in production code.
  • Standardize before PCA unless every feature already shares a meaningful common scale. Because PCA maximizes raw variance, an unscaled feature on a larger numeric range will dominate the first component for reasons that have nothing to do with actual signal — StandardScaler → PCA is effectively running PCA on the correlation matrix instead of the covariance matrix.
  • Principal components sacrifice interpretability. Each component is a linear combination of every original feature with real-valued loadings, so "PC1 went up" rarely maps to one human concept — if interpretability matters more than compression, prefer Lasso-based feature selection or domain-driven feature engineering over PCA.
  • PCA is linear and variance-driven — it is blind to class labels and nonlinear structure. A component that maximizes overall spread can be nearly orthogonal to what actually separates your classes (use LDA when labels exist and separability is the goal), and manifold structure like a Swiss roll gets crushed flat; reach for Kernel PCA or t-SNE/UMAP when the data doesn't live on a linear subspace.
  • Fit on train, transform on test — never refit PCA on validation/test data. Refitting leaks test-set covariance structure into the projection, silently inflating downstream validation metrics; for datasets too large to fit in memory at once, IncrementalPCA fits the same components via mini-batches instead of loading everything at once.
