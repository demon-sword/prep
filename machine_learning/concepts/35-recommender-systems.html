35Recommender Systems

Collaborative filtering (user-based, item-based, matrix factorization) vs content-based filtering, and hybrid architectures used in production recommenders.

Theory

Two Philosophies: "People Like You" vs "Items Like This"

Recommender systems answer one question — what should this user see next — from two fundamentally different signal sources. Collaborative filtering (CF) uses only the interaction matrix (who rated/clicked/watched what) and assumes users who agreed in the past will agree again; it needs zero information about item content, which makes it powerful but data-hungry. Content-based filtering uses item features (genre, text embeddings, price, tags) and a per-user profile built from the features of items the user liked; it works from day one for a new item but tends to over-specialize, recommending near-duplicates of what a user already consumed and rarely surfacing serendipitous discoveries. Most production systems are hybrids that blend both, precisely because each covers the other's blind spot.

Neighborhood Methods

The classic CF approach is memory-based: user-based CF finds users with similar rating vectors (cosine or Pearson similarity) to the target user and recommends what those neighbors liked; item-based CF (Amazon's original "customers who bought this also bought…", Linden et al. 2003) instead computes item-item similarity from co-rating patterns and is far more stable in production because item-item similarities change slowly compared to a user's neighbor set, which can churn every session. Both approaches are simple and interpretable but scale poorly — computing full similarity matrices is O(n²) in users or items — and degrade badly under sparsity: on a catalog with millions of items, most user pairs share almost no co-rated items, so similarity estimates become noisy.

Matrix Factorization — The Latent Factor Model

The approach that won the Netflix Prize (2006–2009, Koren/Bell/Volinsky's BellKor solution) reframes the problem as filling in a sparse users × items ratings matrix R by decomposing it into two low-rank matrices: a user-factor matrix P (n_users × k) and an item-factor matrix Q (n_items × k), such that R̂[u,i] = P[u] · Q[i] (plus user/item bias terms and a global average in practice). Each row of P and Q is a dense k-dimensional embedding (typically k = 20–200 in production) capturing latent taste dimensions the model discovers on its own — no one hand-labels them "action-ness" or "quirky-comedy-ness," but they often align with human-interpretable axes after training.

min_{P,Q} Σ_(u,i)∈known (r_ui − p_u·q_i)² + λ(‖p_u‖² + ‖q_i‖²)

This is optimized either via SGD (Funk-SVD style — sample a known rating, compute the error, nudge p_u and q_i a small step against the gradient; fast, easy to parallelize with Hogwild-style lock-free updates) or via Alternating Least Squares (ALS) — fix Q, solve for the optimal P in closed form via ridge regression, then fix P and solve for Q, repeating until convergence. ALS is the default in Spark's ALS and is preferred for implicit feedback (clicks, watches, purchases — signals that only tell you positive engagement, never an explicit negative) because Hu, Koren & Volinsky (2008) showed how to reformulate the objective with a per-interaction confidence weight instead of a rating value, treating all unobserved entries as weak negatives rather than missing data.

Cold Start and Hybrid Architectures

Pure CF fails completely for a brand-new user or item with zero interactions — there's nothing to factorize. The standard fix is a hybrid: fall back to content-based or popularity-based recommendations until enough interaction data accumulates, then blend in CF signal, weighting it up as confidence grows. Two-tower neural models (a user encoder tower and an item encoder tower trained jointly to produce embeddings whose dot product predicts engagement) are the modern generalization of matrix factorization — they naturally absorb content features (text, image embeddings, metadata) into the item tower, which mitigates cold start because a new item's embedding can be computed from its features alone, without waiting for interaction history.

Production Reality

Real-world recommenders are almost never single-model — they're a two-stage pipeline: a cheap candidate generation stage (matrix factorization, two-tower retrieval, or item-item CF) narrows millions of items down to a few hundred using approximate nearest-neighbor search over embeddings (FAISS, ScaNN, HNSW), followed by an expensive ranking stage — a gradient-boosted tree or deep model with hundreds of features (recency, session context, diversity penalties) that re-scores just those candidates. Offline metrics (precision@k, recall@k, NDCG, MAP) routinely disagree with online engagement, because they reward reproducing held-out clicks rather than genuine user satisfaction — a system that just recommends the most popular items scores deceptively well offline while adding zero value online. This is why recommender changes are almost always shipped through online A/B tests (36-ab-testing) rather than trusted on offline metrics alone, and why teams explicitly track diversity/novelty metrics alongside accuracy to counteract the popularity-bias feedback loop where already-popular items get recommended more, get more clicks, and get recommended even more.

    Key Takeaways

    • Item-based CF beats user-based CF in production stability — item-item similarity (Amazon, Linden et al. 2003) changes slowly because it's aggregated over many users, while a single user's nearest-neighbor set can flip session to session; most "customers who bought X also bought Y" features are item-based, not user-based.
    • Matrix factorization is just R ≈ P·Qᵀ learned by SGD or ALS — the Netflix Prize-winning approach compresses a sparse ratings matrix into dense k-dimensional (typically 20–200) user and item embeddings; ALS is preferred for implicit feedback (clicks, not star ratings) using the Hu-Koren-Volinsky confidence-weighted formulation, and is the default in Spark MLlib's ALS.
    • Cold start is structural, not a bug to tune away — a brand-new user or item has no interaction history for CF to factorize, so production systems fall back to content-based or popularity signals and blend in collaborative signal only as confidence accumulates; two-tower neural retrieval models solve this natively by encoding items from content features alone.
    • Real systems are two-stage: retrieval then ranking — a cheap ANN search (FAISS, ScaNN, HNSW) over embeddings narrows millions of items to a few hundred candidates, then an expensive GBM or deep ranker with hundreds of contextual features re-scores just those candidates; conflating the two stages into one model doesn't scale past a small catalog.
    • Offline metrics (NDCG, MAP, recall@k) routinely mislead — a model that just recommends popular items scores well offline (held-out interactions correlate with popularity) while adding zero incremental value; recommender launches are almost always gated on online A/B tests measuring actual engagement lift, not offline leaderboard rank (36-ab-testing).
    • Popularity-bias feedback loops compound silently — items shown more get clicked more, which reinforces the model's belief they should be shown more; teams counter this with explicit diversity/novelty penalties in the ranking stage and exploration mechanisms (epsilon-greedy or bandit-based slot allocation), not by hoping accuracy metrics catch it.
