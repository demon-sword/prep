26L1 vs L2 Regularization

L1 (Lasso) vs L2 (Ridge) penalties — why L1's diamond constraint region produces sparse weights while L2's circular region shrinks smoothly.

Theory

Why Regularize at All

A model trained to minimize training loss alone will happily exploit noise: with enough features (or enough parameters relative to samples), it can drive training error to zero while generalizing terribly — the high-variance end of the bias-variance tradeoff. Regularization fights this by adding a penalty on model complexity to the objective, trading a little bias for a large reduction in variance. For linear models the two workhorses are L2 (Ridge), J(w) = Loss(w) + λ·Σwᵢ², and L1 (Lasso), J(w) = Loss(w) + λ·Σ|wᵢ|. Both shrink weights toward zero as λ grows, but they get there through very different geometry, and that difference has large practical consequences.

The Geometric Story: Circle vs Diamond

The Lagrangian penalty form is equivalent to a constrained optimization: minimize the loss subject to Σwᵢ² ≤ t (L2) or Σ|wᵢ| ≤ t (L1) for some budget t tied to λ. Geometrically, L2's constraint region is a smooth circle (hypersphere in higher dimensions); L1's is a diamond (a cross-polytope) with sharp corners sitting exactly on the coordinate axes. The unconstrained OLS solution sits at the center of a family of elliptical loss contours; the regularized solution is the point where the smallest loss contour first touches the constraint region's boundary. Because the diamond has corners on the axes, that first point of contact is disproportionately likely to land exactly on an axis — meaning one or more coordinates are exactly zero. A circle has no corners, so the tangency point almost never lands exactly on an axis; L2 shrinks every weight toward zero but essentially never sets one to exactly zero. This is the entire reason L1 performs implicit feature selection and L2 doesn't.

The Algebraic Story: Constant vs Proportional Gradient

The same fact falls out of the subgradients. L2's penalty gradient is 2λwᵢ — proportional to the weight itself, so as wᵢ shrinks, the pull toward zero weakens too; it's a smooth exponential decay (literally called weight decay in deep learning: each SGD step multiplies the weight by (1 − ηλ) before applying the data gradient) that asymptotically approaches but never reaches zero. L1's penalty gradient is λ·sign(wᵢ) — a constant magnitude regardless of how small wᵢ already is, so it keeps pushing at full strength until the data gradient can no longer counteract it, at which point the coordinate-wise optimum is exactly zero. This is the closed-form soft-thresholding operator that Lasso solvers apply at each coordinate: wⱼ* = sign(w_ls)·max(|w_ls| − λ/(2a), 0), where w_ls is the unregularized least-squares solution for that coordinate holding others fixed.

Bayesian Interpretation

Both penalties are MAP estimation with a specific prior on the weights (see MLE vs MAP): L2 corresponds to a zero-mean Gaussian prior, wᵢ ~ N(0, σ²/λ) — Gaussians have light-but-smooth tails, matching L2's gentle, never-quite-zero shrinkage. L1 corresponds to a zero-mean Laplace (double-exponential) prior, p(w) ∝ exp(−λ|w|/σ²), whose sharp peak at zero puts substantially more prior mass exactly at zero than a Gaussian does — matching L1's tendency to snap coordinates to exactly zero.

Correlated Features and Elastic Net

When two features are highly correlated, Ridge distributes weight between them roughly evenly (it prefers many small coefficients over one large one, because the squared penalty punishes large values disproportionately). Lasso, in the same situation, tends to arbitrarily pick one of the correlated features and zero out the other — the selection is unstable, flipping between the two features under small perturbations of the data. Elastic Net (λ₁Σ|wᵢ| + λ₂Σwᵢ², sklearn.linear_model.ElasticNet with an l1_ratio mixing parameter) fixes this "grouping effect" problem by blending both penalties — sparse but stable under correlated features.

Production Reality

Ridge has a closed-form solution, w = (XᵀX + λI)⁻¹Xᵀy, so sklearn.linear_model.Ridge solves it directly via Cholesky/SVD — no iterative optimizer needed for small-to-medium feature counts. Lasso has no closed form (the absolute value isn't differentiable at zero) so sklearn.linear_model.Lasso uses cyclic coordinate descent, solving one coordinate at a time via soft-thresholding while holding the others fixed, sweeping repeatedly until convergence — the exact update used in the visualization below. LARS (Least Angle Regression) is a faster alternative that computes the entire regularization path in one shot, useful when you need Lasso solutions across many λ values (sklearn.linear_model.lasso_path/LassoLars). In practice λ (sklearn calls it alpha) is tuned by cross-validation over a log-spaced grid — RidgeCV/LassoCV default to something like np.logspace(-4, 1, 100) — and features must be standardized first, since the penalty is scale-dependent: an unscaled feature measured in millimeters vs meters would get a wildly different effective penalty. In deep learning, L2/weight decay is applied per-step in the optimizer; note that naive L2-as-added-loss interacts incorrectly with Adam's adaptive per-parameter scaling, which is why AdamW decouples weight decay from the gradient update (see Gradient Descent Variants). L1 regularization in neural nets is rare — dropout and L2/weight decay dominate — because true sparsity in a dense layer doesn't translate into a compute speedup without specialized sparse kernels.

Key Takeaways

  • L1 zeroes coefficients because its constraint region has corners on the axes; L2's circular region doesn't — this is a geometric fact, not a tuning accident, and it's the entire mechanism behind Lasso's implicit feature selection.
  • Ridge has a closed-form solution ((XᵀX+λI)⁻¹Xᵀy); Lasso does not — sklearn's Lasso solves it with cyclic coordinate descent and per-coordinate soft-thresholding, the same update the visualization above runs live; LassoLars/lasso_path computes the whole regularization path more efficiently when you need many λ values at once.
  • Always standardize features before regularizing — the penalty term is scale-dependent, so an unscaled feature gets an arbitrary effective penalty relative to others; StandardScaler before Ridge/Lasso is non-negotiable in production pipelines.
  • Under correlated features, Lasso's selection is unstable — it arbitrarily picks one of two correlated predictors and zeroes the other, flipping under small data perturbations; Elastic Net (l1_ratio blend of both penalties) restores a "grouping effect" that keeps correlated features together.
  • L2 = Gaussian prior, L1 = Laplace prior on the weights under a MAP interpretation — the Laplace distribution's sharp peak at zero is exactly why L1 puts real probability mass on exact sparsity while the smooth Gaussian never does.
  • In deep learning, L2/weight decay is the default (not L1) — true weight sparsity from L1 doesn't speed up dense matrix multiplies without specialized sparse kernels, and naive L2-as-loss interacts badly with Adam's per-parameter adaptive scaling, which is why AdamW decouples decay from the gradient update instead of adding λ‖w‖² to the loss.
