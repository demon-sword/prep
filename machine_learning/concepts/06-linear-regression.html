Supervised Learning

06Linear Regression

Ordinary least squares, the normal equation, and gradient descent fitting a line — assumptions (linearity, homoscedasticity) and when they break.

Theory

The Model and the Closed-Form Solution

Linear regression models a continuous target as a linear combination of features: y = Xβ + ε, where ε is assumed zero-mean noise. Ordinary least squares (OLS) picks the coefficient vector β that minimizes the sum of squared residuals:

β̂ = argmin_β  ‖y − Xβ‖²   ⟹   β̂ = (XᵀX)⁻¹Xᵀy

This normal equation is a closed-form solution — no iteration required — because the squared-error loss is convex and quadratic in β, so its gradient has a single root. In practice, nobody inverts XᵀX directly: it's numerically unstable when features are correlated (the matrix becomes near-singular and inversion amplifies floating-point error). scikit-learn's LinearRegression instead solves the least-squares problem via SVD (through scipy.linalg.lstsq), which is stable even when XᵀX is ill-conditioned or features are perfectly collinear (it returns the minimum-norm solution). The closed form costs roughly O(nd² + d³) — fine for d in the hundreds, prohibitive once d reaches the tens of thousands, which is exactly when iterative solvers take over.

Gradient Descent as the General-Purpose Alternative

Gradient descent minimizes the same squared-error objective iteratively: β ← β − η·∇L(β), where ∇L(β) = −2Xᵀ(y − Xβ)/n for mean squared error. It's the fallback whenever the closed form is unavailable or too expensive: d is huge (millions of one-hot text features), the loss doesn't have a closed form (Lasso's L1 penalty has no analytic solution — coordinate descent or proximal gradient methods are used instead), or the dataset doesn't fit in memory (mini-batch/stochastic gradient descent, as in SGDRegressor). Convergence speed of gradient descent is governed by the condition number of XᵀX — features on wildly different scales (e.g. "age in years" vs "income in dollars") create an elongated, ill-conditioned loss bowl that makes vanilla gradient descent zig-zag slowly toward the minimum. This is why feature standardization is essential for gradient-based fitting but mathematically irrelevant to the closed-form normal equation (it just rescales β, it doesn't change the fitted predictions).

Assumptions and What Breaks When They Fail

  • Linearity — the true relationship between features and target is linear in the parameters (polynomial/interaction terms still count as "linear regression" since they're linear in the transformed features). Violated ⇒ systematic bias in predictions, visible as curvature in a residual-vs-fitted plot.
  • Homoscedasticity — residual variance is constant across the range of predictions. Violated (heteroscedasticity, common in financial/count data) ⇒ OLS coefficients stay unbiased but are no longer minimum-variance, and the standard errors/p-values reported by default are wrong. Fix: heteroscedasticity-robust standard errors (HC3 in statsmodels) or weighted least squares.
  • Independent errors — violated constantly in time series (autocorrelated residuals) and panel/grouped data (clustered errors). Fix: Newey-West standard errors, clustered SEs, or model the correlation structure directly (GLS, mixed-effects models).
  • No severe multicollinearity — highly correlated features make (XᵀX)⁻¹ near-singular, inflating coefficient variance and making individual coefficients uninterpretable (sign flips, huge swings under small data perturbations) even though overall predictions stay fine. Diagnose with VIF (variance inflation factor); VIF > 10 is a common red flag. Fix: drop redundant features, PCA, or Ridge regression, which directly stabilizes (XᵀX + λI)⁻¹.
  • Normally distributed residuals — matters only for exact small-sample inference (t-tests, confidence intervals); point estimates and predictions are fine without it, and the Central Limit Theorem bails out inference asymptotically as n grows (see CLT).

Production Reality

Use sklearn.linear_model.LinearRegression when you only need predictions — it's fast, SVD-based, and gives no inferential statistics. Use statsmodels.OLS when you need p-values, confidence intervals, or an F-test for feature significance — it's the tool for causal/explanatory regression, not just prediction. R² measures the fraction of variance explained but always increases (or stays flat) as you add features, even useless ones — report adjusted R² or, better, cross-validated MSE/MAE for model comparison. Squared-error loss is sensitive to outliers (a single leverage point can swing the fitted line dramatically) — check Cook's distance for influential points, or switch to HuberRegressor/RANSACRegressor for outlier-robust fitting. When d approaches or exceeds n, or features are collinear, plain OLS overfits or becomes ill-posed — reach for Ridge/Lasso/ElasticNet (see L1 vs L2 regularization), which is the practical default in almost every production linear model pipeline.

Key Takeaways

  • sklearn's LinearRegression never inverts XᵀX directly. It solves via SVD-based least squares for numerical stability under collinearity — inverting XᵀX by hand (as textbooks show) blows up with correlated or near-duplicate features. If you ever implement OLS from scratch for an interview, mention np.linalg.lstsq over explicit matrix inversion.
  • Feature scaling changes gradient descent's convergence speed but not the closed-form answer. The normal equation is scale-invariant (up to numerical precision); gradient descent's convergence rate depends on the condition number of XᵀX, which unscaled features can make enormous. Always standardize before SGDRegressor or when training with a fixed learning rate.
  • R² is not a valid model-comparison metric on its own — it never decreases when you add a feature, even random noise. Use adjusted R², or better, cross-validated held-out MSE/MAE, when deciding whether a new feature actually helps.
  • Default OLS standard errors are wrong under heteroscedasticity — coefficients stay unbiased but p-values and confidence intervals are miscalibrated. In statsmodels, fit with .fit(cov_type="HC3") as the default-safe choice rather than trusting classical SEs blindly, especially with real-world (non-homoscedastic) data.
  • Multicollinearity doesn't hurt predictions, it hurts interpretation. A model with VIF = 50 on two correlated features can still predict well but its individual coefficients are meaningless and unstable — don't use them for "feature importance" without addressing the correlation first (drop one, PCA, or Ridge).
  • Squared-error loss is quadratically sensitive to outliers — one bad data point with a large residual dominates the loss and can swing the fitted line substantially. Check Cook's distance/leverage, or swap to HuberRegressor/TheilSenRegressor/RANSACRegressor when your data has heavy-tailed noise or contamination.
