## Framing

### Trigger phrases
- "find all **unique triplets** in the array which give the sum of **zero**"
- "the solution set must **not contain duplicate triplets**"
- "return a list of lists" / "triplets can be in any order"
- Often follows Two Sum II mentally — one more dimension (fix one element, two-pointer the rest)

### Constraints that matter
- n up to 3000 → O(n³) brute force TLE; O(n²) with sort + two pointers is the target
- **Duplicates in input** — output triplets must be unique; skip equal values at anchor and both inner pointers
- Values can be negative, zero, positive — sorting enables monotonic two-pointer control on the remainder
- No requirement to preserve original order — sorting the array is allowed

### Pattern
Sort + fixed anchor + opposite ends — for each index `i`, run the Two Sum II scan on `[i+1 .. n-1]` with target `0 - nums[i]`; dedupe at all three levels.

## Approach

### Invariant
After sorting, any valid triplet `(nums[i], nums[left], nums[right])` with `i < left < right` and sum zero can be found by the inner two-pointer loop without missing solutions, as long as duplicate anchors and duplicate inner pairs are skipped. When `nums[i] + nums[left] + nums[right] == 0`, that triplet is recorded and both inner pointers advance past equal neighbors.

### Steps
1. Sort `nums` ascending.
2. For each anchor index `i` from `0` to `n - 3`:
   - If `i > 0` and `nums[i] == nums[i - 1]`, skip (duplicate anchor).
   - Set `left ← i + 1`, `right ← n - 1`, `need ← 0 - nums[i]`.
   - While `left < right`:
     - If `nums[left] + nums[right] == need`, append triplet, then skip duplicate `left`/`right` values and move both inward.
     - If sum `< need`, increment `left` (need larger pair sum).
     - Else decrement `right` (need smaller pair sum).
3. Return collected triplets.

### Pseudocode skeleton
```
function threeSum(nums):
    sort nums
    result ← empty list
    n ← length(nums)

    for i from 0 to n - 3:
        if i > 0 and nums[i] equals nums[i - 1]:
            continue

        left ← i + 1
        right ← n - 1
        need ← 0 - nums[i]

        while left < right:
            sum ← nums[left] + nums[right]

            if sum equals need:
                append [nums[i], nums[left], nums[right]] to result
                left ← left + 1
                right ← right - 1
                while left < right and nums[left] equals nums[left - 1]:
                    left ← left + 1
                while left < right and nums[right] equals nums[right + 1]:
                    right ← right - 1
            else if sum < need:
                left ← left + 1
            else:
                right ← right - 1

    return result
```

### Complexity
| | |
|-|-|
| **Time** | O(n²) — O(n log n) sort plus O(n) inner scan per anchor; each pointer moves at most n steps total per anchor |
| **Space** | O(1) extra excluding output and sort scratch (in-place sort) or O(log n)–O(n) depending on sort implementation |

## Tradeoffs

### Brute force
Three nested loops over all `(i, j, k)` with `i < j < k`, check sum zero, dedupe with a set — O(n³) time, awkward duplicate handling. Fails at n = 3000.

### Why this pattern
Sorting turns the "find two numbers summing to `-nums[i]`" subproblem into the same monotonic opposite-ends scan as Two Sum II. One pass per anchor gives all triplets for that first element without revisiting pairs. Duplicate skipping at `i`, `left`, and `right` keeps output unique without a global set of triplets.

### When NOT to use this
- **Two Sum (single pair, unsorted)** — hash map O(n) is simpler; no need to sort or outer loop.
- **3Sum Closest / kSum variants with tight k** — same skeleton often applies, but k > 3 may need recursion plus two pointers at the deepest level, not a flat triple loop.
- **Must preserve original indices in output** — sort-with-index tracking or hash-based approaches may be required instead of value-only triplets.

---

## Pitfalls
- **Forgetting duplicate skip at anchor `i`** — consecutive equal `nums[i]` produce identical triplet sets; always `continue` when `nums[i] == nums[i-1]`.
- **Advancing only one pointer after a hit** — leaves duplicate `(left, right)` pairs and repeats the same triplet; move both and skip equal neighbors.
- **Using a set to dedupe triplets after the fact** — works but hides the pointer discipline interviewers expect; inline skip is O(1) per step.
- **Off-by-one on outer loop bound** — need at least two elements after `i`, so stop at `i <= n - 3`, not `n - 1`.
